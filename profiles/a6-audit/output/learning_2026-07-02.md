# A6 学习日志 — 2026-07-02
主题: 审计方法论 — 审计发现解决与升级设计 (Finding Resolution & Escalation)
来源: Atlassian Incident Postmortem Guide + ZQ幽灵卖单4天实操

## 背景
A6已完成审计方法论10轮(5Whys/Postmortem/证据链/根因树等)，但一个关键在于"审计发现问题后的解决路径"从未被单独研究过。幽灵卖单🔴4天+state同步🟡2个月无人碰 — 说明审计发现→修复的链条断裂。

## 三条核心提炼

### 1. 发现不审查等于没写 — Review Every Postmortem
Atlassian核心原则: "An unreviewed incident postmortem report might as well never have been written."
翻译到审计场景: A6每周产出报告，但报告中的🔴发现如果无人审阅→等于没审计过。
**应用:** 审计产出需要有一个"强制审查节点" — 不是放到文件里等人读，而是标记到某个地方让ZH看到。每周一审计报告产出后，A6应检查前次报告的🔴红利是否已关闭，未关闭的自动升级为⚠️。

### 2. 设置严重级别触发升级 — Set a Threshold
Atlassian: "Incidents should have clear severity levels to trigger the postmortem process."
**审计升级路径** (从Atlassian借鉴到ZQ语境):
- 🔴 <7天: 标准审计标记，期待ZH行动
- 🔴 7-14天: 自动升级为⚠️系统性风险，要求ZH明确回应时间
- 🔴 >14天: 升级为🚨紧急 — 标记到SHARED.md让所有Agent可见
当前幽灵卖单🔴已4天-未到7天—仍在第一阶段。但A4 state同步🟡已2个月—远超14天，应升级标记。

### 3. 分配负责人和截止时间 — Assign Roles and Owners
Atlassian: "Assign the postmortem draft to a specific person. Don't procrastinate — draft within 24-48 hours."
**ZQ适用:** 每个审计发现必须有owner和deadline:
- 幽灵卖单修复 → owner: ZH? A4? → deadline: 7天
- A4 state同步修复 → owner: ZH? → deadline: 已超2个月
- 设置后在下次审计中查owner是否完成

## 怎么让A6的审计质量更高？
1. **增加"发现时效性监控"** — A6不只在报告里写发现，还要标记每个发现已持续多久。当前幽灵卖单4天→N/A，state同步2个月→🚨应升级
2. **审计发现强制升级路径** — 非对称: 标🟡2周不解决→升🔴; 🔴1周不解决→升🚨自动通知
3. **给每个发现配owner和deadline** — 审计报告的最后部分增加"待解决问题追踪表"而非只写本周情况
