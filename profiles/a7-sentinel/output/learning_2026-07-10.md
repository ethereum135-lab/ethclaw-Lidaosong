## 3条核心要点

### 🟢 要点一：KOL权重框架的结构性缺陷 — 从根源减少误报

**C1原始KOL权重框架：**
```
KOL权重(硬编码) × 关键词强度(1-3x) ≥ 10 → 告警
          ↓                     ↓
    Elon=10               基础级=1x
    CZ=8                  行动级=2x
    Saylor=6              靶向级=3x
    Trump/Vitalik/Brian=5
    Arthur Hayes=3
    行业KOL=2
    匿名=1
```

**C1-Re视角：这个框架有5个结构性缺陷，每个都产生不必要的误报：**

#### 缺陷1：静态权重完全无法适应市场变化

| 问题 | 表现 | 根源误报 | C1-C4积累的解决方案 |
|:----|:-----|:--------|:------------------|
| Elon的权重固定在10 | 但Elon 2025年后推特影响力下降（频率减少50%+，且非加密推文占比上升） | 很多Elon的非加密/闲聊推文仍然触发告警 | **C2滚动MIS** (06-03) + **C4 HMM行为模型** (06-19)：MIS取最近30条推文的实际价格影响，HMM区分KOL的「认真喊单态vs闲聊态」 |
| 新KOL无权重 | 比如SOL链上崛起的新大V初始权重未知 | 新KOL的重大喊单被漏掉（漏报也是误报的一种） | **C4冷启动策略**（初始设为2，前10条推文后根据MIS动态校准） |
| CZ权重8但时效性下降 | CZ自2023年离任CEO后，Binance公告不再由他个人发布 | 旧权重下CZ的每条推文都算8分，实际影响力已下降 | **权重关联到「职位+时间衰减」**：权重 = 基础分 × 职位衰减系数 × 时间衰减系数 |

**C1-Re修复：动态权重系统**
```
动态权重 = 基础分 × MIS滚动系数 × 活跃度系数 × 职位状态系数

基础分：C1原有的分级（Elon 10, CZ 8, ...）
MIS滚动系数：最近30条推文实际15min价格影响/历史平均MIS（来自C2产出）
活跃度系数：最近7天发加密相关推文数量/30条基准（低活跃→权重下降）
职位状态系数：在职=1.0，离职/退休=0.7，沉默>90天=0.5
```

#### 缺陷2：关键词强度分级过于线性

C1的强度分级（基础1x / 行动2x / 靶向3x）假设所有推文都能被3个等级准确分类，但实际上：

| 场景 | C1会如何判断 | 实际应该怎么判断 | 根源问题 |
|:-----|:----------:|:--------------:|:--------|
| Elon发「😄」 | 基础级1x → 10×1=10 → 告警 | 纯表情无意义，不应告警 | 强度分级需要「零级」（0x）：完全无意义的内容不参与评分 |
| KOL发「crypto is the future」 | 基础级1x → 2×1=2 → 不告警 ✅ | 正确不告警 | ✅ 本场景处理正确 |
| KOL发「just sold my bags」 | 行动级2x → 2×2=4 → 不告警 ❌ | 在下跌行情中这是重要负面信号，应告警 | 缺乏「方向性」评分：卖出=重要负面信号 |
| KOL发「this project has serious technical issues, but I'm still bullish overall」 | 关键词检测可能捕获「bullish」→ 行动级2x | 实际是负面为主，正面为补充的反讽 | C1无法处理复合情绪（C4 FinBERT可解决） |

**C1-Re修复：强度分级增加两个维度**
```
强度评分 = 内容等级(0-3) × 方向性权重(正面1.0/负面1.5) × 特异性(泛谈0.5/具体标的1.0/靶向价格1.5)

内容等级：
  0 = 无意义（表情/纯粹闲聊/lol/哈哈）→ 不参与评分  ← 新增「零级」
  1 = 基础级（泛泛谈 crypto/BTC/ETH）
  2 = 行动级（buy/sell/pump/dump/accumulate）
  3 = 靶向级（$XXX + 明确方向 + 价格目标）

方向性权重：
  正面（bullish/buy/pump/moon/accumulate）：1.0
  负面（bearish/sell/dump/scam/hack/crash）：1.5  ← 负面权重更高（因A7宁可漏报不可误报，负面需快速捕获）

特异性：
  泛谈（无具体标的）：0.5
  有具体标的（$DOGE）：1.0
  有具体价格目标（"BTC to 200k"）：1.5
```

#### 缺陷3：缺乏利益冲突检测

C1框架假设KOL发推是出于「观点表达」，但实盘中大量KOL推文存在利益冲突：

| 冲突类型 | 示例 | 如何检测 | 对权重的处理 |
|:---------|:-----|:--------|:----------|
| **收费喊单** | KOL收5-10ETH发推推某个小币 | 推文后15min查看该KOL钱包是否有转入/转出行为（需要钱包地址已知） | 标记为「付费推广」，权重×0.3 |
| **自持仓喊单** | KOL推自己投资的币种 | 检测KOL是否持有该币种（已知钱包地址时） | 标记为「利益相关」，权重×0.7 |
| **反手操作** | KOL说买但自己钱包显示卖 | 检测推文前后KOL钱包交易方向 | 标记为「说一套做一套」，标记为反向信号 |
| **关联项目方** | KOL是项目的顾问/投资人 | 从公开信息(AngelList/Crunchbase)标志关联关系 | 标记为「关联身份」，权重×0.5 |

**⚠️ 当前限制：** A7没有链上钱包监控能力（A8的领域），也没有Crunchbase API接入。但**利益冲突标记可以先用白名单方式实现**：对已知有利益冲突的KOL（如某些持币大V），在config.yaml中手动标记，等A8链上数据接入后再自动化。

#### 缺陷4：缺乏时间序列一致性

C1框架把每条推文当作独立事件评估，忽略了KOL行为的时间序列模式：

| 模式 | 含义 | 对权重的影响 |
|:-----|:-----|:-----------|
| KOL突然高频发某个币 | 可能是炒作/出货信号 | 标记为「集中鼓吹模式」，对该KOL的该币推文降权×0.5 |
| KOL连续发相反方向 | 信号不稳定，KOL自己也不确定 | 标记为「摇摆不定」，过去3天权重×0.6 |
| KOL在重大事件后沉默 | 可能被禁言/被风险警示 | 保持现有权重，但标记「近期沉默，需关注恢复情况」 |
| KOL推文时间与UTC+8 23:00-06:00高度重合 | 可能不是本人（AI代发/自动化发推） | 标记为「非本人时段发推」，权重×0.5 |

**来源：C4 HMM建模（06-19）**：KOL行为可用隐马尔可夫模型建模为3态：
- 状态1: 正常互动（日常推文，影响力一般）
- 状态2: 重点推介（高强度喊单，对应利益相关时段）
- 状态3: 沉默期（不发声或仅转推）

HMM帮助识别KOL何时处于「利益相关状态」，在此期间自动降权。

#### 缺陷5：社区共振缺乏量化节点

C1框架对社区共振的处理是「需要多源确认」，但没有量化标准：

| C1的表述 | 问题 | C1-Re量化修复 |
|:---------|:-----|:-------------|
| 「需多源确认」 | 多少源？同时问还是顺序？权重如何加总？ | **多源共振分数**：N个独立来源 × min(来源权重) × 方向一致性系数 |
| 「Elon/CZ原创除外」 | 他们的推文确实自带高权重，但也需要共振验证（防止被黑客盗号发假消息） | **所有来源一视同仁**，但Elon/CZ的基础权重高，少源也能告警。例：Elon(10)×靶向(3)=30，只需1源就够了；匿名(1)×靶向(3)=3，需3源独立确认 |
| 社区共振判定 | Reddit/Telegram都要搜吗？什么时间窗口？ | **社区共振分数 ≥ 3 才算确认**。单来源标记为「单源信号」，高置信度不靠社区共振（Elon/CZ的靶向推文自带高置信度） |

**C1-Re完整KOL评估更新公式：**
```
告警分数 = KOL动态权重 × 强度评分 × 方向权重 × 特异性系数 × 利益冲突系数 × 时间序列模式系数

告警决策：
  分数 ≥ 20 → 一级告警（立即通知ZH，高置信度）
  15 ≤ 分数 < 20 → 二级告警（标记[低优先级]，ZH有时间再看）
  10 ≤ 分数 < 15 → 三级信息（不打alert，仅打标到选币库）
  分数 < 10 → 静默（不产生任何输出）

社区共振判定（覆盖告警决策后的每个级别）：
  共振分数 ≥ 3 或 来源权重 ≥ 8 → 不附加[单源信号]标签
  共振分数 < 3 且 来源权重 < 8 → 附加[单源信号]标签
```

### 🟢 要点二：源头预防 vs 末端过滤 — 在KOL评估中的具体体现

C1对于KOL告警的设计是「窄口入宽口出」：关键词匹配什么都能进来→权重筛选去掉一部分→最后判断是否告警。这个设计导致**噪音从第一阶段就进入了系统**。

#### KOL领域的「源头预防」三步法

**第一步：在L1就阻止90%的闲聊噪音**

| 噪音类型 | C1处理方法 | C1-Re源头预防方法 |
|:---------|:----------|:----------------|
| **无意义内容**（"lol"/"😄"/"gm"） | 作为基础级1x进入→权重*1≥10时告警 | **新增零级(0x)**：完全无意义的内容不参与评分 |
| **行业泛谈**（"crypto is the future"） | 作为基础级1x进入→权重*1<10不告警 ✅ | ✅ 保持正确，但注意区分「上升市中的泛谈」和「恐慌市中的泛谈」 |
| **转发他人推文** | 转发和被转发的推文相同权重 | **转推降权×0.5**：转推表明KOL认可但不一定是自己的判断 |
| **非本人发的推文**（AI/团队代发） | 无法区分 | **HMM行为模式检测**：如果推文时间/频率/内容异常，标记为「非本人模式」 |
| **重复内容**（同一推文在不同平台同步） | 60min时间窗口去重 | **内容哈希+跨平台语义去重**：同一内容的Twitter/X和Threads版本合并为1条信号 |

**第二步：L2权重筛选时区分「真影响力」和「虚假影响力」**

C1的L2只是简单的「权重×强度≥10」，没有区分：

| KOL类型 | C1权重 | 实际影响力 | C1-Re调整 |
|:--------|:-----:|:---------|:---------|
| Elon发加密相关推文 | 10 | ✅ 仍然影响大 | 保持10，但增加活跃度系数（最近加密推文减少→系数下调） |
| Elon发非加密推文（政治/自家品牌） | 10 | ❌ 对加密市场无影响 | **主题相关性过滤**：topic != 加密 → 题材系数×0.3 |
| CZ发Binance公告 | 8 | ✅ 影响大 | 保持8 |
| CZ发个人观点 | 8 | ❌ 影响力下降（2023后） | 职位状态系数×0.7 → 实际权重 5.6 |
| 行业KOL收费发推 | 2 | ❌ 付费推广，非真实观点 | 利益冲突标记→如果证实收费→系数×0.3 → 实际权重 0.6 |
| 新KOL突然连续发同一个币 | 2（初始） | ⚠️ 可能炒作 | 时间序列模式系数×0.5（集中鼓吹模式）→ 实际权重 1.0 |

**第三步：L3验证时用「多维度确认」代替「单维度确认」**

C1原框架的L3市场验证 = 推文前后5分钟价格变动>1%。但真正影响市场的KOL推文会同时影响多个维度：

| 验证维度 | 数据源 | C1覆盖 | C1-Re覆盖 | 异常阈值 |
|:---------|:------|:------:|:---------:|:--------:|
| 价格变动 | Binance K线 | ✅ 5min >1% | ✅ 保留 | 根据KOL调整（Elon:2min, CZ:10min, Saylor:30min） |
| 成交量放大 | Binance K线 | ❌ | ✅ 新增 | 推文后10min成交量 > 前1h的10min平均×2 |
| 资金费率变动 | Binance | ❌ | ✅ 新增 | 费率绝对值变化>0.01% |
| 未平仓合约变化 | Binance | ❌ | ✅ 新增（需API） | OI变化>5% |
| 社交媒体提及量 | 暂无（需CryptoPanic等） | ❌ | ✅ 设计预留 | 提及量15min内增加>3倍 |

**多维验证的决策逻辑（新增）：**
```
如果 仅1维验证通过 → 标记[低置信度：仅价格异动]
如果 ≥2维验证通过 → 标记[正常置信度：价格+成交量确认]
如果 ≥3维验证通过 → 标记[高置信度：多维度共振]
```

### 🟢 要点三：告警三级体系的KOL特化版本 — 从C1到C4告诉我们对什么该告警

C1-Re不只是「加过滤」。而是重新定义告警级别，把ZH的注意力集中在真正重要的事情上。

#### KOL影响力评估的「信号金字塔」

```
                    ┌─────────────┐
                    │  一级告警    │  ← 最上层：立即通知ZH
                    │ （~5%信号）  │
                    ├─────────────┤
                    │  二级告警    │  ← 中间层：标记到alert
                    │ （~15%信号） │     标记[低优先级]
                    ├─────────────┤
                    │  三级信息    │  ← 下层：只打标到选币库
                    │ （~30%信号） │     A3/A9可读
                    ├─────────────┤
                    │  静默        │  ← 底层：完全不处理
                    │ （~50%信号） │     （闲聊/无意义/重复）
                    └─────────────┘
```

#### KOL特化版告警三级体系

**一级告警（立即通知ZH）— 告警分数 ≥ 20 或 来源权重≥8且强度≥3**
```
特征：
  - 高影响KOL + 靶向级内容（Elon说$DOGE + 价格已异动 + 多维度验证）
  - 或 ZH/Commander特别关注的KOL（如Elon/CZ）的明确行动型推文
  - 或 多个高权重KOL(≥6)同时同方向发推（群体喊单模式）

alert示例：
  # A7舆情告警 — 2026-07-10 08:17 BJT
  ## 告警类型：[高级别 · KOL]
  ## 事件：Elon Musk 提及 DOGE (靶向级)
  ## 验证：价格+3.2%(2min) + 成交量×4.5 + 资金费率异动
  ## 标签：[高置信度][社区共振:强][KOL驱动市场]
  ## (高影响KOL + 多维度验证 + 社区共振)

输出格式：alert.md，必须≤10行
```

**二级告警（标记到alert，附[低优先级]标签）— 15 ≤ 告警分数 < 20**
```
特征：
  - 高权重KOL + 行动级内容，但有任一「低置信度标记」
  - 或 社区共振有但弱（仅1-2个来源）
  - 或 KOL影响中等，但内容含强烈方向性

alert示例：
  # A7舆情告警 — 2026-07-10 08:17 BJT
  ## 告警类型：[中级 · KOL]
  ## 事件：Arthur Hayes 提及 BTC（方向偏好明显）
  ## 验证：价格+0.8%(15min) + 成交量无放大
```

## 附录：C1-Re KOL框架完整更新公式

```
KOL动态权重 = 基础分 × MIS滚动系数 × 活跃度系数 × 职位状态系数

告警分数 = KOL动态权重 × 强度评分 × 方向权重 × 特异性系数 × 利益冲突系数 × 时间序列模式系数

强度评分 → 内容等级(0-3) × 方向性权重(正面1.0/负面1.5) × 特异性(泛谈0.5/具体标的1.0/靶向价格1.5)

多维度验证：
  价格验证 = abs(推文后价格变动%) > KOL特定阈值(Elon 2min 1%, CZ 10min 1%, Saylor 30min 1%)
  成交量验证 = 推文后10min成交量 > 前1h的10min平均 × 2
  费率验证 = 费率绝对值变化 > 0.01%
  OI验证 = OI变化 > 5%

社区共振分数 = N个独立来源 × min(来源权重) × 方向一致性系数
  共振分数 ≥ 3 或 来源权重 ≥ 8 → 不附加[单源信号]
  共振分数 < 3 且 来源权重 < 8 → 附加[单源信号]

告警决策：
  分数 ≥ 20 → 一级告警（立即通知ZH，≤10行alert.md）
  15 ≤ 分数 < 20 → 二级告警（标记[低优先级]，附到alert.md）
  10 ≤ 分数 < 15 → 三级信息（enrich_coin.py打标，不打alert）
  分数 < 10 → 静默（不产生任何输出）

高置信度标记：
  多维度验证≥2 + (社区共振≥3 或 来源权重≥8) + 无利益冲突标记 → [高置信度]
  Granger因果检验 p<0.05 确认KOL推文领先价格变动 → [KOL驱动市场]
  Granger因果检验 p<0.05 确认价格变动领先推文 → [KOL跟风补推]
  推文前45分钟价格Z-score>2 → [补推跟风]
  利益冲突系数<0.8 → [利益冲突:降权]
  HMM检测到集中鼓吹模式 → [集中鼓吹模式:降权]
  仅1维验证(价格) → [单源信号]
```
