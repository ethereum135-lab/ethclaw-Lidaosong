# Mac与AWS分工工作指引

> 版本：v1.0 | 2026-05-13 | 老李确认
> 目的：明确Mac和AWS各负责什么，全团队学习执行，不再混淆

---

## 一、一句话总原则

> **Mac = 大脑（Agent人格/判断/分析）**
> **AWS = 手眼（交易执行/数据采集）**

Mac上的Hermes Agent是核心——所有判断在这里做。AWS只是因Mac VPN不通，把执行和数据拉取移过去。

---

## 二、Mac负责什么

**运行位置：** 本地电脑

**核心职责：** 所有Agent的人格、职能、判断、分析

| 角色 | 在Mac做什么 |
|:---|:---|
| ZH总指挥 | 行业研判、Agent调度、产出检查、系统设计 |
| A1数据官 | 设定采集策略、分析采集到的数据 |
| A2选币官 | 两阶段筛选、评分、出候选池 |
| A3牛币官 | 四维评分精选、出推荐报告 |
| A4交易官 | 评估持仓、做Hold/减仓/清仓决策 |
| A5复盘官 | 每日复盘、经验值积累 |
| A6审计官 | 每周审计 |
| A7舆情官（暂停） | 舆情监测（暂等API） |
| A8资金官（暂停） | 聪明钱跟踪（暂等API） |
| A9学研官 | 全网搜索新工具/新策略 |

**一句话：所有"想"的事都在Mac。**

---

## 三、AWS负责什么

**运行位置：** AWS VPS (15.134.211.154)

**核心职责：** 只能做以下两件事：

### 3.1 币安交易执行

| 工作 | 说明 |
|:---|:---|
| 接收Mac端A4交易官的执行指令 | A4在Mac做决策→写到AWS→AWS执行 |
| 执行币安买入/卖出 | 通过Binance API |
| 回传交易结果给Mac | 写入TRADES.md供A5复盘 |

### 3.2 数据采集（因Mac VPN不通）

| 数据源 | 说明 |
|:---|:---|
| Binance API（Top50行情、K线、资金费率等） | Mac VPN不通，由AWS采集回传 |
| CoinGecko API（市值、排名、趋势、类别） | 同因 |
| Alternative.me（F&G恐慌指数） | 同因 |
| 后续：Twitter/X数据 | 可选方案，AWS采集→回传Mac分析 |
| 后续：链上数据（Etherscan等） | 可选方案 |

**一句话：所有"执行"和"采集"的体力活都在AWS。**

## 四、数据流向图

```
第三方数据源（Binance/CoinGecko/推特等）
       ↓ (AWS直连，无VPN封锁)
    AWS
       ├── 数据采集 → 存为文件 (data/aws_snapshot.json等)
       ├── 执行交易 → 回传结果 (TRADES.md)
       └── 所有结果通过SSH同步回Mac
              ↓
    Mac (Hermes Agent)
       ├── A1读数据 → 生成data_feed
       ├── A2读data_feed → 选币候选池
       ├── A3读候选池 → 精选推荐
       ├── A4读推荐 → 做交易决策 → 写执行指令回AWS
       ├── A5读交易结果 → 复盘分析
       ├── A6/A9/ZH读所有产出 → 审计/学习/调度
       └── 所有Agent在Mac上运行
```

## 五、常见混淆纠正

| ❌ 错误说法 | ✅ 正确说法 | 原因 |
|:---|:---|:---|
| "A1在AWS上采集数据" | "A1在Mac上设定采集策略，数据由AWS拉取" | A1是Agent人格，在Mac |
| "A2选币官在AWS运行" | "A2在Mac做两阶段筛选，数据从AWS同步回来" | A2判断在Mac |
| "A4在AWS执行交易" | "A4在Mac评估仓位做决策→写指令到AWS→AWS执行" | 决策在Mac，执行在AWS |
| "Agent迁移到AWS" | "只有交易执行和数据采集在AWS，Agent全部在Mac" | Agent人格永远在Mac |
| "AWS跑Agent" | "AWS跑Python脚本做执行/采集" | AWS不运行任何Agent人格 |

## 六、禁止行为

| ❌ 禁止 |
|:---|
| 说"某Agent在AWS运行" |
| 把Agent的人格/判断放到AWS上 |
| 在AWS上创建新Agent |
| 混淆Mac和AWS的职责边界 |
