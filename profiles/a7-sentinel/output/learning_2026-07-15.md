## 3条核心要点

### 🟢 要点一：C1黑天鹅事件框架的6个结构性缺陷 — 从源头分析假黑天鹅和漏黑天鹅的根因

**C1原始黑天鹅框架：**
```
黑天鹅事件 → 检测 → 分类（黑客/监管/升级）→ 告警
                      ↓                 ↓
                阈值: >$10M         方向: 恐慌/利好
                
监控方式: web_search("crypto hack") / web_search("crypto regulation")
         → 纯被动响应式监控
```

**C1-Re审视：这个框架有6个结构性缺陷，每个都直接影响误报率和漏报率。**

#### 缺陷1：「假黑天鹅」与「真黑天鹅」的混淆 — 80%的事件是噪音

C1框架把所有「黑客/监管/升级」都放入同一个告警通道，但实际影响差异巨大：

| 事件类型 | C1分类 | 实际影响范围 | A7实盘影响 | 根源问题 |
|:---------|:-----:|:-----------:|:----------|:--------|
| Bybit $1.4B被盗 (2025-02) | 黑客(>$10M) ✅ | BTC -8%，全市场恐慌，影响持续1周以上 | **真黑天鹅** — 应触发紧急告警 | ✅ C1阈值捕获，但反应时间不够快 |
| 某DeFi跨链桥$20M被盗 | 黑客(>$10M) ✅ | BTC -1%，受影响项目+20%，2天后恢复 | **准黑天鹅** — 应触发中级告警 | ✅ 阈值捕获，但影响评估不够细 |
| 某小型DEX $2M被闪电贷攻破 | 黑客(<$10M) ❌ 未触发 | 仅该项目-90%，市场无反应 | **普通事件** — 不应告警 | ❌ C1阈值>$10M正确排除了 |
| 某交易员个人钱包被盗$15M | 黑客(>$10M) ✅ | 链上-0.1%，市场无反应 | **误报** — 私人事件与系统无关 | ❌ 阈值太粗，没区分「交易所级别」vs「个人级别」 |
| **总量：80%的「黑客」新闻其实是小额rugpull/周报汇总/旧闻重发** | — | — | **源头噪音污染** | ❌ 无「事件重要性过滤器」 |

**C1-Re修复：事件重要性分级体系**

不是所有"hack"都值得告警。需要区分事件的**影响范围**而非只看金额：

```markdown
# 事件重要性评分（EIS — Event Importance Score）
EIS = 影响范围权重 × 受损资产权重 × 系统性风险系数 × 时效性系数

影响范围权重：
  交易所级别(中心化): 5  — 影响所有用户资产
  协议级别(DeFi/L1): 3   — 影响一个生态
  个人级别(钱包): 1       — 只影响个人
  未知来源: 0.5           — 暂无法确认

受损资产权重：
  核心资产(BTC/ETH/USDT/USDC): 3  — 影响整个市场
  长期项目(上市>1年/前200): 2     — 影响特定赛道
  小币/新项目: 1                  — 影响有限
  未知: 0.5

系统性风险系数（当前市场状态下的事件传染力）：
  高波动市(恐慌/F&G<30): 1.5      — 利空会被放大
  低波动市(正常/F&G 30-70): 1.0   — 事件影响适中
  高贪婪市(F&G>70): 0.7            — 利空会被消化

时效性系数（事件的新鲜度）：
  首发(0-30min): 1.0
  已发酵(30min-2h): 0.6
  旧闻(>2h): 0.2

告警阈值：
  EIS ≥ 20 → 一级告警（真黑天鹅，立即告警）
  EIS 10-20 → 二级告警（准黑天鹅，标记[中级]）
  EIS 5-10 → 三级信息（不告警，打标到选币库）
  EIS < 5 → 静默（不产生任何输出）
```

**Real-world 验证：**
- Bybit $1.4B被盗: 交易所(5)×核心资产(3)×恐慌市(1.5)×首发(1.0) = **22.5 → 一级告警** ✅
- 个人钱包$15M被盗: 个人(1)×核心资产(3)×正常市(1.0)×首发(1.0) = **3.0 → 静默** ✅（本来就不该告警）
- DeFi桥$20M被盗: 协议(3)×长期项目(2)×正常市(1.0)×首发(1.0) = **6.0 → 三级信息** ⚠️（偏保守，可下调阈值）

#### 缺陷2：监管类型「一刀切」— SEC声明与国家级禁令被等同

C1把「监管=恐慌」作为固定映射，但实际监管事件的影响差异极大：

| 监管类型 | C1处理 | 实际影响 | C1-Re重新分类及EIS调整 |
|:---------|:-----:|:--------|:--------------------|
| SEC正式起诉/发传票 | 恐慌级告警 | ✅ 确实重要，通常影响-5~15% | 国家级别(5)×核心资产(3)×恐慌系数(1.5)=**22.5 → 一级** ✅ |
| CFTC商品认定（如ETH=商品） | 恐慌级告警 | ❌ 实际中性至利好（明确了监管归属） | 政策级别(3)×核心(3)×中性系数(0.5)=**4.5 → 静默** ❌ 不应告警 |
| 国会议员提案（尚未通过） | 恐慌级告警 | ❌ 不具约束力，市场无反应 | 言论级别(1)×核心(3)×草案系数(0.3)=**0.9 → 静默** ❌ 不应告警 |
| Binance/Coinbase被调查 | 恐慌级告警 | ✅ 确实重要 | 交易所(5)×核心(3)×恐慌(1.5)=**22.5 → 一级** ✅ |
| 某个国家对加密货币的税收规则更新 | 恐慌级告警 | ❌ 影响极有限，市场无反应 | 地域级别(2)×非核心(1)×0.3=**0.6 → 静默** ❌ 不应告警 |

**C1-Re修复：监管事件分类升级**

```markdown
# 监管事件分类（替代C1的「监管=恐慌」单一映射）

按影响从大到小：
1. **执法级**（正式起诉/冻结/查抄/逮捕）
   - 权重: 5
   - 代表事件: SEC起诉Binance, CFTC诉Tether
   - 影响: -5~15%
   - 告警级别: 一级

2. **政策级**（正式成文的法律/法规/行政令）
   - 权重: 4
   - 代表事件: MiCA通过, 美国总统数字资产行政令
   - 影响: -2~5% 或 +2~5%（取决于内容）
   - 告警级别: 一级

3. **指引级**（监管部门发布的指导意见/草案）
   - 权重: 2
   - 代表事件: ETP规则草案, 稳定币框架
   - 影响: -1~2% 或 无影响
   - 告警级别: 二级或三级

4. **言论级**（官员讲话/听证会/采访）
   - 权重: 1
   - 代表事件: 某国财长说"crypto is risky"
   - 影响: 通常<1%或不影响
   - 告警级别: 静默或三级（除非出自Gensler/Yellen级人物）

5. **税务级**（税收规定更新）
   - 权重: 0.5
   - 代表事件: DeFi税收报告要求
   - 影响: 无即时市场冲击
   - 告警级别: 静默
```

#### 缺陷3：方向假设太绝对 — 升级≠利好，监管≠恐慌

C1对事件方向的假设（监管=恐慌、升级=利好）过于简化：

| C1假设 | 反例 | 实际方向 | C1-Re处理 |
|:-------|:-----|:--------|:----------|
| 升级=利好 | L1主网上线后-20%（高开低走） | 短期利好出尽是利空 | 方向 = 事件性质(利好) × 市场预期(高开已price in则反向) |
| 升级=利好 | 代币通胀率降低但锁仓期延长（社区反弹） | 中性至负向（社区情绪差） | 需要社区情绪验证：升级公告后检查链上活动和社区反应 |
| 监管=恐慌 | 美国BTC现货ETF获批 | 实际超级利好 | 区分「利好型监管」（合规化/牌照/ETF获批）和「利空型监管」（禁令/起诉/查抄） |
| 监管=恐慌 | 日本承认加密货币为合法财产 | 实际利好 | 同上，需极性判断 |
| 黑客=恐慌 | 2025 GLIF被黑但FIL完全没跌 | 中性（漏洞已被修复，影响被吸收） | 影响评估 = 事件本身影响 × 市场吸收能力（看同一赛道其他币是否联动） |

**C1-Re修复：事件方向性评分**

```markdown
# 事件方向性评分（EDS — Event Direction Score）
EDS = 事件基础方向 × 市场预期差 × 赛道联动系数

事件基础方向：
  +2 = 明确利好（ETF获批/机构入场/核心技术突破）
  +1 = 边际利好（升级/扩容/合作）
   0 = 中性（人事变动/普通新闻）
  -1 = 边际利空（监管草案/部分裁员/赎回减少）
  -2 = 明确利空（禁令/被盗/大规模清退）

市场预期差（是否有price in）：
  低于预期（事件好于市场预期）: +1.2
  符和预期（已经price in）: 1.0
  高于预期（事件差于市场预期）: 0.8
  逆向（与预期方向相反）: 1.5

赛道联动系数（该事件是否影响整个赛道）：
  核心叙事（直接关系赛道龙头）：1.5
  赛道相关（影响同一赛道但非龙头）：1.2
  无关（事件只影响单一项目）：0.8

最终方向判断：
  EDS > 1.5 → 强利好
  EDS 0.5 ~ 1.5 → 边际利好
  EDS -0.5 ~ 0.5 → 中性
  EDS -1.5 ~ -0.5 → 边际利空
  EDS < -1.5 → 强利空
```

#### 缺陷4：全被动响应 — 不检测黑天鹅的前兆信号

C1框架只在**事件发生后**才工作，但真正的黑天鹅几乎从不凭空出现：

| 前兆类型 | 对应黑天鹅 | C1检测 | C1-Re检测 | 提前量 |
|:---------|:---------|:------:|:---------|:-----:|
| **链上异常活动**：大额BTC/ETH从交易所冷钱包流出，或异常合约交互 | 交易所被盗/桥攻击 | ❌ | ✅ 引入CTA/多签钱包异常活动监控 | 30min-12h |
| **安全研究员预告**：知名白帽发推提示漏洞 | 协议被攻击 | ❌ | ✅ web_search("critical vulnerability" + 协议名) | 1-48h |
| **舆论先兆**：某个监管机构前官员接受采访 | 监管升级 | ❌ | ✅ 跟踪SEC/CFTC/FinCEN活动 | 3-30天 |
| **流动性先兆**：某个稳定币持续脱锚或异常增发 | 系统性风险 | ❌ | ✅ F&G+稳定币溢价+交易所BTC溢价监控 | 1-24h |
| **技术先兆**：测试网活动激增、Github提交暴增/骤降 | 重大升级/分叉 | ❌ | ✅ 关注项目github活动、节点数变化 | 5-30天 |
| **社区先兆**：核心开发人员突然离职/项目方钱包转账 | 项目方跑路/rugpull | ❌ | ✅ 关注项目方官方社媒活跃度变化 | 12-72h |

**C1-Re修复：「预警链」模式 — 不等事件发生，监控事件发生的前兆**

```markdown
# 黑天鹅预警链设计
每个黑天鹅事件类型，定义3个前置预警级别：

## 黑客/安全类预警链
Lv1（绿）— 有安全报告但无具体威胁 → 不告警，留日志
Lv2（黄）— 安全研究员发"critical"级预警 → 写信息级alert，标记[预警:安全]
Lv3（红）— 链上检测到异常大额转账+合约交互 → 立即告警

## 监管类预警链
Lv1（绿）— 某国/地区开始讨论监管框架 → 不告警（EIS<5）
Lv2（黄）— 草案出台 + 核心人物表态 → 三级信息
Lv3（红）— 正式执法行动 → 一级告警

## 协议/升级类预警链
Lv1（绿）— 开发路线图更新 → 不告警
Lv2（黄）— 测试网异常/代码审计发现高风险 → 三级信息
Lv3（红）— 治理攻击/参数操控/停止出块 → 一级告警
```

#### 缺陷5：事件生命周期追踪缺失 — 旧闻当新事件重推

C1对每个事件只检查一次（检测到就进入告警判断），不追踪事件生命周期：

| 问题 | 表现 | 案例 | C1-Re修复 |
|:----|:-----|:-----|:---------|
| **旧闻重推** | 同一事件在Diff平台重复出现，每次被当新事件 | 某黑客事件已发酵3天，但被不同媒体重新报道后，web_search每次都命中 | **事件指纹哈希**：事件摘要(TF-IDF) → 哈希 → 查重。首发30min内→EIS×1.0；30min-2h→×0.6；>2h→×0.2 |
| **次生事件混入** | 主事件的延伸报道被当独立事件 | 黑客事件后的"项目方回应"被单独告警 | **事件树追踪**：事件1(主)→事件1.1(回应)→事件1.2(恢复进展)，同一事件树只告警一次 |
| **事件反转** | 初期报道不准确，后续有纠正 | "交易所被黑"→30分钟后确认是钱包维护 | **事件状态机**：pending(待确认)→confirmed(已确认)→debunked(已辟谣)→resolved(已解决)。只在confirmed状态且EIS达标时告警 |

**C1-Re修复：事件生命周期状态机**

```markdown
# 事件状态转换图
                    pending(待确认)
                   /     |      \
                  v      v       v
              確認    辟谣     无信息更新
              [confirmed] [debunked] [timeout: dropped]
              /      \
             v        v
         持续影响    已解决
        [active]    [resolved]
        
状态转换规则：
  pending → confirmed：≥2个独立来源确认 或 1个权威来源(CoinDesk/CZ/Binance官方)确认
  pending → debunked：官方澄清/权威来源反证
  confirmed → resolved：事件已处理/修复/影响结束 (>24h无新进展)
  pending/pending > 2h无更新 → dropped（自动丢弃）
  
告警时机：
  只在 confirmed 状态且 EIS ≥ 阈值 时告警
  pending 状态不告警（标记[待确认]）
  debunked 状态如果已发过告警，发一次[事件辟谣]更正
```

#### 缺陷6：无「黑天鹅度」量化指标 — 无法区分真正的尾部风险

C1把所有「黑客/监管/升级」都当作黑天鹅事件处理，但真正的黑天鹅（尾部风险事件）有明确的量化特征：

| 特征 | 真黑天鹅 | 伪黑天鹅(普通重大事件) | 噪音 |
|:----|:--------|:-------------------|:----|
| 影响幅度 | >20% (BTC) 或 >50% (山寨) | 5-20% (BTC) 或 20-50% (山寨) | <5% (BTC) |
| 持续时间 | >48h（非V形反转） | 12-48h | <12h |
| 多维度联动 | 价格+成交量+费率+OI+情绪同步异动 | 2-3个维度异动 | 1个维度异动（通常是价格仅短暂波动） |
| 后续级联 | 引发清算/交易所暂停/其他币种连锁下跌 | 有跟跌但无系统性风险 | 事件吸收后无后续影响 |
| 市场深度变化 | BTC买盘深度骤降>50% | 深度下降20-50% | 深度基本不变 |

**C1-Re修复：黑天鹅度指数（BSI — Black Swan Index）**

```markdown
# 黑天鹅度指数（BSI）
BSI = ∑(各维度Z-score) × 联动一致性 × 恢复时间因子

各维度Z-score（事件发生后30min vs 前24h）：
  BTC价格Z-score: |当前价 - 24h平均价| / 24h标准差
  交易量Z-score: 当前30min量 / 24h同时间平均量
  资金费率Z-score: 当前费率 / 24h平均费率
  OI Z-score: 当前OI / 24h平均OI

联动一致性（所有Z-score符号是否相同→方向一致）：
  所有同方向 +50%
  部分同方向 +20%
  不一致 -20%

恢复时间因子（从事件发生到市场恢复原状的时间）：
  <12h → 0.3（V形反弹，不是黑天鹅）
  12-48h → 0.6（中等恢复）
  >48h → 1.0（持续性影响，黑天鹅特征）

BSI阈值：
  > 3.0 → 一级黑天鹅告警（尾部风险事件，需立即响应）
  1.5-3.0 → 二级黑天鹅告警（重大事件，需重点关注）
  0.5-1.5 → 三级信息（普通事件，仅打标入库）
  < 0.5 → 静默（噪音，不产生任何输出）
```

### 🟢 要点二：源头预防 vs 末端过滤 — 在黑天鹅事件检测中的具体体现

C1对于黑天鹅检测的设计是「所有hack消息进来→阈值>$10M筛掉一部分→剩余告警」。这个设计导致**80%的告警候选一开始就是不该进入的噪音**。

#### 黑天鹅领域的「源头预防」三步法

**第一步：在事件进入系统时就阻止80%的噪音**

| 噪音类型 | C1处理方法 | C1-Re源头预防方法 |
|:---------|:----------|:----------------|
| **个人级别安全事件**（某用户钱包被盗） | 进入系统→>$10M?→可能告警 | **EIS影响范围权重=1 → 直接静默**，不浪费后续判断 |
| **旧闻重推**（同一个事件不同媒体报） | 每次都进入→60min去重→跳过 | **事件指纹哈希+生命周期状态机**：pending→confirmed→resolved，防止重复 |
| **误读标题**（"hack"但不是加密黑客） | 进入系统→搜索标题匹配→误告警 | **事件分类器**：先判断是否加密相关+是否合理影响范围 |
| **最小化事件**（损失金额<$50K的普通安全事件） | 进入系统→<$10M?→跳过 ✅ | ✅ 保持正确，但可进一步收紧阈值（<$1M直接静默，<100K不进入系统） |
| **FUD转发**（无来源的黑客谣传） | 进入系统→搜索返回→可能告警 | **待确认状态(pending)**：不强依赖单一来源，≥2独立来源才确认 |

**第二步：事件进入后区分「系统性风险」和「孤立事件」**

C1缺乏「系统性风险」这个概念框架，所有事件都被看作独立事件处理：

| 事件类型 | C1处理 | 是否系统性风险 | C1-Re处理 |
|:---------|:------|:-------------:|:---------|
| Bybit $1.4B被盗 (2025-02) | 黑客>$10M → 告警 | ✅ 系统性（核心交易所被黑，市场信心崩塌） | **一级告警** + 标记[系统性:中心化交易所风险] |
| 某DeFi桥$20M被盗 | 黑客>$10M → 告警 | ⚠️ 部分系统性（DeFi桥是基础设施，影响整个桥生态） | **二级告警** + 标记[系统性:跨链基础设施] |
| 某DEX被闪电贷攻破$2M | 黑客<$10M → 跳过 | ❌ 孤立事件（仅是DEX自身漏洞） | 和C1一样跳过 ✅ |
| 某个人钱包被盗$15M | 黑客>$10M → 告警 ❌ | ❌ 孤立事件（即使金额大，影响范围仅个人） | **EIS=3.0 → 静默** ✅ |

**系统性风险判断树：**
```
事件是否影响整个市场的基础设施？
├── 是（交易所/主要L1/主要桥/稳定币发行方被影响）
│   └── → 系统性风险事件，BIS评分×2.0
├── 是（核心项目被影响，但非基础设施）
│   └── → 部分系统性风险，BIS评分×1.2
└── 否（仅为协议/个人/DApp级别）
    └── → 非系统性风险，BIS评分×0.5
```

**第三步：事件发生后进行「后续影响追踪」而非一次判断结束**

C1是单次判断：web_search发现→判断→告警/不告警→结束。但真正的黑天鹅事件有清晰的**后效模式**：

| 时间窗口 | 后效检查项 | 正常表现 | 异常表现（黑天鹅模式） |
|:---------|:----------|:--------|:-------------------|
| 事件后5min | BTC价格是否出现>3%异动 | 可能短暂波动后恢复 | 价格持续下跌且量放大 |
| 事件后30min | 资金费率是否异常 | 正常或小幅调整 | 费率骤降至负（市场一边倒看跌） |
| 事件后1h | 前10大币种是否全部跟随下跌 | 只有直接相关币种跌 | 普跌>3%，无差异化反应 |
| 事件后2h | OI是否大规模平仓 | 小幅减少 | OI骤降>10%（大量爆仓/平仓） |
| 事件后4h | 稳定币市场是否稳定 | USDT/USDC保持在$0.99-1.01 | USDT溢价>2%（避险情绪）或脱锚 |
| 事件后24h | 是否出现连锁事件 | 事件被消化，市场恢复 | 第二个/第三个关联事件出现（级联） |

**C1-Re新增：后效追踪机制**
```markdown
# 事件后效追踪（event_traceback）
在事件告警后，A7应持续追踪检查后续影响，而非一次告警结束。

追踪周期：
  一级告警: 事件后 5min/15min/30min/1h/2h/4h/24h 各检查一次
  二级告警: 事件后 15min/1h/4h 检查三次
  三级信息: 不追踪

每次检查输出格式（追加到alert.md后，不重复写整个文件）：
  ## 后效追踪 [T+30min]
  - BTC: -8.2%, 量×3.5 (持续下跌，量放大—黑天鹅模式确认)
  - 费率: -0.05% (市场一边倒看跌)
  - 前10普跌: 是，全部跌>5%
  - 判定: 黑天鹅确认 ✅

后效追踪发现「原来判断错误」时的处理：
  - 如果事件影响消退（价格恢复，市场恢复正常）→ 发[事件缓解]标记，更新状态为resolved
  - 如果事件持续恶化（BTC跌>20%）→ 发[升级]标记，一级告警保持不变
  - 如果事件被辟谣 → 发[辟谣]更正，更新状态为debunked
```

## 附录：黑天鹅事件模式 C1-Re 完整框架更新公式

```markdown
# 事件重要性评分（EIS）
EIS = 影响范围权重 × 受损资产权重 × 系统性风险系数 × 时效性系数

影响范围权重: 交易所5 / 协议3 / 个人1 / 未知0.5
受损资产权重: 核心3 / 长期2 / 小币1 / 未知0.5
系统性风险系数: 恐慌1.5 / 正常1.0 / 贪婪0.7
时效性系数: 首发1.0 / 已发酵0.6 / 旧闻0.2


# 事件方向性评分（EDS）
EDS = 基础方向 × 市场预期差 × 赛道联动系数

基础方向: +2~-2
市场预期差: 低于预期1.2 / 符合预期1.0 / 高于预期0.8 / 逆向1.5
赛道联动系数: 核心叙事1.5 / 赛道相关1.2 / 无关0.8

方向判断: >1.5强利好 / >0.5边际利好 / ±0.5中性 / <-0.5边际利空 / <-1.5强利空


# 黑天鹅度指数（BSI）
BSI = (价格Z + 量Z + 费率Z + OI Z) / 4 × 联动一致性因子 × 恢复时间因子

联动一致性因子: 全同方向+50% / 部分同方向+20% / 不一致-20%
恢复时间因子: <12h 0.3 / 12-48h 0.6 / >48h 1.0

BSI阈值: ≥3.0一级黑天鹅 / 1.5-3.0二级准黑天鹅 / 0.5-1.5三级信息 / <0.5静默


# 告警决策总公式
告警等级 = max(EIS等级, BSI等级, 系统性风险标记, 预警链级别)

一级告警条件:
  - EIS ≥ 20 或 BSI ≥ 3.0
  - 或 系统性风险事件（交易所/主要L1/主要桥/稳定币被影响）+ 方向为负
  - 或 预警链Lv3（红）+ 事件已确认

二级告警条件:
  - 10 ≤ EIS < 20 或 1.5 ≤ BSI < 3.0
  - 或 部分系统性风险事件
  - 或 预警链Lv2（黄）+ 事件已确认

三级信息条件（不打alert，打标入库）:
  - 5 ≤ EIS < 10 或 0.5 ≤ BSI < 1.5
  - 或 预警链Lv1（绿）

静默条件:
  - EIS < 5 或 BSI < 0.5
  - 或 pending/debunked状态
  - 或 非加密相关事件


# 事件生命周期状态机
状态: pending → confirmed → resolved
                   ↓
              debunked（如被辟谣）

转换规则:
  pending → confirmed: ≥2独立来源 或 1权威来源(CoinDesk/交易所官方/CZ/Binance)
  pending → debunked: 官方澄清/权威来源反证
  confirmed → resolved: >24h无新进展
  pending > 2h → dropped（自动丢弃）

只在 confirmed 状态且EIS/BSI阈值达标时告警


# 预警链（每个事件类型独立定义）
## 黑客类预警链
Lv1: 安全研究员发一般安全警告  → EIS+3
Lv2: 安全研究员发"critical"级  → EIS+5
Lv3: 链上异常交易 + Lv2已触发 → 直接一级

## 监管类预警链
Lv1: 开始讨论监管框架        → EIS+1
Lv2: 草案出台 + 核心人物表态  → EIS+3
Lv3: 正式执法行动            → 直接一级

## 协议类预警链
Lv1: 测试网异常/代码审计问题  → EIS+2
Lv2: 治理攻击提议 或 参数操控 → EIS+5
Lv3: 停止出块/严重漏洞被利用  → 直接一级


# 后效追踪计划
一级告警: T+5min/15min/30min/1h/2h/4h/24h + 追踪BTC/量/费率/OI
二级告警: T+15min/1h + 有限追踪
三级信息: 不追踪

追踪输出格式：
  ## 后效追踪 [T+X]
  - BTC: ±XX%, 量×X.X（判定）
  - 关联波动: 关联币种涨跌
  - 费率: ±X.XX%
  - OI变化: ±X%
  - 判定: 确认/缓解/恶化
```
