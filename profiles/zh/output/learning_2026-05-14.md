## 第一部分: 网格交易（Grid Trading）— 深度消化

### 1.1 核心原理

网格交易是在预设价格区间内挂出多层买入/卖出挂单，**不预测方向**，通过价格波动自动低买高卖。

> 核心思想：震荡市场中反复收割价差。趋势市场中需配合止损。

### 1.2 三种网格模式

| 模式 | 间距方式 | 适用条件 | 代码实现复杂度 |
|:-----|:---------|:---------|:--------------:|
| **静态等差网格** | 固定USDT差（如每$100一层） | 低波动、稳定区间 | 低 |
| **动态等比网格** | 固定%差（如每0.5%一层） | 高波动、适应价格变化 | 中 |
| **自适应网格** | 根据ATR动态调整间距 | 极端波动、快速变化 | 高 |

### 1.3 关键参数设计

```
网格区间: [下限, 上限]
网格层数: N层
每层资金: 总资金 / N（均分）
间距（等差）: (上限 - 下限) / (N - 1)
间距（等比）: (上限/下限)^(1/(N-1)) - 1
```

**经验参数（加密货币）：**
- 网格区间：当前价格±10%~20%（取决于波动率）
- 网格层数：15-30层（层数太多则单笔利润太小，无法覆盖手续费）
- 每笔利润需 > 双边手续费（约0.2%）
- 近期BTC 24h波动约3.3%（$78,754-$81,324）→ 适合5-10层窄网格

### 1.4 风险控制

| 风险 | 应对 |
|:-----|:-----|
| 单边突破（价格突破网格上限） | 设置趋势过滤器（如MA50方向判断），突破上限时暂停网格 |
| 单边下跌（价格跌破下限全仓套牢） | 设置网格下限止损，突破下限时清仓转为等待 |
| 手续费侵蚀利润 | 使用maker挂单费率（0.1%），避免吃单 |
| 极端波动滑点 | 设置限价单，不追市价 |

## 第二部分: 资金费率套利（Funding Rate Arbitrage）

### 2.1 核心原理

永续合约每8小时交换资金费率。做多现货 + 做空永续 = 方向对冲，赚取费率差。

原理公式：
```
现货买入 → 做空永续 → 每8小时收资金费率 → 费率回落时双边平仓
收益 = 资金费率收入 - 手续费 - 价差成本
```

### 2.2 执行步骤

1. 监控资金费率（币安fapi/v1/premiumIndex）
2. 当费率 > 0.01%/8h（年化~11%）时触发信号
3. 现货买入 + 永续做空（等量对冲）
4. 持仓至费率回落至正常水平（<0.005%/8h）
5. 双边平仓

### 2.3 实时检测结果

| 币种 | 当前费率(8h) | 年化换算 | 套利空间 |
|:----|:-----------:|:--------:|:--------:|
| BTC | **+0.004136%** | ~4.4% | 🔴 不达阈值 |
| ETH | **+0.006225%** | ~6.8% | 🔴 不达阈值 |
| DOGE | **+0.008992%** | ~9.9% | 🔴 接近但未达阈值 |

**实时结论：** 当前三个主流币种的资金费率均低于套利阈值0.01%/8h，**无套利机会**。年化4-10%的收益不足以覆盖双边交易手续费(~0.2%)和价差风险。适合等恐慌加剧（F&G<25时费率往往极端）或牛市FOMO（F&G>80时正费率飙升）。

## 第三部分: 三角套利（Triangular Arbitrage）

### 3.1 核心原理

利用三个交易对之间的汇率不一致性（A→B→C→A路径），实现无风险套利。

公式：`(B/A) × (C/B) × (A/C) > 1 + 手续费`

### 3.2 市场现实

| 维度 | 评价 |
|:-----|:-----|
| 机会频率 | 币安等头部交易所几乎为零 |
| 执行速度需求 | < 100ms（高频交易级） |
| 资金规模需求 | 单次 > $1K才有意义 |
| 系统需求 | 低延迟API + 就近服务器 + 多线程 |

### 3.3 接入评估

**结论：❌ 当前不接入**

原因：
- 当前总资产仅$303，单次套利利润<$1（扣除手续费后）
- 系统运行在Mac + AWS通用服务器（非低延迟），无法竞争
- 三角套利机会在主流交易所已被高频做市商消灭

**替代方案：** 保留知识点。未来如果系统升级到高频交易模块 + 资金量达$10K+，可重新评估。
