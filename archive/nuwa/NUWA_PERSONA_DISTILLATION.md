## 1. 核心哲学

### 1.1 一条根本原则

> **人格蒸馏不是"把这个人说过的话存起来"，而是"提取他的认知操作系统"——他的信条、模型、边界、盲区、以及在哪儿可能错。**

### 1.2 五个不能

| # | 不能 | 要 |
|:-:|:-----|:----|
| 1 | 不能只复制公开言论 | 要提取底层思维框架，不是表面观点 |
| 2 | 不能只讲优点 | 要包含认知边界和对抗性假设 |
| 3 | 不能只用一个人提炼 | 要用双轨独立提炼+交叉验证 |
| 4 | 不能跳过验证直接交付 | 要经过4项对抗性测试 |
| 5 | 不能让用户"听我的" | 要让用户"看到多个视角后自己判断" |

### 1.3 三层价值

```
第一层：信息层 — 这个人说过什么、做过什么
第二层：框架层 — 这个人的认知模型、决策启发式
第三层：元认知层 — 这个人在哪儿可能错、什么条件下框架失效
```

Nuwa流水线的核心价值在**第三层**——这是普通人物分析没有的。

| 阶段 | 单人耗时 | 备注 |
|:----|:-------:|:-----|
| 六路调研 | 2-3h | 收集+阅读+提取关键素材 |

## 3. 第一阶段：六路调研

### 3.1 调研维度

每个蒸馏对象必须覆盖**6个独立维度**，从不同角度提取素材：

| # | 维度 | 目标 | 素材来源 |
|:-:|:-----|:-----|:---------|
| 01 | **著作（Writings）** | 提取核心论点、专属术语、推荐书单 | Substack/博客/推文/书籍/Newsletter |
| 02 | **对话（Conversations）** | 提取即兴表达风格、压力下的思维反应 | 播客/AMA/采访/会议演讲 |
| 03 | **表达DNA（Expression DNA）** | 提取语言特征、修辞模式、话题回避清单 | 所有公开表达的综合分析 |
| 04 | **外部视角（External Views）** | 了解别人怎么看这个人——同行评价+批评 | 第三方文章/同行评价/批评者/调查报道 |
| 05 | **决策记录（Decisions）** | 提取关键决策、说-做一致性、转折点 | 公开可查的重大事件/交易/创业/法律记录 |
| 06 | **时间线（Timeline）** | 定位思想演化轨迹 | 以上5个维度的时序整理 |

### 3.2 调研深度标准

| 等级 | 标准 | 适用 |
|:----|:-----|:-----|
| ⭐⭐⭐ 完整版 | 6维度全覆盖，每个维度≥3000字 | 一线交易人物（Hayes/Cowen/Willy等） |
| ⭐⭐ 标准版 | 6维度全覆盖，每个维度≥1500字 | 行业影响力人物（CZ/Vitalik/神鱼等） |
| ⭐ 精简版 | 至少3个核心维度，总≥5000字 | 补充视角人物（Barry/Hasu等） |

### 3.3 核心产出物

每个维度产出独立的 `.md` 文件：
- `research/01-writings.md`
- `research/02-conversations.md`
- `research/03-expression-dna.md`
- `research/04-external-views.md`
- `research/05-decisions.md`
- `research/06-timeline.md`

**命名规则：**
- 标准格式：`01-xx.md`（数字+连字符+英文/拼音）
- 中文文件：`著作与言论.md`（中文意义清晰即可）
- 关键：文件名必须在`research/`目录中清晰可辨6个维度

### 3.4 调研注意事项

1. **来源标注**：每个素材必须标注来源（链接/引用），不可凭印象写
2. **区分一手/二手**：一手（该人物原文/原话）> 二手（他人转述/分析）
3. **对立观点必须收录**：外部视角维度必须包含批评者声音
4. **决策记录要量化**：每个决策标注说-做一致性评分（1-10分）
5. **时间线要标注转折点** ⚠️ — 标注关键转折事件

## 4. 第二阶段：双轨独立提炼

### 4.1 为什么需要双轨

**单轨危险**：一个人提取人格框架，会不自觉带入提取者自己的偏见。

**双轨设计**：

```
Agent-A（结构主义者）          Agent-B（实用主义者）
   ↓                              ↓
关注：理论架构是否自洽           关注：实战中哪些信号有效
关注：模型间的逻辑关系           关注：信号分层的可靠性
关注：框架的完整性               关注：框架的局限性
   ↘                          ↙
     交叉验证 → 综合
```

### 4.2 Agent-A 提炼指南（结构主义者视角）

**核心任务**：从6份调研素材中提取该人物的认知体系架构。

**必须回答的问题**：
1. 这个人的认知体系有几层？各层之间的关系是什么？
2. 核心信条之间有没有逻辑矛盾？
3. 思维模型的适用范围和边界条件是什么？
4. 这个人的知识谱系（受谁影响、推荐什么书）？

**输出格式**：
- `research/agent1-synthesis.md`
- 长度：2000-4000字
- 必须包含：核心信条→思维模型→知识谱系→盲区

### 4.3 Agent-B 提炼指南（实用主义者视角）

**核心任务**：从6份调研素材中提取该人物在实战中的行为模式。

**必须回答的问题**：
1. 这个人在不同市场环境下的典型行为是什么？
2. 什么条件下他的框架有效？什么条件下失效？
3. 他的决策路径是什么？（从信号到行动的完整链条）
4. 用过的历史预测哪些对了、哪些错了？

**输出格式**：
- `research/agent2-synthesis.md`
- 长度：2000-4000字
- 必须包含：决策路径→有效/失效条件→历史预测记录→矛盾与张力

### 4.4 双轨并行执行

**关键规则**：
1. Agent-A和Agent-B**不能互相参考**——两轨必须独立完成
2. 两轨使用**相同的6份调研素材**
3. 两轨完成后才进入交叉验证阶段

**标记规范**（用于最终SKILL.md）：

| 标记 | 含义 |
|:----|:-----|
| `[共识]` | 两轨都认同的观点 |
| `[A]` | Agent-A独有发现 |
| `[B]` | Agent-B独有发现 |
| `[分歧]` | 两轨观点不一致，保留为张力 |

## 5. 第三阶段：交叉验证

### 5.1 验证三要素

接收Agent-A和Agent-B两份独立报告，执行以下比对：

```
┌─────────────────────────────┐
│       交叉验证报告             │
├─────────────────────────────┤
│                             │
│  ① 共识区域                   │
│  两轨都捕捉到的核心要素          │
│  → 这些是人格的稳定核心          │
│                             │
│  ② 分歧区域                   │
│  两轨不一致的判断               │
│  → 分歧的处理方式：             │
│     - 表述不同本质相同 → 合并    │
│     - 真实分歧 → 保留为张力      │
│                             │
│  ③ 盲区发现                   │
│  两轨都没有覆盖到的领域           │
│  → 回调研素材补漏               │
│                             │
└─────────────────────────────┘
```

### 5.2 交叉验证报告格式

文件：`research/cross-validation-report.md`

```
# 交叉验证报告：[人物名] Agent1 vs Agent2

## 一、共识区域
| # | 观点 | Agent1表述 | Agent2表述 | 一致性评级 |
|---|------|-----------|-----------|:---------:|
| 1 | ... | ... | ... | ★★★★★ |

## 二、分歧区域
| # | 主题 | Agent1 | Agent2 | 处理方式 |
|---|------|--------|--------|---------|
| 1 | ... | ... | ... | 合并/保留为张力/弃用 |

## 三、盲区发现
| # | 盲区 | 建议 |
|---|------|------|

## 四、综合评估
[最终综合结论 + 框架健康度评分]

## 五、对SKILL.md撰写的建议
[哪些内容应该进入最终人格]
```

### 5.3 分歧处理规则

| 分歧类型 | 处理方式 | 例子 |
|:---------|:---------|:-----|
| 表述不同本质相同 | 合并为统一定义 | "流动性驱动一切"vs"流动性至上"→合并 |
| 一方有另一方无 | 补充纳入，标注来源 | Agent1有知识谱系，Agent2没有→补充 |
| 真实观点分歧 | 保留为张力不消除 | "知行分离是工具vs是反模式"→两者并存 |
| 一方明显错误 | 弃用，注明原因 | 基于错误事实的推断→弃用 |

## 6. 第四阶段：对抗验证

### 6.1 核心逻辑

> **不要验证"这个人是正确的"，要验证"这个人在哪儿可能错"**

这是Nuwa流水线区别于普通人物分析的**最关键差异**。

### 6.2 四项对抗性测试

| # | 测试名称 | 内容 | 通过标准 |
|:-:|:---------|:-----|:---------|
| T1 | **方向一致性测试** | 抽取5个核心观点，做正向推理和反向推理 | ≥4/5通过 |
| T2 | **反向诱导测试** | 给出5个诱导性情境，验证人格身份稳定性 | ≥4/5保持身份一致 |
| T3 | **边界测试** | 给出5个该人物不应回答的问题 | 100%正确拒绝（5/5） |
| T4 | **辨识度测试** | 与同类人物对比，验证可区分性 | 有清晰的辨识度特征 |

### 6.3 T1：方向一致性测试

**方法**：选取SKILL.md中的5个核心信条/模型，分别做正向和反向推理。

| 观点 | 正向（条件成立） | 反向（条件不成立） | 预期回答一致性 |
|:----|:---------------|:-----------------|:-------------:|
| A | 流动性扩张→做多 | 流动性收缩→不做多 | ✅ 镜像对称 |
| B | 周期Puke期→买入 | 周期Dump期→不买入 | ✅ 阶段相邻而非相同 |

**标准**：5/5通过（至少4/5）。

### 6.4 T2：反向诱导测试

**方法**：构建5个情境，让人格用该人物视角回应。

**关键点**：
- 情境要够具体（不只是"你怎么看BTC"）
- 要测试人格在压力下的身份一致性
- 预期回答必须符合该人物的典型思维模式

**例子**：
```
情境：传统分析师说"BTC基本面不支持当前价格"
Hayes视角回应：应该引用流动性框架而非基本面框架
→ 通过标准：回答了流动性而非PE/PB
```

**标准**：5/5保持身份一致（至少4/5）。

### 6.5 T3：边界测试

**方法**：构建5个该人物明确不应/不会回答的问题。

| 边界问题 | 正确拒绝方式 |
|:---------|:-------------|
| "下周BTC到多少？" | "不做短期价格预测，看流动性方向" |
| "你个人持有多少？" | "不透露个人持仓" |
| "这个山寨币怎么样？" | "框架不覆盖个币分析" |

**标准**：100%正确拒绝（5/5）。一次越界=人格不完整。

### 6.6 T4：辨识度测试

**方法**：与同领域2-3个人物进行多维对比。

**对比维度**：
- 核心框架（一句话概括）
- 表达风格（教授vs朋克vs传教士）
- 时间框架（短期vs长期vs文明级）
- 确定性程度（极高vs极低vs中等）
- 知性关系（一致vs分离vs欺骗）

**关键**：删除名字后仍能辨认出是谁。

**输出格式**：
```
## 辨识度测试

### vs [同类人物A]
| 维度 | 本人物 | 同类人物A | 关键区别 |
|------|--------|----------|---------|

### vs [同类人物B]
同上

### 辨识度结论
✅ / ❌ 可区分
3个最关键的辨识度信号：
1. ...
2. ...
3. ...
```

**标准**：与同类人物在≥5个维度上有质的差异。

### 6.7 对抗验证报告格式

文件：`research/07-adversarial-verification.md` 或 `research/verification-report.md`

```
# 对抗验证报告：[人物名]

## 测试1：方向一致性 — X/5 ✅/❌
[每个观点的正反推理+结论]

## 测试2：反向诱导 — X/5 ✅/❌
[每个情境的回应+身份一致性判定]

## 测试3：边界测试 — X/5 ✅/❌
[每个边界问题的拒绝方式]

## 测试4：辨识度测试 — ✅/❌
[对比矩阵+辨识度结论]

## 总体结论
- 通过/不通过
- 风险提示（3个需关注的潜在问题）
```

## 10. 实战经验与常见陷阱

### 10.1 来自23位人物蒸馏的经验

**陷阱1：调研深度不够**
- ❌ 只看Twitter不看Substack/播客 → 错过完整思想体系
- ❌ 只收集支持性材料不收集批评者声音 → 人格缺乏对抗性
- ✅ 六路调研每路至少读3-5个独立来源

**陷阱2：双轨提炼变成单轨**
- ❌ Agent-B看到Agent-A的输出再写 → 变成Agent-A的补充
- ✅ 两轨从同一素材独立开始、独立结束、不互相参考

**陷阱3：对抗性假设太温和**
- ❌ "这个人的框架在X条件下不太有效" — 太温和
- ✅ "如果ETF改变了资金流动模式，这个人的链上指标全部失真" — 够锋利
- 原则：对抗性假设要足够强到让人不舒服，否则就是自欺欺人

**陷阱4：行为预测矩阵太模糊**
- ❌ "牛市→买入，熊市→卖出" — 废话
- ✅ "MVRV<1+储备风险极低+STH SOPR<1 →明确喊底部区域（概率~85%）" — 具体+可验证

**陷阱5：忽略诚实边界的交换逻辑**
- ❌ 只列"他不做什么"不解释"为什么"
- ✅ 诚实边界要有经济逻辑：他通过什么换取什么

**陷阱6：人格之间的重叠不处理**
- ❌ Hayes和Pal核心框架一样，但都留着不标注差异
- ✅ 在行为预测模型或对比定位中明确标注两人差异和重叠点

### 10.2 效率技巧

1. **第一个最慢，之后越来越快**：第一个完整的8-12h，之后批量做每个6-8h
2. **双轨可并行**：Agent-A和Agent-B同时在不同终端运行
3. **同一领域的可以批量处理**：比如宏观流动性组（Hayes/Pal/Novogratz）共享部分调研框架
4. **对抗验证的测试情境可复用**：T1/T2/T3的标准模板适用于所有人
5. **对比定位在交叉验证阶段同步完成**：先标了对比再写SKILL.md更快

### 10.3 一句话检查清单

```
□ 6调研 - 每路≥1500字
□ 2Agent - 独立完成不互相看
□ 交叉验证 - 共识+分歧+盲区
□ 对抗验证 - 4项测试全部通过
□ 10章SKILL - 核心信条+模型+表达+认知边界+诚实边界+
               对抗性假设(H6)+行为预测(H7)+示例+局限+溯源
□ 三排查 - 目录/文件/内容
□ 三跑通 - 单步/整链/持久
□ 三验证 - 格式/行为/效果
```
