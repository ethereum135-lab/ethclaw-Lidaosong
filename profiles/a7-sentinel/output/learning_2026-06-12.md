### 🟢 要点一：实时流处理框架的舆情流水线架构（Spark / Flink / Kafka）

**理论：** 现代实时舆情监控的核心是Lambda/Kappa架构。Apache Flink和Apache Spark Streaming是两大标杆框架。Kafka作为消息队列缓冲区，Flink做有状态流处理（Exactly-Once语义），配合Redpanda（Kafka兼容的零GC替代）构建端到端延迟<500ms的监控管道。

**应用到A7的具体方式：**

1. **当前A7架构评价：** 当前A7每15分钟一轮cron+tools轮询，端到端延迟即cron精度±7.5分钟。实际监测用的是curl+SSH的一步到位交互式检查，非常适合当前系统规模。但未来当监控数据源从3个扩展到20+个（多个KOL/多个新闻源/社区爬虫）时，15分钟cron轮询会碰到扩展瓶颈。

2. **Flink-Kafka舆情流水线架构（未来方案）：**
   ```
   Twitter API ─┐
   Reddit API  ─┼─→ Kafka Topic → Flink CEP → FinBERT打分 → 告警判断 → alert.md
   News API    ─┘                     ↑
                                Redis State Store (去重+时间窗)
   ```
   - Kafka Topic `raw_sentiment`: 接收多源原始数据，解耦生产和消费
   - Flink CEP（Complex Event Processing）：定义事件模式匹配（如"Elon发推+5分钟内Reddit同方向情绪上升→触发验证"）
   - Flink窗口函数（Sliding Window 15min）：自动实现时间衰减权重
   - State Backend（RocksDB）：维护推文去重表，避免同事件从3个源重复触发

3. **立即可以借鉴的概念：**
   | 概念 | A7当前实现 | Flink等价物 | 收益 |
   |:----|:----------|:-----------|:----:|
   | 15分钟窗口 | cron每15分钟检查 | SlidingEventTimeWindow(15min) | 数据驱动而非定时驱动 |
   | 事件去重 | 60min dedup_window | KeyedState + TTL | 更精确的状态管理 |
   | 时间衰减 | 手动计算0.85^(t/15) | ProcessFunction + Timer | 框架原生支持 |
   | 多源交叉验证 | delegate_task二次搜索 | CEP pattern match | 事件模式匹配而非人工编排 |

4. **A7的直接受用点（无需Flink）：** 借鉴Flink的状态管理和窗口概念改进A7的现有代码——将当前分散的检查步骤（F&G/涨幅榜/打标/写state）用类似的状态机组织，给每个来源一个TTL状态，监控异常时先查状态再决定是否需要重新搜索。

### 🟢 要点二：Transformer架构在金融时序异常检测中的最新进展

**理论：** Amazon Science（2024）提出了一种改进的Transformer架构用于多元时间序列异常检测，利用重建损失（Reconstruction Loss）作为异常分数。核心机制：将多元序列编码为Transformer嵌入，计算模型重建值与实际值的差异，差异越大→异常概率越高。相比传统方法（ARIMA/GARCH/3σ），Transformer的Multi-Head Attention能捕捉长程依赖和非线性模式。

**应用到A7的具体方式：**

1. **用于价格异动关联（C3的币价关联验证升级）：**
   - 当前A7的P4（价格关联验证）只做简单的"发推前后5分钟涨跌>1%"判断
   - Transformer方案：对BTC/ETH的5分钟K线序列训练一个轻量Transformer Autoencoder，每个推文到来时：
     - 取前30根K线（2.5小时）作为输入
     - 计算重建损失：ReconstructionError = ‖X - X̂‖²
     - 如果损失突然升高（>3σ历史均值），说明当前K线行为与历史模式不符→价格异常=推文有效应
     - 如果损失正常→价格行为符合预期模式→推文没有驱动市场

2. **AnomalyTransformer（Amazon 2024）的简化版本用于A7：**
   ```python
   # 轻量版Transformer异常检测器（适用于A7的Python环境）
   import torch.nn as nn
   
   class TimeSeriesTransformer(nn.Module):
       def __init__(self, d_model=64, nhead=4, num_layers=2):
           super().__init__()
           self.embedding = nn.Linear(5, d_model)  # 5 features: OHLCV
           encoder_layer = nn.TransformerEncoderLayer(d_model, nhead, batch_first=True)
           self.encoder = nn.TransformerEncoder(encoder_layer, num_layers)
           self.decoder = nn.Linear(d_model, 5)    # 重建输出
       
       def forward(self, x):
           # x: (batch, seq_len=30, features=5)
           embedded = self.embedding(x)
           encoded = self.encoder(embedded)
           reconstructed = self.decoder(encoded)
           return reconstructed
       
       def anomaly_score(self, x):
           with torch.no_grad():
               recon = self.forward(x)
               return ((x - recon) ** 2).mean(dim=(1,2))  # 每个样本的异常分数
   ```

3. **与C3的CUSUM对比：**
   | 方法 | 类型 | 优势 | 劣势 |
   |:----|:----|:----|:----|
   | CUSUM（C3） | 统计检验 | 无监督、计算快、可解释 | 不能捕捉非线性模式 |
   | Transformer（C4） | 深度学习 | 捕捉非线性、长程依赖 | 需训练、计算成本高、不可解释 |

4. **A7的实用建议：** Transformer异常检测适合作为"离线校准模型"（每周在训练数据上Fine-tune一次），而非实时在线推理。CUSUM做第一层快照，Transformer做第二层验证——如果CUSUM报警了而Transformer说"价格行为正常"，标记为误报候选。

### 🟢 要点三：在线学习（Online Learning / Continual Learning）更新FinBERT权重

**理论：** FinBERT（ProsusAI, 2019）基于BERT对金融文本做正面/负面/中性三分类。但加密领域高频出现新词汇（"rug pull", "wen moon", "ape in", "rekt"），静态预训练模型6个月后词汇覆盖率下降，预测精度衰减。burakutf/finetuned-finbert-crypto（2024）在标注的加密推文数据上Fine-tune了FinBERT，F1提升到0.94+。但是仍然需要continual learning来处理新产生的术语和表达。

**应用到A7的具体方式：**

1. **主动学习（Active Learning）循环：**
   ```
   [A7推文采样] → [ZH/Trainer标注] → [增量FinBERT Fine-tune] → [更新后的模型]
         ↑                                                          |
         └────────────────── 下一轮采样 ─────────────────────────────┘
   ```
   - 每两周从web_search搜索结果中采集50条低置信度推文（FinBERT打分在0.4-0.6之间，无法确定是正面还是负面）
   - 交给ZH人工标注（或用确定性规则先预标注：含"buy/bull/pump"→正向，含"sell/bear/dump"→负向）
   - 用LoRA微调FinBERT，只更新~0.1%的参数（AdaLoRA更优，自适应寻找最需要更新的层）
   - 更新后的模型直接用于下一轮的A7舆情判断

2. **词汇适应（Vocabulary Adaptation）：**
   - FinBERT的词表（WordPiece, ~30K tokens）不包含加密领域新词
   - 方案A（简单）：添加领域special tokens（`[CRYPTO_TERM]`），用梯度激活追踪发现新词
   - 方案B（推荐）：使用嵌入对齐（Embedding Alignment, Kaji et al. 2024）——每2周从爬取的推文语料中学习新token的嵌入，通过对齐训练使其与原FinBERT嵌入空间一致
   - 方案C（最轻量）：维护一个外部术语映射表，将新词映射到已知语义相似的旧词（"ape in"→"buy aggressively"），在输入FinBERT前预处理

3. **在线学习的技术注意事项：**
   | 问题 | 风险 | 解决方案 |
   |:----|:----|:--------|
   | 灾难性遗忘（Catastrophic Forgetting） | 微调后忘记原金融文本分类能力 | Experience Replay：每次保留20%原始训练数据混合训练 |
   | 分布漂移（Distribution Shift） | 新词的语义可能很快过时（如meme币周期） | 弹性权重巩固（EWC）：给重要参数加正则化惩罚 |
   | 数据标注成本 | ZH没时间每天标注大量推文 | Active Learning只采低置信度样本（不确定性采样） |
   | 算力限制 | A7运行在Hermes上，无GPU | 使用ONNX Runtime量化FinBERT，CPU推理<100ms/条 |

4. **立即可行的第一步（无需训练）：**
   ```python
   # 在A7流程中用finetuned-finbert-crypto替换原始FinBERT
   # 从HuggingFace加载，纯CPU推理
   from transformers import pipeline
   
   crypto_sentiment = pipeline(
       "text-classification",
       model="burakutf/finetuned-finbert-crypto",
       device=-1  # CPU
   )
   
   # 对每条推文打分
   result = crypto_sentiment("DOGE TO THE MOON! 🚀")
   # [{'label': 'positive', 'score': 0.987}]
   result = crypto_sentiment("BTC is dying, nothing can save it")
   # [{'label': 'negative', 'score': 0.965}]
   result = crypto_sentiment("I bought some crypto today")
   # [{'label': 'neutral', 'score': 0.782}]
   ```
