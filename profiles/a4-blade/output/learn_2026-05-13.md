## 一、为什么需要执行算法？

市价单(Market Order)在流动性不足时会带来严重滑点。对于>$100的订单（A4可能遇到），直接市价单可能导致：
- 吃掉多个盘口的深度
- 大额滑点（尤其在流动性差的山寨币）
- 对市场价格造成冲击

**执行算法（Execution Algorithms）** 将大额定单拆分为多个小单，在时间/价格维度上优化执行。

---

## 二、TWAP（Time-Weighted Average Price）

### 核心原理
将大额定单按**时间均匀切割**，在指定时间内分批执行。

**公式：**
```
TWAP = Σ(每笔成交价 × 该笔数量) / Σ(总数量)

每次下单量 = 总数量 / 总时间片数
```

### 执行机制
- 把T时间分成N个相等片段（如1小时分12个5分钟片）
- 每个时间片执行 **等量** 订单
- 不关心市场走势/成交量变化

### 优点
| 维度 | 评价 |
|:-----|:-----|
| 简单性 | ⭐⭐⭐⭐⭐ 实现最简单，无参数调优 |
| 可预测性 | ⭐⭐⭐⭐⭐ 每段时间执行量固定，容易风控 |
| 减少冲击 | ⭐⭐⭐ 中等，不根据流动性调整 |
| 隐蔽性 | ⭐⭐ 会被对手方识别（固定时间模式） |

### 缺点
- ❌ 忽略成交量变化——流动性下降时仍按固定量执行，造成更大滑点
- ❌ 可被反推识别——对手方一旦发现TWAP模式，可以在固定时间片前撤单制造滑点
- ❌ 不优化价格——市场向不利方向移动时不暂停

### A4适用场景
- 固定金额买入（如$15-$50），拆3-5单在5分钟内执行
- 流动性中等（如CHZ/STRK）的币种
- 时间要求不紧急的情况

---

## 三、VWAP（Volume-Weighted Average Price）

### 核心原理
将大额定单按**历史成交量分布**切割，成交量大的时段多执行，成交量小的时段少执行。

**公式：**
```
VWAP = Σ(每笔成交价 × 该笔成交量) / Σ(总成交量)

每次下单量 = 总数量 × (该时段历史成交量占比)
```

### 执行机制
1. 取过去N天同一时段的成交量分布作为预测
2. 在成交量大的时段分配更多订单
3. 目标：执行价接近市场VWAP

### 优点
| 维度 | 评价 |
|:-----|:-----|
| 成交量匹配 | ⭐⭐⭐⭐⭐ 跟随流动性，减少冲击 |
| 隐蔽性 | ⭐⭐⭐⭐ 执行模式与自然交易流相似 |
| 价格优化 | ⭐⭐⭐⭐ 不容易偏离加权均价 |
| 市场友好 | ⭐⭐⭐⭐ 减少对市场的人为扰动 |

### 缺点
- ❌ 依赖历史数据——突发情况（新闻/公告）导致成交量预测失效
- ❌ 滞后性——用历史预测未来，极端行情偏差大
- ❌ 实施复杂——需要分钟级成交量历史数据+实时校准

### A4适用场景
- 大额执行（>$200），如未来USDT积累到$200+
- 流动性好的币种
- 有时间窗口可以分段执行

---

## 四、TWAP vs VWAP 对比

| 维度 | TWAP | VWAP |
|:-----|:----:|:----:|
| **核心依据** | 时间均匀 | 成交量分布 |
| **实现难度** | 低 | 中高 |
| **流动性自适应** | ❌ 否 | ✅ 是 |
| **需要历史数据** | ❌ 不需要 | ✅ 需要 |
| **可预测性** | 高（规则固定） | 中（随成交量变化） |
| **大额优势** | 一般 | 显著 |
| **小额定单($15-$50)** | ✅ 推荐 | ⚠️ 过度设计 |
| **趋势行情适应性** | ❌ 差 | ⚠️ 一半好一半差 |

### 何时用哪个？
- **TWAP 推荐：** A4当前场景（$15-$50买入/卖出，5-15分钟完成，不需要历史数据）
- **VWAP 推荐：** 未来大额场景（>$200，有分钟级成交量数据，需要最小化市场冲击）

**决策树：**
```
定单量 < $50 → TWAP (3-5片，5分钟内完成)
定单量 $50-$200 → TWAP (5-10片，15分钟内完成)
定单量 > $200 + 有成交量数据 → VWAP (按成交量分布切割)
定单量 > $200 + 无成交量数据 → TWAP (增加时间片数)
```

## 五、进阶：实施框架

### 最小可行TWAP实现（适合A4）

```
输入：币种, 总金额, 时间片数N, 总时长T
步骤：
1. 每片金额 = 总金额 / N
2. 每片间隔 = T / N
3. for i in 1..N:
   a. 等待间隔时间
   b. 查询当前价格
   c. 下市价单(每片金额)
   d. 记录成交价和数量
   e. 计算实际执行均价 vs 市场均价
4. 输出：总成交均价, 总滑点%
```

### 参数建议（A4初期）
| 参数 | 建议值 | 理由 |
|:-----|:-------|:-----|
| 最小执行片数 | 3片 | 太少不如直接市价单 |
| 最大片数 | 10片 | 太多会导致单笔太小(<$5触发交易所最小限制) |
| 每片间隔 | 30-60秒 | A4每30分钟一次，内部执行不能太久 |
| 总时长 | 2-5分钟 | 不给下一次A4节点造成延迟 |

### 风控扩展
- **价格偏离保护：** 每片执行前检查价格偏离初始价格>±3%→暂停
- **成交量骤降保护：** 实时成交量<历史均值30%→降低该片量
- **滑点上限：** 累计滑点>1%→剩余订单取消

## 六、相关概念补充

### Implementation Shortfall（执行缺口）
衡量实际执行价格与决策价格之差。更全面的指标，包含：
- 延迟成本（等待导致的价差）
- 市场冲击（订单本身推动价格）
- 机会成本（未成交部分的价格变动）

### POV（Percentage of Volume）
按市场成交量的一定比例（如5%）执行，避免过度暴露。

### Adaptive Algorithms（自适应算法）
结合TWAP/VWAP/POV，根据市场条件实时调整策略。华尔街主流方向。

## 七、对A4的实践意义

| 当前A4场景 | 建议 | 理由 |
|:-----------|:-----|:------|
| $15-$50买入 | **TWAP 3-5片** | 简单可靠，无需历史数据，2-5分钟完成 |
| 清仓卖出 | **直接市价单** | 清仓优先速度，且当前单币<$100直接出 |
| 减仓50% | **TWAP 3片** | 减少滑点，又不拖延减仓时间 |
| 未来>$200大额 | **VWAP** | 需要提前准备分钟级成交量数据源 |
