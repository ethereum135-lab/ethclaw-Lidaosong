## 第一条根因：我们根本没有「edge」

外面定义 **edge = 对方为什么在这个价格亏钱给你？**

我们定义 edge = 「网格从$xxxx到$yyyy，100层，每层赚0.1%」

**问题是：谁在亏？**

网格只是一种订单布放模式，不是edge。如果市场随机游走（Hurst指数≈0.5），网格的长期期望值是**负的**——因为手续费。

- 没有EDGE = 没有正期望的系统
- 没有正期望 = 交易量越大亏越多
- 我们的A4每5分钟交易一次 = 把亏损自动化、加速化

**外面怎么定义有edge的系统：**
1. 观察到市场结构中的某种**强制性约束**（谁被迫交易？什么限制让他们不能最优操作？）
2. 提出假设为什么这个约束会持续
3. 严格统计验证后部署

**我们没有第1步。没有第2步。没有第3步。** 我们选币的方式（涨幅榜筛选→各维度评分）本质是找到了涨得好的币，不是找到了「为什么它会继续涨」——这完全是两回事。

## 第二条根因：$186不可能同时「有意义地增长」和「专业风控」

这是数学，不是观点。

**风险破产公式：RoR = ((1-W)/W)^(Account/Risk_per_trade)**

我们现有系统：
- 资金：$186
- 每仓风险（实际）：5-15%/仓（多币多仓并行时的实际暴露）
- 胜率（诚实估计）：40-45%

代入公式：
- W=0.42, Account/Risk=186/9.3=$20（按5%风险算）
- RoR = (0.58/0.42)^20 = (1.38)^20 ≈ **恒大于1 → 必然破产**

就算我们跳到专业标准（2%/仓，50%胜率，1:1.5 R/R）：
- RoR = (0.5/0.5)^(186/3.72) = 1^50 = **1.0（仍然必然破产——因为胜率刚好等于盈亏平衡线）**

真相：**低于$25k，在统计意义上就不可能跑出正收益**（行业研究共识）。不是观点，是数据。

## 第三条根因：Grid bot 本身是「最破坏性的机器人类型」

行业研究明确列出：

| 机器人类型 | 失败机制 |
|-----------|---------|
| **Grid bots** | 成千上万的交易产生巨额手续费；每格利润微薄；**任何持续性趋势都会爆掉网格范围** |
| DCA bots | 逆势加仓，需要强趋势延续，均值回归市场会灾难性亏损 |
| Scalping bots | 需要亚秒级执行——零售VPS做不到 |

我们正在跑一个**网格bot**，每隔5分钟就在跑，手续费累计来看：

ETH网格16单（8买8卖），每单在Binance spot收0.1%：
- ETH $1,900 × 0.001 × 16 = **$30.4** 手续费
- 网格本身利润：格子利润约$0.5-1/格，8个卖出格获利约+$14
- **手续费吃掉利润的2倍以上**
- 这是ETH这4天的情况

其他币种呢？TOWNS 12,742枚，网格每格利润约$1-2，但价差$0.0001/格——跌了5%就全线套住。

## 第四条根因：我们不是「系统」，是「一个脚本」

专业机构的6层架构 vs 我们的：

| 层 | 专业机构 | ZQ Web 4.0 | 
|---|---------|-----------|
| 数据层 | 多数据源，tick级，纳秒级时间戳 | A1爬几个API，polling 1min-15min |
| 信号层 | 多个独立signal，每个有机制文档 | 评分公式，无机制 |
| 组合构建 | 信号融合，等风险分配，相关性管理 | **没有** |
| 执行层 | SOR/VWAP/冰山单/市场影响模型 | 简单限价单 |
| 风控层 | 独立服务，可以override所有策略，实时断路器 | 策略内的硬编码止损 |
| OMS | 订单全生命周期状态机 | API调用成功/失败 |

**我们缺失的是整个Portfolio Construction和Risk Management两层。**

我们的A4代码里写了一些风控逻辑（连续E卖暂停、每日亏损限制），但这些是策略代码的一部分。外面专业的做法是：**风控是一个独立的层，和策略代码运行在不同的进程/不同的机器上，有权限在任何时候切断所有交易。**

我们呢？风控和交易在同一个进程里，风控逻辑是策略逻辑的if-else。

## 第五条根因：手续费在$186级别下是致命伤

Binance spot round trip = 0.2%（买+卖手续费）

$186 × 0.2% / 笔 = $0.37/笔

每30分钟跑一次，一天48次：
- 1个币种：$17.76/天 = **9.5%/天的资金消耗**
- 2个币种：$35.52/天 = **19%/天的资金消耗**

要覆盖手续费，每个交易必须有0.4%以上价差收益——在$186资金下，5分钟频次内，这在统计上不可能稳定实现。

**外面专业机构的费率：0.01-0.03%/笔**
**我们的费率：0.1-0.15%/笔**
**差5-10倍。**

但这个根因的更深层问题：**我们选择了spot而不是futures**。Binance futures的手续费是0.02-0.05%/笔，便宜3-5倍。但更根本的是——**$186去做5分钟频次的交易，无论什么费率都亏。**

---

## 根本结论：系统设计在错误的起始点上

```
网格 = 定价机制，不是交易系统
$186 < $25k资本门槛 → 统计上不可能正收益
Spot + 高频次 → 手续费吞噬所有利润
无edge → 每一笔交易都在亏给专业的对方
```

**我们花了大量精力去调试参数（E2从0.6到0.4，网格范围调整，止损位置），但这些都是在错误上改错。**

参数优化的前提是：**底层逻辑是对的**。如果系统本身没有正期望，调参只是在控制亏损速度，而不是解决问题。
