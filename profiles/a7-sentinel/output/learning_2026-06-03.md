## 提炼3条核心要点

### 要点1：Granger因果检验区分「KOL驱动市场」vs「KOL跟风补推」

**理论：** 这是Cycle 1 L1过滤（推文前10分钟看价格）的统计升级版。Granger因果检验通过VAR（向量自回归）模型判断：时间序列A（KOL推文强度）是否在统计意义上**先于**时间序列B（价格变化）发生。如果推文→价格的p<0.05，KOL是市场驱动者；如果价格→推文的p<0.05，则KOL在跟风。

核心公式（滞后阶数τ=1~4个15分钟窗口）：
```
推文强度(t) = α + Σβ_i * 推文强度(t-i) + Σγ_j * 价格收益(t-j) + ε_t
价格收益(t) = α + Σβ_i * 价格收益(t-i) + Σγ_j * 推文强度(t-j) + ε_t
```
如果价格方程中推文滞后项的γ_j联合显著(F-test p<0.05) → 推文→价格（KOL驱动市场）
如果推文方程中价格滞后项的γ_j联合显著 → 价格→推文（KOL跟风补推）

**应用到A7的具体方式：**
- 对每条触发候选告警的KOL推文，缓存该币种发布前2小时的15分钟K线（8个时间片）
- 将推文强度离散化为归一化指标（0=无提及，1=提及，2=强烈靶向）
- 对币安K线15分钟收益序列 X[t-8:t] 和推文强度 Y[t-8:t] 跑 Granger 检验
- 输出标签：
  - `[KOL驱动市场]` — 推文领先于价格变动（高置信度信号）
  - `[KOL跟风补推]` — 价格变动领先于推文（反向因果风险↑↑）
  - `[无法判断]` — 样本不足或无显著因果方向

**所需工具：** `statsmodels.tsa.stattools.grangercausalitytests` 可直接用。

**收益：** 将Cycle 1的「推文前10分钟价格检查」从简单阈值升级为统计检验，消除80%的跟风补推误报。

### 要点2：社区共振量化（Emb相似度 + 情绪一致性矩阵）

**理论：** Sentence-BERT (SBERT) 能将文本映射到384维向量空间。KOL推文和社区讨论的向量余弦相似度，量化了「共振强度」。当Twitter+Reddit+Telegram在±15分钟内出现同方向情绪聚合时，市场反应概率显著高于单源信号。

**应用到A7的具体方式：**

**共振检测管道：**
```
KOL推文 → SBERT嵌入 → 搜索社区文本(Telegram/Reddit/Discord) → 嵌入对比

共振得分 = α * 余弦相似度 + β * 情绪一致性 + γ * 传播深度

其中：
  余弦相似度 = cos(emb(KOL推文), emb(社区消息聚类质心))
  情绪一致性 = 1 - |sentiment(KOL) - avg_sentiment(社区)|
  传播深度 = 社区内提及该推文的独立频道数
  α=0.4, β=0.4, γ=0.2
```

**三档输出：**
| 共振得分 | 标签 | 行为 |
|:--------:|:----|:-----|
| ≥0.7 | `[社区共振:强]` | 高置信度告警，市场共识正在形成 |
| 0.4~0.7 | `[社区共振:中]` | 有一定讨论但未形成共识，谨慎告警 |
| <0.4 | `[社区共振:弱]` | KOL单方发声无人跟，标记「单源信号」静默 |

**具体实现方案（无需实时API）：**
- 在监控流程中，当KOL推文触发候选告警时，用 `web_search("$XXX Reddit Telegram sentiment 2026")` 做二次检索
- 对检索结果做快速情绪聚合（FinBERT打分取平均）
- 嵌入相似度用本地 `sentence-transformers` 库离线推理（all-MiniLM-L6-v2仅80MB，MacBook推理<50ms）
- 当前A7的备选方案：用web_search做近似社区共振检测

**收益：** KOL单独喊话不再自动告警，只在「名人发起+社区跟随」的双重确认后触发。消除线性噪声。

### 要点3：先涨后推检测算法（Lead-Lag Cross-Correlation + 预推文异常检测）

**理论：** 离散互相关函数测量两个时间序列在不同滞后下的相关性：
```
ρ(τ) = Σ[(P_t - μ_P)(T_{t+τ} - μ_T)] / (σ_P * σ_T)
```
当 τ<0（价格变化领先于推文）时相关性峰值 >0.7 → 推文是补推。
加上预推文异常检测（Z-score > 2 的成交量或波动率）做双重确认。

**应用到A7的具体方式：**

**算法流程：**
```
输入: KOL推文时间戳 T₀, 币种15分钟K线(前2h+后2h)
输出: [驱动市场]/[跟风补推]/[无法判断]

1. 构建16个时间片的价格收益序列 P[-8:+8]
2. 构建推文信号序列 S（0/1/2 离散化）
3. 计算互相关 ρ(τ) for τ ∈ [-4,+4] (即±1小时)
4. 补充检查：推文前3个时间片的平均收益Z-score
   - 如果 Z_avg > 2.0 且 ρ峰值在τ<0 → [跟风补推] (置信度:高)
   - 如果 Z_avg < 1.0 且 ρ峰值在τ>0 → [驱动市场] (置信度:高)
   - 如果 ρ无显著峰值 → [无法判断] (不附加任何标签)
5. guard: 样本<8个时间片(不足2小时K线)时退出，不产生标签
```

**A7现有工具的适配：**
- 当前A7没有币安K线API直接接入，但可以在监控流程中用 `delegate_task` 或 `terminal` +
  `python3 tools/fetch_kline.py XXXUSDT 15m 16` 获取价格数据（如果该工具存在）
- 或通过 `ssh web4` 上的脚本获取
- 无K线数据时的降级：继续使用Cycle 1的简单L1过滤（推文前10分钟看价格）

**收益：** 从Cycle 1的简单时间戳比较升级为时间序列统计分析。区分「推文发完市场才动」和「市场先动KOL再发」。
