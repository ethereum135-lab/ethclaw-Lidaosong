### 从「单池成交量」升级为「多池共识」

当前 `a8_data_fetch.py` 步骤⑥扫描选币库的币时，DexScreener返回的往往是多个链上多个池子的数据。当前脚本只取成交量最大的那个池子报INFLOW信号。**但Nansen集群方法论告诉我们：三个池子同时放量的信号 > 一个池子单量大。**

**新产出字段：** 在INFLOW信号中新增 `pool_consensus` 字段：

```json
{
  "type": "INFLOW",
  "symbol": "PEPE",
  "top_pool": {"chain": "ethereum", "volume_24h": 1630000, "liquidity": 510000},
  "all_pools": [
    {"chain": "ethereum", "volume_24h": 1630000},
    {"chain": "base", "volume_24h": 520000},
    {"chain": "arbitrum", "volume_24h": 310000}
  ],
  "pool_count": 3,
  "pool_consensus": 3,
  "quality": "high",
  "score": 18
}
```

**评分规则：**
- 多池共识=多个池子(DexScreener返回的pairs中filtered后≥2) → 加分+3/池(上限+9)
- 单池信号 → 维持原分
- 多池且全部在主流链 → 额外+2分(非meme烟花)

**对A3的影响：** `pool_consensus >= 2的INFLOW → A3+18分`（原+15分的高质量分+3分共识加分）

### 为什么这么做

Nansen说「Smart Money is defined by wallet performance, not wallet size.」 把这句话映射到A8：
- 老李纠正说「不要找谁在买，要找哪有大钱进来」
- **升级版：** 不要只看「一个池子有大钱」→还要看「多个池子同时有大钱」=真金白银强度+10倍
- 一个池子的大成交量可能是刷量或LP挖矿。三个池子同时放量=真资金进入

## 🔑 要点二：流动性质量 — 从「快照过滤」升级为「趋势确认」

**核心发现：** Nansen的Solana交易指南区分**流动性集中**(Liquidity concentration=积极信号) vs **流动性碎片化**(Liquidity fragmenting=红旗信号)。A8当前只做单次快照的流动性过滤(>$5K/$10K/$50K分行层级)，没有跟踪流动性趋势。

### 流动性趋势的价值

| 场景 | 单次快照 | 趋势视角 |
|:-----|:---------|:---------|
| 池子A: 流动性$100K(新加) 成交量1M | 判断: mid→high质量 | 判断: 🟢 流动性在增加 = 真实资金 |
| 池子B: 流动性$10K(快撤了) 成交量1M | 判断: low→可能是刷量 | 判断: 🔴 流动性在减少 = 准备收割 |
| 池子C: 流动性$50K(稳定) 成交量$50K 连续5轮 | 判断: mid质量 | 判断: 🟢 稳定持续 = 真实交易 |

A8无法直接写缓存（no_agent脚本不宜维护复杂SQLite），但可以从DexScreener返回数据推断：

```python
# 从DexScreener返回的pair attributes推断流动性趋势
def liquidity_trend_signal(pair: dict) -> str:
    """使用txns(交易笔数)变化判断流动性趋势"""
    txns_h24 = pair.get('txns', {}).get('h24', {})
    buys = txns_h24.get('buys', 0)
    sells = txns_h24.get('sells', 0)
    total = buys + sells
    
    liq = pair.get('liquidity', {}).get('usd', 0)
    volume = pair.get('volume', {}).get('h24', 0)
    
    # 如果成交量很大但交易笔数很少 → 疑似大额刷量
    if volume > 100000 and total < 50:
        return '🚩 possible wash_trading'
    # 如果成交量适中但交易笔数很多 → 真实散户参与
    if volume > 50000 and total > 200:
        return '🟢 organic_volume'
    # 买卖比极端(买>卖10:1) → 买压在积累
    if buys > 0 and sells > 0 and (buys / sells) > 5:
        return '🟢 buy_pressure'
    
    return 'neutral'
```

**对A3的影响：** 携带趋势标签的INFLOW信号 → A3在原有评分上再调整：
- `organic_volume` → +2分(真实交易)
- `buy_pressure` → +3分(买压积累)
- `possible wash_trading` → -5分(疑似刷量,降级)

## 🔑 要点三：多时间窗确认 — 从每15分钟快照升级为24-72h趋势分析

**核心发现：** Nansen的Smart Money交易指引强调「not just where price is, but how positioning has changed over 24 to 72 hours」。A8当前每15分钟独立扫描，**没有任何跨轮次的状态跟踪**。

### 问题现场

```
轮次1 (07:00): INFLOW|DOGE|成交量$300K|质量mid → A3 +10分
轮次2 (07:15): INFLOW|DOGE|成交量$310K|质量mid → A3 +10分 (又加一次)
轮次3 (07:30): INFLOW|DOGE|成交量$295K|质量mid → A3 +10分 (再加)
```
A3在一天内收到96次加分（每15分钟→96轮/天），同一个币的"信号"不仅不衰减还重复加分。

### 改进：信号衰减器

既然A8 no_agent脚本不能维护复杂状态（纯脚本无模型，不宜维护SQLite），采用**时间窗口去重策略**：

**规则：同一币种的同一质量等级INFLOW，在24h内只记一次加分。**

实现方式——在 `a8_data_snapshot.json` 中新增 `daily_boost` 字段：

```json
{
  "buy_signals": [
    {"type": "INFLOW", "symbol": "DOGE", "quality": "mid", "daily_boost": true}
  ]
}
```

- `daily_boost: true` = A3今天已经加过这个币的同等级分了，不再重复加
- `daily_boost: false` = 新信号，A3可以加分
- 每天08:00重置（与cron日报时间对齐）

**A3 step 0.5读取逻辑：**
```python
# 已实现daily_boost字段后
if signal['daily_boost']:
    # 今天已加过，不再重复
    pass
else:
    if signal['quality'] == 'high':
        score += 15 + pool_consensus_bonus
    elif signal['quality'] == 'mid':
        score += 10
    else:
        score += 5
```
