# 三跑三验证 · 通用框架 v1.0
**用于评估所有Agent的独立运行、协同运行和抗压能力**

## 一、核心概念

每个Agent的成熟度由 **3个运行阶段 × 3个验证维度 = 9格矩阵** 定义。

| 等级 | 分数 | 含义 |
|:---|:---:|:-----|
| S | ≥90% | 可独立考核，可上实盘 |
| A | 75-89% | 核心功能打通，少量边界待完善 |
| B | 50-74% | 基本能用，依赖外部协助 |
| C | <50% | 还在搭建中 |

## 二、三跑（Three Runs）

### 第一跑：独立运行（5项×4分=20分）

测试Agent在**没有外部依赖**下能否完成自己的核心职能。

| # | 检测项 | 标准 | /4 |
|:-:|:-------|:----|:-:|
| 1.1 | 输入接收 | 能从指定源（文件/API/用户指令）正确获取输入 | |
| 1.2 | 核心处理 | 能按职能完成核心逻辑（分析/选币/学习/采集等） | |
| 1.3 | 输出产出 | 能生成完整、结构化、可被其他Agent阅读的输出 | |
| 1.4 | 6文件完备 | SOUL/IDENTITY/PERSONALITY/AGENTS/MEMORY/config齐全且一致 | |
| 1.5 | 自检脚本 | 有self_test.py且全部测试通过 | |

### 第二跑：协同运行（4项×4分=16分）

测试Agent在**多Agent环境**下的协作能力。

| # | 检测项 | 标准 | /4 |
|:-:|:-------|:----|:-:|
| 2.1 | 下游接收 | 上游Agent的输出它能正确读取和理解 | |
| 2.2 | 上游输出 | 它的输出能被下游Agent正确读取 | |
| 2.3 | 通信标准 | 文件/消息格式统一，路径约定一致 | |
| 2.4 | 异常上报 | 发现问题时能定位到具体Agent并上报 | |

### 第三跑：抗压运行（4项×4分=16分）

测试Agent在**边界/异常/故障**下能否稳定运行。

| # | 检测项 | 标准 | /4 |
|:-:|:-------|:----|:-:|
| 3.1 | 空输入 | 输入为空/不完整时系统有防御机制 | |
| 3.2 | 数据异常 | API超时/格式错误/数值越界时能处理 | |
| 3.3 | 限流/重试 | 被限流时有退避机制，不崩溃 | |
| 3.4 | 多轮稳定 | 连续运行≥24h不出现退化或发散 | |

## 三、三验证（Three Verifications）

### ✓ 自验证（Agent自己完成，3项×4分=12分）

| # | 检测项 | 标准 | /4 |
|:-:|:-------|:----|:-:|
| ✓1 | 输出自检 | 输出格式符合约定的schema，字段完整 | |
| ✓2 | 逻辑自洽 | 输出结果在内部逻辑上一致（如买入价<卖出价） | |
| ✓3 | 源数据可溯 | 每个结论都能追溯到原始输入数据 | |

### ✓✓ 交验证（其他Agent交叉检查，3项×4分=12分）

| # | 检测项 | 标准 | /4 |
|:-:|:-------|:----|:-:|
| ✓✓1 | 格式验证 | 下游能正常解析输出文件 | |
| ✓✓2 | 合理性验证 | 下游认为数据在合理范围内 | |
| ✓✓3 | 一致性检验 | 和另一Agent的同类数据对比，无重大矛盾 | |

### ✓✓✓ 终验证（总指挥H1/ZH验收，3项×4分=12分）

| # | 检测项 | 标准 | /4 |
|:-:|:-------|:----|:-:|
| ✓✓✓1 | 可读性 | 报告/输出不需要额外解释就能看懂 | |
| ✓✓✓2 | 可信度 | 结果经过实践检验（两天实跑） | |
| ✓✓✓3 | 可迭代 | 有明确的改进路径而非死循环 | |

## 四、Agent职能差异对照表

| 职能类型 | 第一跑侧重 | 第二跑侧重 | 第三跑侧重 |
|:---------|:----------|:----------|:----------|
| **数据型** | 1.2数据采集完整度 | 2.1数据格式标准化 | 3.2源站故障需降级 |
| **分析型** | 1.2分析算法正确性 | 2.2输出含置信度标识 | 3.1缺数据时不下错误结论 |
| **执行型** | 1.3指令下达不可歧义 | 2.4确认/回滚双通道 | 3.3失败时不能静默 |
| **复盘型** | 1.2因果链分析深度 | 2.3报告格式需被引 | 3.4长期趋势不走偏 |
| **学习型** | 1.2外部策略转化能力 | 2.1读取各Agent输出做输入 | 3.1知识库不因空输入退化 |

加权规则：侧重项 ×1.5，标准项 ×1.0

## 五、验收流程

```
步骤1 — 检查6文件
  → SOUL / IDENTITY / PERSONALITY / AGENTS / MEMORY / config.yaml
  → 不可缺失，不可矛盾

步骤2 — 第一跑 + ✓自验证
  → 给标准输入，看能否产出标准输出
  → 跑self_test.py
  → 检查逻辑自洽 + 源数据可溯

步骤3 — 第二跑 + ✓✓交验证
  → 上下游Agent读取输出，检查能否正常解析
  → 对比同类数据，无重大矛盾

步骤4 — 第三跑 + ✓✓✓终验证
  → 给边界输入 / 模拟故障
  → 观察行为是否符合预期
  → H1/ZH阅读报告，给出综合评分
```
