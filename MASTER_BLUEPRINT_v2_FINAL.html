7个Agent人格定义（SOUL.md）

Agent 所在平台 人格定义 决策风格 不能做什么
交易执行官 Hermes 铁血执行者：策略说买就买，说卖就卖 不犹豫、不追涨、不杀跌 不能自己改策略参数
风控官 Hermes 铁律守门人：止损是铁律，不可覆盖 冷静、机械、无情绪 不能被任何指令覆盖止损
策略分析师 TraeCode 全球视野+周期思维，理性不情绪 多空辩论，不偏听 不能直接调交易所API
裁判 TraeCode 综合多空意见做最终AI层判断 权衡风险收益，保守优先 不能覆盖风控官的止损
监控哨兵 OpenClaw 敏感哨兵：任何异常立即告警 宁可误报不漏报 不能触发交易
内容官 WorkBuddy 把复杂分析变成通俗内容 通俗、有趣、有数据支撑 不能接触交易系统
工程师 Claude Code 代码工匠：写代码、测试、部署 严谨、可测试、不偷懒 不能接触API密钥

决策权层级 — 冲突时听谁的

第一优先级：风控官（Hermes风控模块） → 止损/熔断是不可覆盖的铁律 → 任何人和任何Agent都不能覆盖 → 连续5笔亏损 → 自动熔断，等人工重启 第二优先级：人工决策（你） → 你说的优先于一切AI建议 → TraeCode只是给你建议，你拍板 → 你可以手动Kill Switch 第三优先级：裁判（TraeCode） → 综合多空辩论做最终AI层判断 → Vibe-Trading的AI分析是参考 → TraeCode做最终决策 第四优先级：Vibe-Trading（29个智能体） → 数据和初步分析 → 不直接做决策，只提供输入
核心原则： 风控 > 人工 > AI判断 > AI分析
风控官的止损是绝对铁律 — 即使TraeCode说"再等等"，风控官说止损就止损。
5

协同机制 — 3个系统

系统1：Redis消息总线 + A2A协议
Vibe-Trading: "美林时钟从复苏→过热，大宗商品利好" ↓ (A2A消息 → Redis pub/sub) TraeCode: "策略方向：减仓加密，关注大宗" ↓ (写策略文件 + A2A消息) Hermes: "收到，执行减仓" → 下卖单 ↓ (A2A消息 + 写共享日志) OpenClaw: "Hermes执行了减仓，推送通知到手机" ↓ (A2A消息) WorkBuddy: "TraeCode产出分析文案 → 生成今日视频"

所有平台通过Redis发布/订阅事件，实时感知彼此状态。
A2A协议（Linux Foundation开放标准）定义消息格式，MCP管Agent→工具，A2A管Agent→Agent。

系统2：多空辩论机制
Vibe-Trading产出数据 ↓ 看多分析师：为什么该买入？（找3个理由） ↓ 看空分析师：为什么不该买？（找3个理由） ↓ 裁判（TraeCode）：综合判断 → 最终决策 ↓ 风控官（Hermes）：检查仓位/止损是否符合规则 ↓ 执行

避免单一视角偏见 — TradingAgents验证：多空对抗优于单Agent决策。

系统3：共享上下文层（数据流转）
数据类型 谁写入 谁读取 存储位置 格式
全球宏观数据Vibe-TradingTraeCodeAWS共享目录JSON/CSV
美林时钟状态Vibe-TradingTraeCode+HermesAWS共享JSONJSON
交易策略配置TraeCodeHermesAWS策略文件YAML/JSON
交易记录HermesTraeCode+OpenClawAWS日志JSONL/MD
告警事件OpenClaw手机(Telegram)OpenClaw内部消息
内容素材TraeCodeWorkBuddy本地共享目录Markdown
F&G/RSI指标HermesVibe-Trading+TraeCodeAWS共享JSONJSON

规则：任何平台不直接调用另一个平台的内部数据。 所有数据通过共享上下文层流转。

6

两个闭环 — 系统越跑越聪明

闭环1：学习闭环（交易→复盘→优化→再交易）
Hermes执行交易 → 交易记录写入共享上下文 ↓ TraeCode复盘：赚了/亏了？为什么？ ↓ 归因：选币问题？信号问题？执行问题？止损问题？ ↓ 修改策略参数 → 写入新策略配置 ↓ Hermes读新策略 → 下一次执行改进了 ↓ ↺ 循环 — 每次都比上次聪明一点
这就是"每一天能盈利"的核心机制 — 不是每次都赚，而是每次都比上次聪明一点。
闭环2：内容闭环（分析→内容→发布→反馈→优化）
TraeCode产出经济分析 ↓ WorkBuddy生成推特/视频/抖音内容 ↓ 发布到各平台 ↓ 读者评论/点赞/转发 → OpenClaw抓取 ↓ 反馈输入TraeCode → 优化下一期内容方向 ↓ ↺ 循环 — 内容越做越精准
7

安全体系 — 三层隔离 + Kill Switch

平台 能接触 不能接触 安全措施 风险等级
Hermes交易所API(交易权限)提现权限(永不开)环境变量+IP白名单最高
TraeCode读写策略配置不能直接调交易所API通过SSH改Hermes配置中
OpenClaw读交易日志不能触发交易、不接触密钥只读权限+SOUL.md限制低
Vibe-Trading公开市场数据API不接触交易密钥数据Key独立于交易Key低
Codex/CC代码仓库不接触API密钥密钥在.env, gitignore中
WorkBuddy内容素材不接触交易系统完全隔离低
三层Kill Switch（紧急停止）
第1层：Hermes自动熔断 → 连续5笔亏损 / 总回撤>8% → 自动停止 → 不需要任何人触发 第2层：Telegram命令熔断 → 手机发 "/killswitch HALT" → Hermes立即停所有交易 → 人工远程触发 第3层：人工API撤销 → 登录交易所 → 撤销API Key → 物理断连 → 最终保底

降级方案 — 故障树

故障 概率 影响 应对
AWS宕机极低Hermes+Vibe全停OpenClaw检测断连→推送手机→人工撤单→等恢复
Hermes宕机低交易停止，挂单仍在OpenClaw检测无心跳→告警→人工重启
TraeCode不在线常态无新策略，交易继续Hermes用最后策略自主运行→我上线后复盘
数据源断中无新数据Vibe-Trading自动降级备用数据源→OpenClaw告警
OpenClaw挂低无告警Hermes自动熔断兜底→定期人工检查
API限流中下单失败Hermes指数退避重试→超阈值暂停→告警
持续亏损已发生资金减少连续5笔亏损→自动熔断→等人工复盘修复
核心原则： 任何单点故障都不能导致资金损失。交易所侧的止损单独立于系统存在。

跨市场协同 — 加密/股票/竞猜

市场 数据层 分析层 执行层 当前阶段
加密货币 Vibe-Trading(CCXT) TraeCode(美林时钟+RSI) Hermes自动交易 Phase 1 运行中
美股/A股/港股 Vibe-Trading(yfinance/Tushare) TraeCode(周期分析) 导出TradingView→人工下单 Phase 1 数据+分析

协同核心：数据互通，不是执行互通。

美债涨 → 美股跌 → Vibe-Trading检测到 → A股/港股跟跌 → OpenClaw推送手机

竞猜平台的核心价值不是赚钱，而是另类情绪数据源 — Polymarket赔率变化比新闻快。
