# Nuwa 人格蒸馏 — Agent执行手册

> 本文件由Hermes Agent写给另一台Hermes Agent（或任何有skill_manage/read_file/write_file的AI Agent）
> 按顺序执行以下步骤即可独立完成任何一个新人物的蒸馏
> 时间预估：6-8小时（新人），4-6小时（熟练后）

---

## 第一章：前置检查

### 1.1 确认你有这些工具

```
需要的工具：
  □ skill_view(name)       — 加载已有技能
  □ skill_manage(action)   — 创建/更新技能
  □ write_file(path, content) — 写文件
  □ read_file(path)        — 读文件
  □ search_files(pattern)  — 搜索文件
  □ web_search(query)      — 搜索网络（调研用）
```

### 1.2 确认目标人物的公开素材量

在开始之前，快速评估素材充足度：

```
执行 web_search("[人物名] crypto" | "人物名 采访" | "人物名 推文")
查看搜索结果数量：
  > 10,000条 → 素材充足，做完整版
  1,000-10,000条 → 做标准版
  < 1,000条 → 做精简版（至少覆盖3个调研维度）
```

### 1.3 创建目录结构

```
skill_manage(action='create', name='[persona-name]', category='trading',
  content='''---
name: [persona-name]
category: trading
description: "[1句话描述]"
tags: [nuwa]
---''')

然后用 mkdir（通过terminal）创建 research/ 目录。
```

### 1.4 素材收集——从哪里找

```
调研素材优先级排序：
  1. 该人物的Substack/Newsletter/博客（最核心——自己写的东西）
  2. YouTube播客/采访（20-60分钟深度对话最好）
  3. Twitter/X推文（注意：推文通常比长文更极端）
  4. 第三方分析/批评文章（不要只收支持性材料）
  5. 书籍（如果有的话，是最完整的思想体系）

搜索公式：
  web_search("[人物名] interview crypto")
  web_search("[人物名] podcast")
  web_search("[人物名] crypto criticism")
  web_search("site:substack.com [人物名]")
```

## 第二章：六路调研（执行阶段）

### 2.1 调研指令

对每个调研维度，**加载zh-commander-agent技能获取行业认知**，然后用web_search和read_file完成。

### 2.2 调研维度01：著作（writings）

**目标**：提取核心论点、专属术语、推荐书单

**执行指令**：
```
1. web_search("[人物名] writings crypto" | "[人物名] substack" | "[人物名] blog")
2. 阅读搜索结果中最相关的3-5篇长文
3. 对每篇长文提取：
   - 核心论点（1-3句话）
   - 专属术语（人物自创的概念/短语）
   - 出现的次数（★★★出现≥3次 = 真信念）
4. 输出到 research/01-writings.md
```

**产出格式**：
```markdown
# 01-writings.md — [人物名]著作调研

## 核心作品清单
| 篇名 | 核心论点 | 首发时间 | 链接 |

## 专属术语表
| 术语 | 含义 | 出现频率 |

## 推荐书单
| 书名 | 作者 | 该人物引用原因 |

## 核心概念出现频率
| 概念 | 出现次数（★★★/★★/★） | 含义 |
```

**最低要求**：收集≥10篇原创内容（文章/推文长thread/书籍节选）

---

### 2.3 调研维度02：对话（conversations）

**目标**：提取即兴表达风格、压力下的思维反应

**执行指令**：
```
1. web_search("[人物名] podcast" | "[人物名] interview" | "[人物名] AMA")
2. 找到2-3个深度采访（20-60分钟）
3. 对每个采访提取：
   - 压力测试时刻（被问到尖锐问题时的反应模式）
   - 口头禅/高频词汇
   - 与书面向内容不一致的地方
4. 输出到 research/02-conversations.md
```

**产出格式**：
```markdown
# 02-conversations.md — [人物名]对话调研

## 采访清单
| 采访名称 | 平台 | 时长 | 关键片段 |

## 压力测试时刻
| 问题 | 回应方式 | 体现的思维特征 |

## 口头禅/高频词汇表
| 词汇/短语 | 上下文 | 含义 |
```

**最低要求**：完成≥2个深度采访的分析

---

### 2.4 调研维度03：表达DNA（expression-dna）

**目标**：提取语言特征、修辞模式、话题回避清单

**执行指令**：
```
从01（著作）和02（对话）的综合分析中提取：
1. 句式特征（短句vs长句、结论先行vs推理先行）
2. 修辞工具箱（类比、反问、数据轰炸、讽刺等）
3. 确定性与概率词的使用比例（"显然"出现频率比"可能"高几倍？）
4. 刻意回避的话题清单
5. 输出到 research/03-expression-dna.md
```

**产出格式**：
```markdown
# 03-expression-dna.md — [人物名]表达DNA调研

## 语言风格总览
| 维度 | 特征 |

## 修辞工具箱
| 修辞手法 | 例子 | 使用频率 |

## 确定性分析
| 确定性等级（极高/中/低） | 表现 |

## 回避话题清单
| 话题 | 回避方式 |
```

---

### 2.5 调研维度04：外部视角（external-views）

**目标**：了解别人怎么看这个人——同行评价+批评

**⚠️ 关键**：这个维度最容易忽略，但**对抗性假设的质量取决于这个维度**

**执行指令**：
```
1. web_search("[人物名] criticism" | "[人物名] controversy")
2. web_search("[人物名] 评价" — 找中文圈评价)
3. 从批评者的角度提取：
   - 对核心信条的质疑
   - 历史上的失败预测/决策
   - 利益冲突指控
4. 输出到 research/04-external-views.md
```

**产出格式**：
```markdown
# 04-external-views.md — [人物名]外部视角调研

## 同行评价
| 评价者 | 评价内容 | 正面/负面 |

## 批评集
| 批评点 | 来源 | 有效性质疑？ |

## 争议事件
| 事件 | 争议点 | 该人物回应 |

## 潜在利益冲突
| 冲突类型 | 证据 |
```

**最低要求**：找到≥3个独立的批评来源

---

### 2.6 调研维度05：决策记录（decisions）

**目标**：提取关键决策、说-做一致性、转折点

**执行指令**：
```
1. 从01-04中提取所有重大决策事件
2. 对每个决策标注"说-做一致性评分（1-10分）"：
   10 = 说了就做了（高度一致）
   5  = 说了做了但结果不同
   1  = 说了完全没做（欺骗）
3. 提取关键转折点（改变立场的时刻）
4. 输出到 research/05-decisions.md
```

**产出格式**：
```markdown
# 05-decisions.md — [人物名]决策记录调研

## 决策时间线
| 时间段 | 事件 | 说-做评分 | 备注 |

## 关键转折点
| 转折点事件 | 转化前立场 | 转化后立场 | 为什么变？ |

## 矛盾点标记⚠️
| 矛盾 | 涉及的两个决策 | 一致性评分差异 |
```

**最低要求**：≥10个可标注的决策事件

---

### 2.7 调研维度06：时间线（timeline）

**目标**：定位思想演化轨迹

**执行指令**：
```
1. 从01-05中提取所有时间的标记事件
2. 按时间顺序整理
3. 标注5个关键转折点（用⚠️标记）
4. 输出到 research/06-timeline.md
```

**产出格式**：
```markdown
# 06-timeline.md — [人物名]时间线调研

| 时间 | 事件 | 类型（职业/观点/法律/市场） | 重要性 |

| 2020 | [事件] | ⚠️ 转折点 | ⭐⭐⭐⭐⭐ |

## 第三章：双轨独立提炼

### 3.1 关键规则

```
❌ 不能做：Agent-B看到Agent-A的输出再写
✅ 要做：两轨从同一素材独立开始、独立运行、独立结束

技术实现：
  Agent-A使用一个terminal会话完成
  Agent-B使用另一个terminal会话完成（不同进程）
  两个会话不互相通信
```

### 3.2 Agent-A提炼指令（结构主义者）

```
读 research/ 目录下的01-06.md文件。

你的任务是：以"结构主义者"视角提炼该人物的认知体系架构。

核心问题（必须回答）：
1. 这个人的认知体系有几层？各层之间的关系是什么？
2. 核心信条之间有没有逻辑矛盾？
3. 思维模型的适用范围和边界条件是什么？
4. 知识谱系（受谁影响、推荐什么书）？

输出格式（必须包含以下元素）：
- 核心信条（5-10条）
- 思维模型（5-8个）每个含定义+机制+局限
- 知识谱系（受影响的思想家+推荐书单）
- 盲区（这个体系在哪可能漏掉信息）

输出到 research/agent1-synthesis.md
长度要求：2000-4000字
```

### 3.3 Agent-B提炼指令（实用主义者）

```
读 research/ 目录下的01-06.md文件。

你的任务是：以"实用主义者"视角提炼该人物在实战中的行为模式。

核心问题（必须回答）：
1. 不同市场环境下该人物的典型行为是什么？
2. 什么条件下框架有效？什么条件下失效？
3. 决策路径是什么？（从信号到行动的完整链条）
4. 历史预测哪些对了、哪些错了？

输出格式（必须包含以下元素）：
- 核心信条（5-10条，侧重实战层面）
- 思维模型（5-8个，侧重行为模式）
- 决策路径（Step1→Step2→…→StepN）
- 有效/失效条件表
- 历史预测记录（正确/错误/部分正确）

输出到 research/agent2-synthesis.md
长度要求：2000-4000字
```

### 3.4 双轨标记规范

双轨完成后，在内容中标注来源标记，用于最终SKILL.md：

```
[共识] = 两轨都认同的观点
[A]   = Agent-A独有发现
[B]   = Agent-B独有发现
```

## 第四章：交叉验证

### 4.1 执行指令

```
读 research/agent1-synthesis.md 和 research/agent2-synthesis.md。
比对两者，执行：

1. 列出共识区域：两轨都捕捉到的核心要素
   → 这些是人格的稳定核心，可信度最高

2. 列出分歧区域：两轨不一致的判断
   → 按以下规则处理：
      - 表述不同本质相同 → 合并
      - 一方有另一方无 → 补充纳入
      - 真实观点分歧 → 保留为张力，不消除
      - 一方明显错误 → 弃用

3. 列出盲区：两轨都没有覆盖到的领域
   → 回到六路调研素材补漏

输出到 research/cross-validation-report.md
```

## 第五章：对抗验证

### 5.1 四项对抗性测试

这是整个流程中最关键的环节——**不经过对抗验证的人格不能交付**。

### 5.2 T1：方向一致性测试

```
从交叉验证报告中抽取5个核心观点。
对每个观点做正向推理（条件成立时的判断）和反向推理（条件不成立时的判断）。
验证正反推理是否逻辑一致。

标准：≥4/5通过。

模板：
| 观点 | 正向（条件→结论） | 反向（反向条件→结论） | 一致性 |
|:----|:-----------------|:---------------------|:------:|
| A | X→Y | 非X→非Y | ✅/❌ |
```

### 5.3 T2：反向诱导测试

```
构建5个情境，让人格用该人物视角回应。
验证输出是否保持身份一致性——不能跳出角色的认知框架。

情境设计原则：
- 情境要够具体（不只是"你怎么看BTC"）
- 要测试压力下的身份稳定性
- 预期回应的正确方向可以从信条/模型中推导

标准：≥4/5保持身份一致。

模板：
| 情境 | 预期回应方向 | 实际回应判定 |
|:----|:------------|:------------:|
| [具体情境] | [应该说什么] | ✅/❌ |
```

### 5.4 T3：边界测试

```
构建5个该人物明确不应回答的问题。
验证人格能否正确拒绝。

典型边界问题模板（适用于所有人格）：
1. "下周价格到多少？" → 应该拒绝短期价格预测
2. "你个人持有多少？" → 应该拒绝透露个人持仓
3. "这个山寨币能买吗？" → 应该拒绝个币推荐
4. "这个项目技术怎么样？" → 如果框架不覆盖技术则拒绝
5. "上次我按你说的亏了..." → 应该划清责任

标准：100%正确拒绝（5/5）。一次越界=人格不完整。
```

### 5.5 T4：辨识度测试

```
与同领域2-3个人物进行多维对比。

对比维度：
1. 核心框架（一句话概括）
2. 表达风格
3. 时间框架
4. 确定性程度
5. 知行关系（一致vs分离vs欺骗）

标准：与同类人物在≥5个维度上有质的差异。
删除名字后仍能辨认。

模板：
| 维度 | 本人物 | 同类人物A | 同类人物B | 关键区别 |
|:-----|:-------|:----------|:----------|:---------|
```

### 5.6 对抗验证报告

```
汇总4项测试结果，输出到 research/07-adversarial-verification.md

格式：
# 对抗验证报告：[人物名]

## 测试1：方向一致性 — X/5 ✅/❌
## 测试2：反向诱导 — X/5 ✅/❌
## 测试3：边界测试 — X/5 ✅/❌
## 测试4：辨识度测试 — ✅/❌

## 总体结论
通过/不通过
风险提示：3个
```

## 第七章：质量控制

### 7.1 三排查（检查清单——按顺序执行）

```

   skill_view(name) 能加载  → 确认SKILL.md有效
   确认YAML格式正确（name/category/description/tags）

□ 第三步：内容排查
   grep '^## ' 确认10章全部存在
   grep '🔴 H[1-6]' 确认对抗性假设≥6个
   grep '场景预测矩阵' 确认行为预测存在
   grep '使用示例' 确认示例存在
   wc -l ≥ 400行
```

```
□ 单步： skill_view(name) → 能加载，格式正确

         问1个边界问题 → 正确拒绝
□ 持久： 连续加载2次 → 输出稳定一致
```

## 第八章：常见错误与修正

### 8.1 Agent在自己执行时容易犯的错误

| # | 错误 | 表现 | 修正方法 |
|:-:|:-----|:-----|:---------|
| 1 | 调研只找支持性材料 | 缺少批评视角，对抗性假设单薄 | 强制web_search("X criticism") |
| 2 | 双轨变单轨 | 先读Agent-A再写Agent-B | 两个进程独立运行不通信 |
| 3 | 对抗性假设太温和 | "可能不太准确"而不是"会系统性失效" | 每个H必须带具体反例+后果 |
| 4 | 行为预测矩阵太模糊 | "牛市买入熊市卖出" | 必须指定触发条件+概率 |
| 5 | 诚实边界缺少交换逻辑 | 只列"不做的事"不解释"为什么不做" | 加「交换逻辑」段落 |
| 6 | SKILL.md不含对比定位 | 看不清这个人和别人的区别 | 加「对比定位」表 |
| 7 | 忘记更新research_date | 下次加载时不知道时效性 | YAML中必须写日期 |

### 8.2 当素材不足时的简化规则

```
如果公开素材不足（搜索<1000条），可以：
- 只做3个核心维度（著作/对话/外部视角）
- Agent-A和Agent-B基于同一份3维度素材提炼
- 对抗验证4项测试减为3项（去掉辨识度测试）
- SKILL.md减少到500行左右
- 在描述中标注"基于有限公开素材"
```
