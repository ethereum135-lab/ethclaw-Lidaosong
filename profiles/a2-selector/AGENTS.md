### Stage 1：硬条件过滤（保留——用于补充通道）

#### 过滤条件（AND逻辑——必须全部满足）

| # | 条件 | 阈值 | 说明 | 数据来源 |
|:-:|:----|:----:|:-----|:--------|
| 1 | 最低成交量 | ≥ $1M 24h | 流动性安全线，低于此无交易价值 | Binance 24hr ticker |
| 2 | 最低价格 | > $0.001<br>(暴跌反弹豁免) | 防止极低价格币的精度问题。**暴跌反弹币(24h跌幅>20%+反弹>10%)豁免价格条件** | Binance ticker/price |
| 3 | 最佳市值 | $10M - $1B | 中市值波段性最好，巨盘不涨，微盘没流动性 | CoinGecko/CG API |
| 4 | 非杠杆/稳定币 | 排除USDT/BUSD/DAI/杠杆代币 | 不能交易稳定币或杠杆产品 | Binance symbol filter |
| 5 | 费率中性 | -0.02% ~ +0.02% | 费率太负=空头拥挤有轧空风险，太正=多头拥挤跑路风险。**放宽到±0.02%避免把主流币因为微小偏差排除（如XRP差0.0008%、SOL差0.0062%）** | Binance FAPI premiumIndex |
| 6 | 非异常币 | 排除HONEYPOT/RUG/貔貅盘 | 排除明显有问题的新币 | A1热度数据交叉验证 |
| 7 | 暴跌反弹检测 | 24h跌幅>20%且当前反弹>10% | **新增：** 暴跌后的强力反弹是潜在机会，标记"⚠️暴跌反弹"保留进入Stage 2，不直接排除 | Binance 24hr ticker |

#### 技术实现

```python
def stage1_hard_filter(symbol: str, data: dict) -> dict:
    """硬条件过滤，返回pass/fail + 原因"""
    checks = {
        "volume_24h": data["volume"] >= 1_000_000,
        "price": data["price"] > 0.001,
        "market_cap": 10_000_000 <= data["mcap"] <= 1_000_000_000,
        "not_stablecoin": not any(s in symbol.upper() for s in ["USDT", "BUSD", "DAI", "USDC"]),
        "not_leveraged": "DOWN" not in symbol.upper() and "UP" not in symbol.upper(),
        "funding_rate": -0.0001 <= data["funding_rate"] <= 0.0002,
    }
    passed = all(checks.values())
    return {
        "passed": passed,
        "reason": " | ".join([f"{k}: {'✅' if v else '❌'}" for k, v in checks.items()])
    }
```

### Stage 2：五因子评分

#### 评分维度与权重

| # | 因子 | 权重 | 说明 |
|:-:|:----|:----:|:-----|
| 1 | 成交量异常 (Volume Anomaly) | 30% | 当前成交量相比基线是否异常放量——量是价的先行指标 |
| 2 | 动量结构 (Momentum Structure) | 25% | 趋势是否健康——EMA排列、价格位置、ADX方向 |
| 3 | 费率健康 (Funding Health) | 20% | 费率是否中性偏正——太负=轧空风险，太正=拥挤 |
| 4 | RSI位置 (RSI Position) | 15% | RSI是否在合理买入区间——30-50为最佳，<30超卖可关注 |
| 5 | 热度修正 (Heat Correction) | 10% | A1的热度数据+A2自己的社交热度判断——热度过高扣分(追高风险) |

#### 评分公式

```python
def stage2_scoring(coin_data: dict) -> float:
    """
    五因子加权评分，返回0-100分
    每个因子自身满分100，按权重加权
    """
    # 1. 成交量异常得分 (0-100)
    surge_ratio = coin_data["volume_current"] / coin_data["volume_baseline"]
    if surge_ratio >= 3.0:
        volume_score = 100  # 3x以上异常放量
    elif surge_ratio >= 2.0:
        volume_score = 80
    elif surge_ratio >= 1.5:
        volume_score = 60
    elif surge_ratio >= 1.0:
        volume_score = 40
    elif surge_ratio >= 0.5:
        volume_score = 20
    else:
        volume_score = 0  # 缩量一半以上

    # 2. 动量结构得分 (0-100)
    # EMA7 > EMA25 = 上升趋势中
    trend = coin_data["trend"]  # -2~+2
    trend_map = {2: 100, 1: 75, 0: 50, -1: 25, -2: 0}
    momentum_score = trend_map.get(trend, 50)

    # 3. 费率健康得分 (0-100)
    fr = coin_data["funding_rate"]
    if -0.005 <= fr <= 0.01:
        fr_score = 100  # 完美中性
    elif -0.01 <= fr < -0.005:
        fr_score = 70   # 略负，关注轧空可能
    elif 0.01 < fr <= 0.02:
        fr_score = 60   # 略正，关注拥挤
    elif -0.02 <= fr < -0.01:
        fr_score = 30   # 偏负
    elif 0.02 < fr <= 0.05:
        fr_score = 20   # 偏正
    else:
        fr_score = 0    # 极端

    # 4. RSI位置得分 (0-100)
    rsi = coin_data["rsi_14"]
    if 30 <= rsi <= 50:
        rsi_score = 100  # 最佳买入区间
    elif 50 < rsi <= 60:
        rsi_score = 70   # 动能向上但已错过最佳入场
    elif 20 <= rsi < 30:
        rsi_score = 60   # 超卖区，可关注反弹
    elif 60 < rsi <= 70:
        rsi_score = 40   # 偏热，追高风险
    elif rsi < 20:
        rsi_score = 30   # 深度超卖，可能是死亡螺旋
    else:  # > 70
        rsi_score = 0    # 超买，不进

    # 5. 热度修正得分 (0-100)，基础分50
    # 热度高≠不能追——宽度比恐惧更重要。有量有涨幅的币不因热度扣分
    is_trending = coin_data.get("is_trending", False)
    chg_24h = coin_data.get("change_24h", 0)
    if is_trending and chg_24h > 5:
        heat_score = 70   # 持续爆涨+热度=强者恒强
    elif is_trending and chg_24h > 0:
        heat_score = 50   # 微微涨+热度=正常关注
    elif is_trending and chg_24h < 0:
        heat_score = 30   # 跌了还热=出货盘
    else:
        heat_score = 50   # 不热不冷=中性

    # 加权求和
    total = (
        volume_score * 0.30 +
        momentum_score * 0.25 +
        fr_score * 0.20 +
        rsi_score * 0.15 +
        heat_score * 0.10
    )
    return round(total, 1)
```

#### 评分判读标准

| 分数区间 | 分类 | 动作 |
|:--------:|:----|:-----|
| ≥ 70分 | 🟢 候选池 | 推送给A3做深度评估 |
| 50-69分 | 🟡 待观察池 | 标记重点关注，不推送 |
| < 50分 | 🔴 排除 | 直接排除，不浪费A3时间 |

- A3验证A2数据的方式：按赛道权重排序后精选候选池中2-3个币，独立验证其评分数据

- ZH验证A2的方式：检查评分是否有规律性偏差（如"总是低评某些赛道"）

## 运维手册

### 常见问题

| 问题 | 原因 | 解决 |
|:----|:-----|:-----|
| 候选池长期为空 | 阈值设定可能过严 | 检查最近10天的排除原因分布，看是哪个条件频繁触发 |
| 某币评分异常高/低 | 数据源可能有误 | 独立查询该币原始数据进行验证 |
| A3反馈候选池质量差 | A3选的币不在候选池中 | 对比A3的选择和A2的评分，看是漏了还是A3判断不同 |
| A1数据延迟 | A1没准时产出 | 等待A1完成再执行，不随意猜测数据 |

### 验证方式

| 验证维度 | 方法 | 频率 |
|:--------|:----|:----:|
| 数据一致性 | 随机抽3个币对比Binance原始数据 | 每天 |
| 评分一致性 | 同评分段币种是否合理 | 每周 |
| 预测准确率 | 候选池中币种的后续10天涨跌统计 | 每周（A5协助） |
| 阈值合理性 | 是否有某条件永远在排除（过严）或从不排除（过松） | 每月 |
