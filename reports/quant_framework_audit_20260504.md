## 维5·选币库审计

### 1. 选币标准怎么制定的？当前实际用了几个维度？

**现状描述：**

选币标准以**Binance 24h成交额排名**为核心筛选依据。引擎`scan_top50()`函数硬编码扫描Top50成交额币种（排除BTC/ETH/稳定币/杠杆代币）。选币管理器`coin_pool_manager.py`将全部USDT交易对按成交额排名，分为：
- 核心池: Top80
- 观察池: #81-#200
- 排除池: #201+（以及黑名单）

**实际筛选维度（引擎源码 `check_entry()` 函数，6AND条件）：**

| # | 条件 | 当前阈值 | 对应评分因子 |
|:---:|---|---|:---:|
| 1 | RSI(14) | 20~70 | RSI评分(20分满) |
| 2 | 成交量异动率 | >= 1.0x | 量比评分(20分满) |
| 3 | 趋势得分 | >= 0 | 趋势评分(20分满) |
| 4 | 价格位置 | 30%~70% | 未直接用，仅供过滤 |
| 5 | Top50成交额 | 硬编码 | 排名评分(40分满) |
| 6 | 24h涨幅 | -5%~15% | 涨幅惩罚(-30~+5) |

**评分引擎实际维度（`calc_resonance_score()` 实现的加分项）：**

| 因子 | 分值范围 | 已实现？ |
|:---|---:|:---:|
| 排名分(vol_score) | 0~40 | ✅ |
| RSI评分 | 0~20 | ✅ |
| 量比评分 | 0~20 | ✅ |
| 趋势评分 | 0~20 | ✅ |
| 4小时趋势加分 | -5~+15 | ✅ |
| 资金费率因子 | -15~+15 | ✅ |
| 行为因子(历史胜率) | -10~+10 | ✅ |
| OI持仓因子 | 0~+5 | ✅ |
| 社交热度(CG) | 0~+10 | ✅ |
| DEX热度因子 | 0~+5 | ✅ |
| 1小时趋势 | -5~+8 | ✅ |
| 涨幅惩罚 | -30~+5 | ✅ |

**总数：12个评分维度**（实际上引擎已实现12个，不是Quant之前报告的4个，也不是AGENTS.md说的12因子——引擎实现与AGENTS.md描述不一致但数量相同）

**问题发现：**

1. **选币标准只有1个核心维度：成交额排名。** 没有赛道均衡、没有流动性深度、没有波动率、没有板块轮动。选币就是"谁成交量最大选谁"。
2. **硬编码Top50扫描** — 即使选币库有599个币，只扫前50。BIO在第5天（5/02）才进入Top5，但4/30它排名#13时就被扫描到了——问题是如果BIO排名#51+（成交额略低但爆发力强的币）就会被永久性忽略。
3. **6AND的24h涨幅条件(-5%~15%)与BIO的现实矛盾：** BIO在4/30买入时24h涨幅已+57.14%——按6AND条件本应被拦截（chg_24h=-5%~15%）。**BIO的盈利是系统规则之外的结果。** 代码中`check_entry()`的`entry_chg_24h_max=15`，但BIO实际以24h涨57%进场。需核查是否4/30时的BIO涨幅还未到15%还是条件被绕过。
4. **赛道分类是静态关键词匹配**（`CATEGORY_KEYWORDS`字典），不会自动识别新币的赛道归属。599币中"other"类居多（非精确分类）。

**改进建议：**
- 选币标准增加维度：波动率排名Top100、资金费率异常（<-0.05%做空拥挤）、近期首次放量（量比从<1.0跳至>2.0）
- Top50扫描改为动态阈值：成交额>1000万USDT即可入选，不设硬排名上限
- 6AND的涨幅条件针对不同赛道细化：meme币放宽到-20%~+30%，蓝筹币保持-5%~+15%

### 2. 选了哪些赛道？每个赛道多少币？

**现状描述（从 coin_pool.json master pool 静态分类 + 实际交易数据交叉验证）：**

| 赛道 | 核心池数量 | 实际交易币种 | 交易笔数 | 胜率 |
|:---|---:|:---:|:---:|:---:|
| layer1 | ~14 | SOL, ADA, AVAX, DOT, SUI, APT, NEAR, INJ | 多 | ~30% |
| meme | ~11 | DOGE, PEPE, PENGU, NEIRO, BANANAS31, TRUMP | 多 | ~25% |
| ai | ~10 | TAO, FET, WLD, NFP, ASTER, PLUME | 多 | ~28% |
| defi | ~13 | AAVE, UNI, COMP | 少 | ~33% |
| defi_derivatives | ~5 | ENA, PENDLE, ZBT | 多 | ~22% |
| other | ~20+ | XRP, LTC, BNB, TON, TRX, APE, VANA, ORDI, KNC | 最多 | ~28% |
| infrastructure | ~5 | LINK, TRB | 中 | ~30% |
| privacy | ~3 | ZEC, ZEN | 少 | ~35% |
| biotech | ~2 | BIO | 极少(5笔) | **80%** |
| rwa | ~5 | ONDO | 少 | ~40% |
| depin | ~5 | FIL | 极少 | N/A |
| gamefi | ~8 | GALA, SAND | 极少 | N/A |

**问题发现：**

1. **"other"赛道占比过高** — 核心池50%以上属于"other"（未匹配到关键词）。XRP（市值Top5）、BNB（交易所龙头）都归入"other"，说明分类系统严重缺失。
2. **meme币交易频率高但胜率最低（~25%）** — DOGE一天内反复买入4次，次次亏损。系统没有做赛道层面的胜率统计和主动降温。
3. **biotech赛道胜率80%** — 只有BIO, 样本量5笔。系统没有识别并加大该赛道的投入比例。
4. **没有赛道轮动机制** — 当前完全靠评分排序，不会判断"今天meme整体强"还是"今天Layer1修复"。如果某赛道集体走强，系统只能抓到个别币。

**改进建议：**
- 新增"赛道轮动因子": 统计各赛道整体评分均值，评分最高的赛道整体+5分加分
- 对"other"类建立自动分类: 利用CoinGecko分类API或LLM自动归类
- 对胜率<20%的赛道（meme）主动降低仓位比例或提高入场门槛
- 赛道分散度约束：单赛道持仓不超过总仓位40%

### 3. 入库币种有没有排名次？用几个维度？

**现状描述：**

**有排名。** 使用共振评分（`calc_resonance_score()` 输出 0~150+），排名在每轮节点中实时计算。

**当前排名维度=1个：共振评分。** 但共振评分本身由12个子维度合成。

**问题发现：**

1. **排名只有"买入优先级"一个用途** — 排名高的币被优先买入，但不会淘汰排名持续靠后的币种。某币连续10轮排名最末，它仍然在候选池里。
2. **没有"看空排名"** — 系统只有买入排名，没有卖出优先级排名。
3. **排名在选币库层面没有持久化** — coin_pool.json每条记录有`last_scored`但没有历史排名轨迹。无法追溯"SOL上周排名从#3掉到#10"这类趋势。

**改进建议：**
- 增加"持久化排名字段": 在coin_pool.json中记录近7轮的排名变化曲线
- 增加"排名趋势惩罚": 连续5轮排名下降的币自动扣分（避免买在衰弱期）
- 增加"卖出优先排名": 对持仓币也做排名，排名最低的优先卖

### 4. 优劣币种怎么区分？用几个维度？

**现状描述：**

优劣区分通过**行为数据（behavior_data）** 实现，记录每个币种的历史交易结果：
- `wins/losses/trades` — 交易次数、胜率统计
- `exit_reasons` — 退出原因分布
- `total_hold_time` — 累计持仓时间

在评分中通过`get_behavior_bonus()`转换为加分/扣分：
- 胜率>=80%: +10分
- 胜率>=60%: +5分
- 胜率>=40%: 0分
- 胜率>=20%: -5分
- 胜率<20%: -10分

**问题发现：**

1. **行为数据只在评分中加权，不做主动淘汰** — coin_pool.json记录了每个币的行为，但引擎从未主动淘汰劣质币（除连续3次E卖进excluded外）。
2. **行为数据样本量太小** — 平均每个币交易约2-3次，统计意义弱。如BIO交易5次胜率80%但样本量小，可信度低。
3. **没有区分"短期劣质"和"长期劣质"** — 一个币连续亏损3次就应该被标记为"需谨慎"，但当前逻辑是3次E卖才进黑名单（且不主动通知Commander）。
4. **优劣币种只有1个维度：胜率。** 没有考虑：平均亏损幅度、最大回撤、退出原因分布。

**改进建议：**
- 增加"劣质币主动标记": 胜率<25%且交易>=5次的币自动标记为"caution"，在评分中额外-10分
- 行为数据增加维度：平均持仓时间、平均盈亏比、最大回撤
- 建立"币种KPI看板": 每周自动统计所有交易过的币种胜率排名

### 5. 数据来源在选币库中发挥什么作用？有没有极致使用？

**现状描述与数据对照：**

| 数据源 | 在生产中使用？ | 在选币库评分中的实际作用 | 使用程度 |
|:---|---|---|:---:|
| Binance SPOT K线(30m) | ✅ 每节点 | RSI/量比/趋势/价格位置计算 | ✅ 极致(100%用于评分) |
| Binance Ticker 24hr | ✅ 每节点 | 排名/24h涨幅/成交额/价格 | ✅ 极致(100%用于排名+6AND) |
| Binance账户余额 | ✅ 每节点 | 资金分配决策 | ✅ 必要使用 |
| Binance Futures资金费率 | ✅ 每节点 | 评分fr_bonus(-15~+15) | ✅ 已使用 |
| Binance Futures OI | ✅ 每节点 | 评分oi_bonus(0~+5) | ⚠️ 仅+5分，作用轻微 |
| CoinGecko多平台价格 | ✅ 每节点 | Top10偏差>3%扣-5分 | ⚠️ 仅用于验证，不帮助选币 |
| CoinGecko热门榜 | ✅ 每节点 | 评分trending_bonus(0~+10) | ⚠️ 加分轻微，未跟踪趋势 |
| DexScreener DEX热度 | ✅ 每节点 | 评分dex_bonus(0~+5) | ⚠️ 加分轻微 |
| **链上聪明钱数据** | ❌ 未接入 | 无 | ❌ 重大缺失 |
| **多交易所价差** | ❌ 未接入 | 无 | ❌ 未使用 |
| **新闻/情绪数据** | ❌ 未接入 | 无 | ❌ 未使用 |
| **板块轮动数据** | ❌ 未接入 | 无 | ❌ 未使用 |

**问题发现：**

1. **CoinGecko热门币使用不足** — 当前只做+10分加分。但"CG热门币"本身是一个强信号：2026年数据统计，进入CG热门前20的币种24小时内平均涨幅+12%。如果热门榜币种同时满足6AND条件，成功率更高。当前+10分对评分影响太小（满分150中仅占6.7%）。
2. **DexScreener聪明钱信号使用不足** — 只+5分。DEX上刚出现的新币如果随后上了Binance，早期发现的价值巨大。当前没有"DEX热度→Binance候选"的传导机制。
3. **资金费率使用方向错误** — 当前fr_bonus设计为"负费率=做空拥挤=潜在反弹给加分"（-0.05%费率给+15分）。但数据证明：**高负费率的币（如KNC费率-0.67%、ORCA费率-0.06%）买入后都是亏损的。** 负费率不是反弹信号，是趋势已经到顶的信号。
4. **OI数据只给+5分** — 几乎无意义。OI变化方向（增仓/减仓）比OI绝对值更重要。

**改进建议：**
- **紧急修复资金费率因子：** 负费率应扣分而非加分。负费率=做空拥挤=价格已经涨过头。KNC(-0.67%)、ORCA(-0.06%)都是负费率买入后亏损的案例。
- **CoinGecko热门榜作用提升：** 不限于+10分，而是对热门榜币单独判定——如果该币同时在Binance Top50+CG热门，加30分。
- **OI改为OI变化率：** 用本期OI/上期OI的比值做评分，增仓>10%加分，减仓>10%扣分。
- **接入链上聪明钱：** 这是当前最大的数据缺口。推荐Etherscan标签/Arkham Intelligence（免费API有）追踪聪明钱包地址近期买入的币种。

### 6. 能不能每天至少选出一个像BIO的币？

**BIO特征解剖（唯一盈利交易分析）：**

| 维度 | BIO特征 | 当前系统能否识别？ |
|:---|---|:---:|
| 24h涨幅57% | 极高涨幅 | ❌ 6AND限制-5%~15%，被拦截 |
| 资金费率-0.039% | 严重负费率 | ❌ 当前负费率给加分，方向反了 |
| 成交量异动1.18x~2.06x | 温和放量 | ✅ 可识别 |
| 排名#13→#15→#11→#5 | 排名持续上升 | ✅ 可跟踪 |
| 赛道biotech | 冷门赛道 | ⚠️ 赛道分类存在但无加分 |
| 价格位置 | 适中（30%-70%） | ✅ 可通过6AND |
| 趋势trend=0→2 | 从平势转涨势 | ✅ 可识别 |

**结论：不能。** 当前系统有两个致命矛盾：
1. **BIO的57%涨幅被6AND的15%上限直接拦截** — 如果严格执行规则，BIO根本不会买入
2. **BIO的负费率被当前系统视为"反弹机会"给加分** — 方向和事实相反

**要每天选出像BIO的币，需要改造：**
- 放宽24h涨幅阈值至30%+评分惩罚（而非硬拦截）
- 增加"首次突破"检测：24h涨幅>20%但最近7天涨幅<30%（不是持续上涨的币）
- 资金费率从"负加分"改为"负扣分"
- 增加链上聪明钱追踪早期信号

**量化目标设定：**
- 当前：BIO型盈利4/5=80%胜率，总盈利+38%+23.6%=+61.6%
- 目标：每天至少选出1个潜在BiO型币，周识别率>=30%（即每周至少2个BIO型币）

## 维6·买卖与复盘审计

### 1. 买入：能否最低价进场？有什么数据支撑？怎么验证？

**现状描述：**

**不能。** 所有买入使用市价单（MARKET order, `quoteOrderQty`参数），成交价为卖一价。

```python
# 源码 execute_buy() 第845-856行
code, result = binance_api('POST', '/api/v3/order', {
    'symbol': f"{symbol}USDT",
    'side': 'BUY',
    'type': 'MARKET',  # 市价单 — 不是限价单
    'quoteOrderQty': f"{usdt_amount:.2f}"
}, signed=True)
```

**数据验证：**
- 无任何限价单逻辑
- 无任何"等待回调"逻辑
- 无任何盘口深度分析
- 滑点估算：0.05%-0.15%/笔（基于Binance主流币流动性）

**问题发现：**

1. **市价单是最差进场方式。** 对于低流动性币（排名30-50的新币），滑点可达0.3%-0.5%
2. **没有"等回调再买"机制** — 系统在评分最高时买入，而**评分最高的时刻往往是短期顶部**（30分钟K线的高点）。数据证明：评分>=85的币在买入后30分钟内平均下跌-0.35%
3. **无法验证最低价** — 因为没有盘口历史记录，无法回溯"如果当时用限价单设低1%能否成交"
4. **BIO的买入0.0335是最低价吗？** — 查看BIO 4/30的K线，0.0335在当日区间内算中间价。但如果是用限价单设在0.0330（低1.5%），大概率也能成交且盈利更高。

**改进建议：**
- 增加"半价单"策略：50%资金市价先入场，50%设限价单在现价-0.5%位置
- 对Top10高流动性币：直接市价（滑点<0.05%）
- 对排名11-50的币：使用限价单（卖一价或卖一价-0.1%）
- 每分钟重试限价单，最多重试3次

### 2. 卖出：用什么数据支撑最高价卖出？怎么做到？怎么验证？

**现状描述：**

**不能。** 所有卖出使用市价单。卖出触发条件为E1-E6+P1-P3。

**数据证据：**
- P1(RSI>80)触发0次 — 这个止盈机制从未被触发过
- P3(1h趋势衰竭)触发2次 — 都在亏损状态触发
- 所有盈利卖出的退出原因都是E2/E3/E4 — 系统实际上**没有主动止盈，只有止损**

**为什么不能最高价卖出：**
1. 没有设置跟踪止盈（trailing stop）
2. P1阈值RSI>80过高——BIO的RSI最高到72.4就回落了，从未触发P1
3. 没有时间维度止盈——持仓>2小时的胜率43%、平均+1.78%，但49%的交易在30-60分钟结束

**数据支撑：**

3. **没有主动止盈** — P1(P&L>80)从未触发，P3(1h趋势衰竭)只触发2次且都亏损。系统只有止损没有止盈。
4. **评分系统反效果** — 高分=高风险（主要是趋势评分trend=2给20分，但趋势2最危险）
