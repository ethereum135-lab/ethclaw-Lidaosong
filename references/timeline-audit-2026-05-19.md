# 全局时间线排查

## 当前链的时间线（BJT）

```
05:00  赛道热度——————————————（ZH，每日）
05:30  方向融合——————————————（ZH，每日）
06:00  A2旧脚本评分——————————（no_agent，每日）
06:00  A3信号扫描→signals.json——（no_agent，每日，用前一天的精选池）
07:00  A3 LLM→出报告————————（LLM，每日）
07:30   ─── A4开始读A3报告 ─────
08:00  A2全量更新+精选池→新数据——（no_agent，每日）
          ↑ 但A3已经跑完了！
          ↑ A3用的永远是昨天的池子
12:00  A4还在读同一份A3报告
18:00  A4还在读同一份A3报告
23:00  A4还在读同一份A3报告
```

## 三个全局问题

### 问题1：A3和A2时间反了（🔴严重）
```
现在: A2 08:00 → A3 07:00(次日) → A3永远滞后A2一天
正确: A2 → A3(同日) 
```
A3的精选池数据源永远是昨天08:00的。

### 问题2：A4读一份报告读24小时（🟡中）
```
A3 07:00出报告 → A4 07:30开始读 → 读到第二天07:00
A4每30分钟跑一次，但推荐币24小时不变
下午2点赛道突变 → A4还在买早上推荐的币
```

### 问题3：没有反馈环（🔴严重）
```
A4买了A3推荐的币 → 赚了还是亏了？ → A2/A3不知道
这个信息需要回到系统影响明天
Freqtrade有FullTradesFilter，我们没有
```

## NFI为什么没有这个问题？

```
NFI：每5分钟跑一次（连续运行）
  每5分钟：
    对所有70个币重算指标
    重新检查所有买入条件
    有信号就出，没信号就不出

我们：cron间隔触发（日频）
  A2一天一次
  A3一天一次  
  A4每30分但读的是一份日频报告
```

Freqtrade是连续运行的，我们是离散触发的。时间缝隙是结构性的。

## 解决方案

### 方案A：调整时间线（最低成本）
```
05:00  A2全量更新+精选池 ← 从08:00改到05:00
06:00  A3信号扫描（用当天精选池）
07:00  A3 LLM出报告（用当天信号）
07:30  A4执行
```
A2改到05:00跑 → A3 07:00用当天数据，不再滞后一天。

### 方案B：A4直接从signals.json读（半实时）
```
A3信号扫描 → 每4-6小时跑一次（no_agent，免费）
              产出signals.json，含实时技术信号
A4每30分钟 → 读signals.json（不是等A3报告）
            + 读A3报告（每日一次，辅助叙事判断）
```
A4的执行不再绑定A3报告的频率。信号扫描可以跑多次。

### 方案C：反馈环
```
A4执行记录 → 写入选币库behavior → 
              第二天A2/A3读behavior → 调整选币/赛道/标准
```
已在coin_pool_manager.py的record_trade功能里，但没有任何Agent在读behavior。
