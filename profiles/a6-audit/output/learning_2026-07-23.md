## 学到的3个要点

### 要点1：SRE自愈机制 vs ZQ的审计标记瓶颈

Google SRE核心原则：**系统应自动降级而非依赖人工介入**。当某组件故障时，自动切换/重试/回退。反观ZQ：A4 ghost signal连续29周期重复同一信号，系统无自愈逻辑——只是重复推AWS、重复记state。审计发现→报告→ZH行动是一个**被动人工链**，无SRE意义上的自愈。

**对A6的启示：** 审计发现应区分「可自愈型故障」和「需人工介入型故障」。可自愈型（如信号缓存过期→重启信号管道）应附带自愈提案；需人工型（如MIN_NOTIONAL尘埃仓）才升级到ZH。

### 要点2：审计阈值 → SLO映射 + Burn Rate告警

将A6审计标准映射为SLO（Service Level Objective）：
- 偏差率<5% = SLO 99% (1周≤1笔超标)
- 偏差率>10% = SLO违约（SLA breach）

SRE的burn rate alerting理念：不等到SLO窗口结束才发现违约，而是**在预算消耗速度异常时提前告警**。映射到A6：不等到偏差率>10%才标记🔴，而是**当偏差率从4%飙升到8%的速率时提前预警**（现有趋势面板的进化版）。

### 要点3：故障依赖图（Dependency Graph）审计

从近期实操（A4 ghost signal + 资本窒息 + 数据源分歧）提炼：A4的执行决策是一个**依赖链**：
```
A1数据时效 → A2候选池 → A3推荐质量 → USDT可用性 → A4执行
```
任何一个依赖断裂，下游输出都是噪声。当前A6按Agent独立审计，不检查依赖链。

**新审计维度：** 在每周审计中增加「依赖链完整性检查」——检查A1→A3→A4三个层级的latest产出时间是否覆盖同一时间窗口。如果A1数据是05:00而A3用的是07:00数据，标记时差；如果A4状态正常但USDT=0，检查是否A3的推荐消耗了计划外资金。

## 怎么让A6的审计质量更高？

1. **增加SRE自动降级检查**：每轮审计加一项「系统自愈性检查」——识别已经持续N周期但没有自愈机制覆盖的故障模式
2. **Burn Rate预警替代静态阈值**：偏差率3周连续上升（即使都在<5%内）应自动升级到🟡，不等突破阈值
3. **依赖链完整性检查**：每周审计增加A1→A3→A4时间窗口一致性扫描，在数据源分歧演变为执行偏差前预警
