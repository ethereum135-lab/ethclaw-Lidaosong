## 🔑 要点一：大额转账的意图分类 — 90%的"鲸鱼警报"是噪声，只有方向性转移才是信号

**核心发现：** Deep Blue Alpha 2026研究指出，绝大多数鲸鱼级别交易是**运营行为**而非方向性信号：交易所热钱包再平衡、资金归集、OTC结算、跨链桥转账、智能合约交互。这些按"大额"标准触发警报，但携带**零方向性信息**。OnChainFlows的研究同样强调：Big transfer ≠ directional trade。

**A8当前的盲区：** 步骤③+步骤⑦中，Etherscan和Dune只按金额过滤(>$500K/$100ETH)，产出的MONEY_IN信号中可能80-90%是运营性转账而不是真实买入信号。老李不需要知道"USD从交易所A转到交易所B"，他需要知道"大钱在买什么币"。

**A8可以实现的四级意图分类（仅用现有数据源，零额外API Key）：**

| 类别 | 转账模式 | 占大额比 | A8动作 | 示例 |
|:----|:---------|:-------:|:-------|:-----|
| **🔴 方向性买入** | 非交易所地址→个人冷钱包/DeFi池 | ~5-10% | 最高权重，A3+20分 | 新地址从CEX提取大量ETH长期持有 |
| **🟢 方向性卖出** | 冷钱包/个人地址→交易所热钱包 | ~5-10% | 标记OUTFLOW，A4减仓参考 | 休眠鲸鱼地址突然向交易所转账 |
| **🟡 运营性归集** | 热钱包↔热钱包 / 交易所内部地址 | ~60-70% | 忽略(汇总到CEX净流量) | 交易所冷钱包向热钱包补充流动性 |
| **⚪ 跨链/桥中** | 跨链桥合约+多签名地址 | ~10-15% | 降级记录，标注`bridge_transit` | Arbitrum→Ethereum跨链桥操作 |

**实现方案（在`a8_data_fetch.py`步骤③新增`classify_transaction_intent()`函数）：**

```python
# 交易意图分类器 — 基于地址标签+转账模式推理
# 输入：tx记录(from, to, value, tx_hash)
# 输出：INTENT_CLASS + CONFIDENCE

def classify_transaction_intent(tx: dict, address_labels: dict) -> dict:
    from_label = address_labels.get(tx['from'], 'unknown')
    to_label = address_labels.get(tx['to'], 'unknown')
    
    # ⚠️ 注意：current address_labels.json 仅16个ETH地址
    # 以下逻辑依赖已有的Etherscan核心追踪地址
    # 未来扩展后可逐步细化分类精度
    
    # 场景1: 非交易所地址 + 非交易所地址 = 鲸鱼个人转账（高价值信号）
    if 'exchange' not in from_label and 'exchange' not in to_label:
        # 但需要排除: 跨链桥/DeFi合约（通过统计发币量或标签）
        if to_label in ['bridge', 'defi_contract', 'multi_sig']:
            return {'intent': 'bridge_transit', 'confidence': 0.6, 'action': 'LOW'}
        return {'intent': 'directional_unknown', 'confidence': 0.5, 'action': 'MONITOR'}
    
    # 场景2: 非交易所→交易所热钱包 = 潜在卖出
    if 'exchange' not in from_label and 'exchange' in to_label:
        return {'intent': 'directional_sell', 'confidence': 0.7, 'action': 'ALERT'}
    
    # 场景3: 交易所热钱包→非交易所地址 = 潜在买入/提取
    if 'exchange' in from_label and 'exchange' not in to_label:
        return {'intent': 'directional_buy', 'confidence': 0.7, 'action': 'ALERT'}
    
    # 场景4: 交易所↔交易所 = 运营性归集 → 忽略,但计入CEX净流量
    if 'exchange' in from_label and 'exchange' in to_label:
        return {'intent': 'operational_rebalance', 'confidence': 0.9, 'action': 'IGNORE_SILENT'}
    
    # 场景5: 未知地址两侧 = 保守降级
    return {'intent': 'unknown', 'confidence': 0.3, 'action': 'LOW'}
```

**预期效果：** MONEY_IN信号量从每轮50-90条降至5-10条方向性信号，噪声去除率约85%，A3/老李只看有效信号。

## 🔑 要点二：从"单笔追踪"升级为"钱包群组净流量聚合" — 个体噪声 vs 群体趋势

**核心发现：** AI Trade Lab 2026研究和CoinXSight的研究都指向同一方法论：**单个CEX转账毫无意义，但钱包群组的聚合净流量趋势才是真信号。** Nansen的Smart Money Netflows API将追踪粒度从"单个地址"提升到"smart money群组净流入/净流出"；Glassnode的Supply by Investor Behavior从成本基分布深入到"谁在买、谁在卖"的行为层。

**当前A8的局限性：** 步骤③追踪固定16个ETH地址，产出MONEY_IN信号时逐条列出（"ETH|USDT|900000|in|0x1a83782223"）。老李看到一堆地址哈希，既不知道这些地址是干什么的，也看不出资金是进是出。

**关键改进方向：钱包群组聚合 + 净流量趋势**

A8不需要追踪"每个钱包"在做什么，而是追踪**钱包群组**的集体行为。如果我们把已知地址分为3个群组：

| 群组 | 包含 | 追踪方式 | 信号规则 |
|:----|:-----|:--------|:--------|
| **CEX热钱包组** | 交易所充值地址/热钱包 | 现有16个ETH地址扩展+地址标签 | 净流出>$5M/2h=机构囤积；净流入>$5M/2h=抛压 |
| **做市商组** | Wintermute/Jump/Amber/GSR | 新加入10-15个公开做市商地址 | 大额异动>$2M标为MarketMakerSignal |
| **休眠鲸鱼组** | >30天无活动的>1000ETH地址 | 动态发现(通过Dune查询) | 突然激活 = 最高权重信号 |

**净流量聚合算法示例：**

```python
# 钱包群组净流量聚合 — 替代逐条列转账
# 输入：群组内所有tx（2h滚动窗口）
# 输出：净流量信号

def aggregate_group_netflow(txs: list, group: str, window_h: int = 2) -> dict:
    """群组净流量计算 — 忽略内部转账，只算外部净流向"""
    # 交易所群组：内转(热↔冷)不计入外部净流量
    net_in = sum(tx['value'] for tx in txs if tx['direction'] == 'in')
    net_out = sum(tx['value'] for tx in txs if tx['direction'] == 'out')
    net_flow = net_in - net_out
    
    # 三态输出
    if net_flow < -5_000_000:  # 净流出>$5M（出>入=负值）
        return {'signal': 'OUTFLOW', 'netflow_usd': net_flow, 
                'interpretation': f'{group}净流出${abs(net_flow/1e6):.1f}M/2h — 机构提币屯积'}
    elif net_flow > 5_000_000:  # 净流入>$5M
        return {'signal': 'INFLOW', 'netflow_usd': net_flow,
                'interpretation': f'{group}净流入${net_flow/1e6:.1f}M/2h — 抛压信号'}
    else:
        return {'signal': 'NEUTRAL', 'netflow_usd': net_flow,
                'interpretation': f'{group}净流量平衡'}
```

**预期效果：**
- 不再逐条列50-90条转账记录
- 每张报告变成**1行群组摘要**（"CEX热钱包组净流出$8.2M/2h"）
- 老李一眼看懂资金流向，不需要看地址哈希
- A3只需要读净流量信号而不是逐条转账

## 🔑 要点三：综合信号优先级排序模型 — 三步将A8的"并发噪声"转化为"行动优先级"

**核心发现：** Rounds 1-3的每轮学习都在扩展A8的信号来源，但**信号不是越多越好**。CoinXSight的研究指出：多信号源的挑战不是数据不足，而是如何在一堆相互矛盾或相关度各异的信号中**决定先看哪个**。Neutralis的研究同样强调：多数大额转账信号被误读的原因是**没有优先级排序**。

**当前A8信号体系的问题：** INFLOW信号(每15分钟) + MONEY_IN信号(每15分钟) + Dune whale信号(每5分钟) + BSC/Arb信号(每15分钟) → 同时发出20-100+条信号 → A3/A4/A8都不知道先处理哪一个。

**三步优先级排序模型（全链条，零新增API成本）：**

### Step 1: 信号分级（入站时打标签）

| 优先级 | 条件 | 处理时限 | A3加分 |
|:------|:-----|:--------:|:------:|
| **P0 紧急** | 方向性买入 + 群组净流出>$5M + 该币在signals.json >90分 | 立即通知 | +30分 |
| **P1 高** | 方向性买入/卖出 + 群组净流向明显 + 该币在signals.json 70-89分 | 本轮处理 | +20分 |
| **P2 中** | 运营性但该币在coin_pool + 成交额质量mid+ | 排入下轮 | +10分 |
| **P3 低** | 运营性或非选币库币 | 存档 | +0分 |
| **P4 资讯** | 跨链桥/合约交互/技术性转账 | 周汇总附录 | 不报 |

### Step 2: 同类信号折叠（避免重复推送）

同一币种的同一方向信号在30分钟内：
- 取最高优先级，不累加
- 写入JSON的 `recent_hits` 字段作为计数，推送时写"最近30分钟N次确认"
- 示例：PEPE在INFLOW中3次出现 → 推送写"PEPE持续资金流入(30min内3次确认)"

### Step 3: 交叉验证（只有N层独立的信号才报T0）

| 交叉条件 | 报告层级 |
|:---------|:--------:|
| DEX成交量(INFLOW) + 群组净流出(MONEY_IN) + 有选币库币 | **T0 - 强信号** |
| DEX成交量(INFLOW) + 选币库币 | T1 - 参考 |
| 只有DEX成交量，不在选币库 | T3 - 存档 |
| 只有MONEY_IN，不在选币库 | T4 - 忽略 |
