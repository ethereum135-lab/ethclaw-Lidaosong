## 3条核心要点

### 🟢 要点一：三层过滤模型的"根源误报"审视 — 每个层级都有结构性缺陷

**C1原始三层过滤模型：**
```
L1 关键词匹配 ─→ L2 来源权重筛查 ─→ L3 市场验证 → 告警
```

**C1-Re视角升级：每个层级不是"有就好的"，而是"有结构性缺陷的"：**

#### L1（关键词匹配）的结构性缺陷

| 缺陷 | 表现 | A7实盘影响 | C1-C4积累的解决方案 |
|:----|:-----|:----------|:------------------|
| **正负失衡** | "buy""pump""moon"等正向词过多，"sell""dump"等负向词过少 | 系统对正面的敏感度远高于负面——但负面消息（黑客/监管）对市场影响往往更大 | **C1-Re修复：** 维护正负词库平衡，至少1:1。负面词权重应为正面的1.5-2倍（符合A7"宁可漏报不可误报"的原则——负面信号更容易被漏掉） |
| **反讽不可检测** | "To the moon!" 在下跌行情中是反讽，在上涨行情中是真诚 | 简单关键词匹配会误判方向 | **C4 FinBERT-Crypto** 可识别上下文语气，但A7还未接入 |
| **同义词覆盖不完整** | "rapidly approaching zero" ≠ 含任何关键词但显然是看空 | 漏掉大量间接表达 | **C3 SBERT嵌入相似度** 可做语义级匹配而非关键词级 |

**C1-Re修复方案：关键词体系的结构化升级**
```markdown
# 结构性关键词体系（代替扁平列表）

## 正面向量（每个词附带强度分）
| 关键词 | 强度 | 分组 | 示例上下文 |
|:------|:----:|:----|:----------|
| buy | 2 | 行动级 | "I'm buying BTC" |
| accumulate | 2 | 行动级 | "accumulating more" |
| bullish | 1.5 | 情绪级 | "very bullish on ETH" |
| pump | 3 | 靶向级 | "this coin will pump" |

## 负面向量（权重1.5x）
| 关键词 | 强度 | 分组 | 示例上下文 |
|:------|:----:|:----|:----------|
| sell | 2 | 行动级 | "selling everything" |
| hack | 3.5 | 事件级 | "hacked for $50M" |
| scam | 3 | 事件级 | "confirmed scam" |
| dump | 2.5 | 行动级 | "massive dump incoming" |
```

#### L2（来源权重筛查）的结构性缺陷

| 缺陷 | 表现 | 解决方案 |
|:----|:-----|:--------|
| **静态权重** | Elon永远是10分，但实际上他的影响力在衰减（2025年后推文影响力下降） | **C4滚动MIS动态权重**（KOL影响力评估C4产出）：每条推文记录15min价格影响，滚动30条加权平均 |
| **缺乏反权重** | 高权重来源不总是正确的——CZ宣布BUSD下架时说的"用户资金安全"后来证明不准确 | 增加"可靠性衰减系数"：如果某KOL的推文被后续事实证明错误，其权重下降20% |
| **没有冷启动** | 新KOL（例如SOL上的新大V）初始权重未知 | 初始权重设置为2（行业KOL平均水平），滚动前10条推文后根据实际影响力调整 |

#### L3（市场验证）的结构性缺陷

| 缺陷 | 表现 | 解决方案 |
|:----|:-----|:--------|
| **单一维度** | 只检查价格变动 | 应该同时检查成交量、资金费率、未平仓合约——真正的KOL影响会同时影响多个维度 |
| **时间窗口固定** | 5min前后检查涨跌>1%，但不同KOL的影响时间不同（Elon: 30秒；CZ: 5-15分钟；Saylor: 30分钟） | KOL特定时间窗口：Elon 2min, CZ 10min, Saylor 30min |
| **无法区分因果** | 涨了但不知道是不是因为这条推文 | C4的**Granger因果检验**（KOL评估C2产出）+ **最小化交易量检测**：推文发布前3分钟成交量应明显低于推文后 |

#### ✅ C1-Re三层过滤模型升级版

```
L1 结构化关键词体系（正负平衡1:1, 语义级匹配）
 │   → 新增：反讽检测 + 同义词嵌入 + 事件型关键词权重上调
 ↓
L2 动态KOL权重（滚动MIS, 可靠性衰减, 冷启动初始值）
 │   → 新增：Granger因果前置过滤 + 反权重机制
 ↓
L3 多维市场验证（价格+成交量+费率+OI, KOL特定时间窗）
 │   → 新增：多维度同时异动才确认 + 因果方向判断
 ↓
┌──────────────────────────────────────┐
│ 最终输出：告警 或 静默               │
│   → 还经过误报过滤（C3 FDR+CUSUM+MAB │
│      + C4 ActiveLearning+元学习）    │
└──────────────────────────────────────┘
```

**核心升级不在于"加了更多层"，而在于"每个层级减少了自身产生误报的结构性原因"。**

### 🟢 要点二：源头预防 vs 末端过滤 — 两种误报控制哲学的权衡

A7在C1→C4的演进中，花费了大量精力在**末端过滤**（误报产生了再过滤掉）。但更高效的策略是**源头预防**（让误报根本不会产生）。

#### 两类误报的对比

```
                    ┌─────────────────────────────────────┐
                    │           源头预防                   │
                    │  L1结构化关键词体系                    │
                    │  L2动态KOL权重                       │
                    │  关键词正负平衡                       │
                    │  反讽/语义级匹配                      │
                    └─────────────────────────────────────┘
                               │
                    ┌──────────▼──────────┐
                    │  信号进入候选池     │
                    │  (理论上已经是高质量)│
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │        末端过滤     │
                    │  C1: 时间窗去重     │
                    │  C3: FDR控制        │
                    │  C3: CUSUM变化点    │
                    │  C4: ActiveLearning │
                    │  C4: AnomalyTransformer │
                    └─────────────────────┘
```

| 维度 | 源头预防 | 末端过滤 |
|:----|:--------|:--------|
| 时机 | 信号进入候选池之前 | 信号进入候选池之后 |
| 工作量 | 一次设计，长期受益 | 每新增一个过滤条件就多一份维护成本 |
| 灵活性 | 低（需要预先知道误报模式） | 高（可以动态调整过滤强度） |
| 维护成本 | **低**（关键词+KOL权重表格） | **高**（FDR阈值/CUSUM窗口/MAB探索） |
| A7当前覆盖 | ⚠️ 部分（L1/L2被C1定义但未结构化升级） | ✅ 全部覆盖（C1→C4都在做） |
| 误报减少潜力 | ~50%源头消除 | ~30%末端滤除（剩下的已经被源头污染） |

#### C1-Re核心洞察：A7的误报问题70%来自源头，不是末端

从实盘经验看：

1. **涨幅榜打标误报**（2026-06-02 FET漏标）：根源在叙事检测的逻辑缺陷（symbol不含叙事关键词就跳过），不是FDR或CUSUM能解决的。如果源头检测好了，后端根本不需要过滤。→ **修复：已知symbol→叙事映射表**

2. **网络阻断时的"静默跳过"导致的监控盲区**：根源是GFW阻断（系统级问题），后端过滤再强也过滤不了"不存在的数据"。→ **修复：VPN/代理基础设施**

3. **时间戳错误（如01:15写成08:15）**：根源在模型的时间感知偏差，不是过滤能解决的。→ **修复：强制命令获取BJT时间**

#### 源头预防的具体操作指南

| 问题类型 | 源头预防方案 | 对应A7产出 |
|:--------|:-----------|:---------|
| 关键词正负失衡 | 维护正负1:1词库，事件级关键词上浮权重 | 更新config.yaml keywords |
| KOL静态权重 | 每周滚动MIS更新权重 | 自动化MIS计算脚本 |
| 时间戳错误 | 所有输出使用`date '+%Y-%m-%d %H:%M BJT'` | 已内置到所有alert模版 |
| 叙事检测死区 | 已知symbol→叙事映射表 | 已在SKILL中定义 |
| 新KOL冷启动 | 初始权重2，10条推文后动态调整 | 新增冷启动模块 |
| 反讽/歧义 | 同方向多源确认后才告警 | 社区共振检测（KOL评估C2产出） |

**原则：能源头解决的就不要留到末端处理。** 每次发现新的误报模式，先问"能否在L1/L2就阻止它"，再问"末端过滤能否捕获它"。

### 🟢 要点三：事件驱动交易的"真正信号" — 从C1到C4告诉我们对什么应该告警

回顾整个C1→C4的学习历程，4个主题从不同角度回答了同一个问题：**什么才是值得告警的真正市场信号？**

#### 真正信号的特征（从C1-C4的交叉验证中提炼）

| 特征 | 对应的C1-C4技术 | 验证方式 |
|:----|:-------------|:--------|
| **多源共振** | KOL推文 + Reddit同方向 + 链上数据变化 | C2社区共振检测 + C4 SIR传播模型 |
| **价格+成交量验证** | 不只看价格变动，还要看成交量放大 | C1 L3市场验证 → C4 Transformer AE |
| **KOL历史影响力支撑** | 该KOL过去30条推文实际影响均价 | C2 Granger检验 → C4 MIS滚动权重 |
| **情绪方向与市场状态一致** | 上涨趋势中的正面消息 vs 下跌趋势中的负面消息 | C2 FinBERT-Crypto情感分类 + C4元学习regime识别 |
| **反事实不可解释** | 剔除该事件后，市场行为无法解释 | C3 SBERT嵌入匹配 + C4 tfcausalimpact |

#### 不是真正信号的特征（应被过滤）

| 特征 | 类型 | 对应的过滤技术 |
|:----|:----|:------------|
| **单来源无验证** | 孤立噪音 | C2 Filter: 需多源确认 |
| **先涨后推** | 补推跟风 | C2 Granger检验 |
| **KOL权重低+关键词强度低** | 社交闲聊 | C1 L2来源权重过滤 |
| **旧闻重复** | 时间窗口过期 | C1 60min去重窗口 |
| **泛兴趣（无具体标的）** | 行业泛谈 | C1 L3市场验证（无具体币种无法验证） |
| **单一维度异动（仅交易量涨）** | 可能是洗盘 | C4 AnomalyTransformer关联结构检查 |

#### 告警三级体系设计

从C1-C4的全部学习成果中，可以提炼出A7告警的三级体系：

```
【一级告警（立即通知ZH）】— 权重×强度≥15
条件：KOL权重≥8 + 靶向级(3x) + 价格已异动 + 多源确认
例：Elon说"DOGE TO THE MOON" + DOGE 3分钟内涨5% + Reddit社区同方向
→ 高置信度，ZH应重视

【二级告警（标记到alert但降低优先级）】— 10≤权重×强度<15
条件：单源未验证 或 社区共振弱 或 先涨后推标记
例：行业KOL说"BTC即将突破" + 未确认 + 无价格验证
→ 标记[单源信号]，ZH有时间再看

【三级信息（不打alert，仅打标到选币库）】— 权重×强度<10
条件：无市场验证 或 泛兴趣 或 无法归因具体币种
例：匿名账号发推"crypto will change the world"
→ 不打alert，但舆情数据入库供A3/A9参考
```

## 改进回答：怎么让A7的告警更准、误报更少？

### C1-Re回答（视角升级版）

过去的回答方向（C1-C4）："加一个新的过滤器来消除某类误报"。

现在的回答方向（C1-Re）：**"重新设计信号源头，让误报根本没机会产生。"**

### 具体的源头改进优先级

| 优先级 | 改进项 | 方法 | 预估误报减少 | 实施量 |
|:------:|:-------|:-----|:----------:|:-----:|
| 🟢 **S1** | **关键词体系结构化** | 将扁平关键词列表升级为正负1:1结构化词库，每个词附带强度分+分组+反讽标记 | 30% | 1小时维护词库 |
| 🟢 **S2** | **KOL权重动态化** | 从静态硬编码改为滚动30条推文的MIS更新（KOL评估C2-C4产出），每24小时自动校准一次 | 20% | 3小时开发脚本 |
| 🟡 **S3** | **三级告警体系实现** | 将当前的"要么告警要么沉默"二元模式改为三级制，一级alert、二级标记、三级入库 | 50% 误报不会再出现在ZH面前（虽然仍有三级信息入库） | 4小时修改alert.md输出逻辑 |

**关键洞察：S1+S2（源头）的投入产出比是S5（末端）的3倍以上。** 先在源头把误报率砍掉一半，再在末端做精细过滤。
