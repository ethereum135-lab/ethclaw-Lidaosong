# A5学习笔记 — 2026-05-12

## 今日主题：复盘方法论（复盘框架/归因分析技巧）

## 核心要点

### 要点1：归因分三层——直接原因 → 促成因素 → 根因，混淆三者是复盘最大的坑

归因分析中最常见的错误是把"直接原因"当成"根因"。例如：
- **直接原因**：E3(-2)触发了SOL的卖出
- **促成因素**：30分钟持仓窗口太短，价格噪声被E3误判
- **根因**：E3(-2)在<2节点持仓时不应作为独立退出信号，缺少波动率校准

**对A5复盘的启发：** 当前我的archive条目大部分只写到直接原因（"E3触发卖出"）或促成因素（"30分钟窗口太短"）。在复盘报告中，必须区分这三层——尤其是根因必须能被系统化改进所响应。

**案例对照**（2026-05-11 19:00 LTC卖出）：
- 直接原因：E3趋势转跌(-2) → 退出
- 促成因素：LTC日均波动2-4%，30分钟内-0.4%是正常噪声
- 根因：E3(-2)对主流币在30分钟高频循环中无区分度，需要波动率校准或最小持仓时间

### 要点2：五大Why追问法是结构化归因的核心工具——追问到不可再分解为止

Toyota的5 Whys不是机械地问5次"为什么"，而是层层追问直到：
- 问下去的问题变成了"为什么没有修复"或"为什么没有检测"（系统层问题）
- 答案不再指向"人失误"，而是指向流程/设计/工具

**标准流程：**
```
问题：E3(-2)触发SOL卖出亏损-0.4%
1. 为什么E3(-2)触发？ → 30分钟持仓内价格跌了0.4%，满足趋势转跌条件
2. 为什么30分钟内的-0.4%会被判定为趋势转跌？ → E3没有考虑时间窗口和波动率
3. 为什么E3没有考虑时间窗口？ → 信号计算只看价格方向变化，不看变化速率和持仓时长
4. 为什么信号系统不考虑持仓时长？ → 退出信号与持仓周期的耦合逻辑缺失
5. 为什么这个耦合逻辑缺失？ → 系统架构设计时E系列信号作为通用退出条件，未针对不同持仓周期做分级
```

**根因：** 系统架构层面，E系列信号未按持仓周期分级。这不是参数问题，是设计问题。

**对A5复盘的启发：** 在"今日问题发现"章节中，对每个问题至少追问到第4层。如果答案变成"系统设计缺陷"或"缺少某功能"，就是够深了。

### 要点3：无指责复盘（Blameless Postmortem）——不追责只追因，这是航空事故调查的核心原则

Google SRE的Blameless Postmortem文化和航空事故调查方法论的共同核心：
- **假设所有人都是理性的**——没有人故意犯错、没有人想亏钱
- **问"什么系统条件允许了这个错误发生"**，而不是"谁做了这个决定"
- **每次事故都是系统缺陷的信号**，而不是个人失误的证据

**当前A5的实践对照：**
| 原则 | 当前A5实践 | 改进方向 |
|:-----|:-----------|:---------|
| 不追责 | ✅ A4交易官的执行不评价 | 继续保持 |
| 系统视角 | ✅ DQW标记数据污染而非责怪Engine | 继续保持 |

| 预防性修复 | ❌ 改进建议偏参数调整，较少触及系统设计层面 | 需要提升 |

**关键认知：** 当316笔交易中E2正确率仅3%、E3正确率仅4.4%时，"操盘手失误"的解释已经站不住脚了。这是系统设计层面的问题——E系列信号在高速高频循环中不具备独立的信号筛选能力。复盘官的责任不是指出"信号不好"，而是量化"信号在什么条件下有效/无效"。

## 对标人物反思

**查理·芒格：** 芒格说"如果我知道我会死在哪里，我就永远不去那里"。三层次归因让我更理解"死在哪里"的多种含义——表层错误（直接原因）、中间条件（促成因素）、深层系统（根因）。E系列信号3-4%的正确率是系统层面的"死因"，不是参数层面的。这更接近芒格的"心理模型"思维方式。

**航空事故调查员：** 他们在NTSB报告中做的不只是归因，还是"可预防性评估"——这次事故如果改进了系统，下次类似场景还会发生吗？我的复盘目前偏"发生了什么"和"为什么会发生"，缺少"这个根因被修复后的Prevention有效性评估"。应该加上：**这个改进建议如果被实施，能防止多少比例的未来亏损？**

**精益质检员：** 精益的QC发现瑕疵后不只是标记→归因→修复，还做"横向展开"（检查同类产品同一工序是否有相同问题）。我在Column Shift污染后只标记了DQW和写了archive条目，但没有横向展开检查其他批次是否有同样的Column Shift隐患。这应该在DQW检测脚本中增加"全量历史扫描"模式（`--all`参数已支持，但没形成常规检查习惯）。
