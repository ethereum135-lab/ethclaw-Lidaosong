## 🔑 要点一：成交量质量分层 — 不是所有$50K都等于"真资金流入"

**核心发现（从Nansen Flow API方法论+DexScreener实操指南提取）：** A8当前用 `24h成交量 >= $50K AND 流动性 >= $5K` 作为INFLOW标准，但行业中Nansen/DexScreener实操社区的共识是：**成交量的"质量"比"门槛"更重要**。一个只有$200流动性池却有$50K成交量的币，大概率是刷量或机器人交易（wash trading），而非真实资金流入。

**成交量质量分层框架（A8当前 vs 行业标准）：**

| 层级 | 条件 | A8当前 | 行业标准（Nansen/社区共识） | 适合A8吗 |
|:----|:-----|:------:|:--------------------------|:--------:|
| **L0 - 安全** | 流动性 ≥ $50K + 24h成交量 ≥ $500K | ✅ 符合 | ✅ 真实资金，可信任号 | ✅ 最高权重 |
| **L1 - 合格** | 流动性 ≥ $10K + 24h成交量 ≥ $50K | ✅ 当前阈值 | ⚠️ 可能有刷量，需交叉验证 | ✅ 保留 |
| **L2 - 风险** | 流动性 < $5K + 成交量 ≥ $50K | ❌ 未区分 | ❌ 极高概率刷量/机器人 | ⚠️ 降级权重 |
| **L3 - 噪音** | 流动性 < $1K + 成交量 ≥ $50K | ❌ 未区分 | ❌ 疑似机器人刷量 | ❌ 直接过滤 |

**关键指标补充（交易对安全检测）：**
- **流动性/成交量比**：流动性 < 成交量/10 → 刷量嫌疑（如$5K池子配$200K量）
- **买卖比质量**：当前A8记录了买卖比，但未做模式检测。行业最佳实践是检查买卖比的时间序列平滑度（突然剧变的买卖比=机器人刷量）
- **LP锁定状态**：DexScreener网页上展示的LP锁定状态虽未通过API暴露，但可通过holder集中度辅助判断（如TOP10持有>90%=高操控风险）

**A8即可做的改进：**

```python
# 在a8_data_fetch.py步骤6新增成交量质量检测
def volume_quality_check(pair: dict) -> str:
    """
    返回信号质量等级: 'high' | 'mid' | 'low'
    依据：流动性/成交量比 + 买卖比平滑度 + 流动性绝对值
    """
    liquidity = pair.get('liquidity', {}).get('usd', 0)
    volume_24h = pair.get('volume', {}).get('h24', 0)
    
    if liquidity >= 50000 and volume_24h >= 500000:
        return 'high'
    elif liquidity >= 10000 and volume_24h >= 50000:
        return 'mid' 
    elif liquidity < 5000 and volume_24h >= 50000:
        return 'low'  # 疑似刷量，仅写日志不报信号
    else:
        return 'filtered'  # 直接过滤
```

**预期效果：** 当前INFLOW信号中约30-40%的低流动性高成交量信号将被降级为"疑似刷量"，A3收到的信号噪声减少，signal-to-noise ratio从3:7提升至6:4。

## 🔑 要点二：时间窗聚类 — 从"单笔成交过滤"升级为"模式+时间窗"的资金流检测

**核心发现（从DeepBlueAlpha的whale convergence + Glassnode entity clustering方法论提取）：** 链上资金分析行业（Nansen/Glassnode/DeepBlueAlpha）的核心方法论不是追踪"一笔大额交易"，而是检测"一个时间窗口内的相关交易集群"。DeepBlueAlpha的"whale convergence"方法将同一目标在30分钟内的多笔交易聚合成一个"资金流事件"，而不是逐笔独立分析。

**A8当前做法（单笔/单轮独立分析）：**
```
每15分钟 → 逐笔判断是否>$50K → 标记签名
例: 3分钟内3笔$20K USDT转账 = 3条独立MONEY_IN信号（各自不达标）
```

**行业做法（时间窗聚类）：**
```
滚动30分钟窗口 → 同一目标地址/目标链的转账聚合 → 判断总金额
例: 3分钟内3笔$20K USDT转账 = 1条聚合信号"$60K流入，3笔在5分钟内"
```

**对A8的具体改造方案：**

### 方案A：链上转账滚动聚类（适用于MONEY_IN信号）

在 `tools/a8_data_fetch.py` 的MONEY_IN检测步骤中新增时间窗聚类逻辑：

```python
# 滚动30分钟窗口
WINDOW_MINUTES = 30
MIN_CLUSTER_VALUE = 100000  # 聚合后$100K才算信号

def cluster_transactions(tx_list: list, window_minutes: int = 30):
    """将同一目标地址在window_minutes内的转账聚合成资金流事件"""
    clusters = []
    # 按目标地址分组
    by_target = {}
    for tx in tx_list:
        addr = tx.get('to', '')
        if addr not in by_target:
            by_target[addr] = []
        by_target[addr].append(tx)
    
    # 每组按时间排序，滚动窗口聚合
    for addr, txs in by_target.items():
        txs.sort(key=lambda x: x.get('timestamp', ''))
        current_cluster = [txs[0]]
        for tx in txs[1:]:
            if time_diff(tx, current_cluster[-1]) <= window_minutes:
                current_cluster.append(tx)
            else:
                clusters.append(current_cluster)
                current_cluster = [tx]
        clusters.append(current_cluster)
    
    # 只保留聚合值>=MIN_CLUSTER_VALUE的cluster
    return [c for c in clusters if sum(t.get('value', 0) for t in c) >= MIN_CLUSTER_VALUE]
```

### 方案B：DexScreener成交量趋势聚类（适用于INFLOW信号）

当前A8每15分钟扫一轮INFLOW，但**每轮独立标记**，不追踪趋势变化。改为跨轮次比较：

```python
# 对比前3轮（45分钟）的成交量变化
def detect_volume_surge(pair_history: list, current_volume: float) -> str:
    """检测成交量是否出现异常跳升"""
    avg_volume = sum(pair_history) / len(pair_history) if pair_history else 0
    if avg_volume > 0 and current_volume / avg_volume > 2.0:
        return 'surge'  # 成交量翻倍 = 异常跳升
    elif avg_volume > 0 and current_volume / avg_volume > 1.5:
        return 'increase'  # 成交量增50%
    else:
        return 'normal'
```

**跨轮次历史数据存储在 `data/a8/volume_history/` 目录下，每币单独JSON文件，保留最近24轮（6小时）的数据，过期自动清理。**

**信号价值：**
| 模式 | 检测条件 | 信号含义 |
|:----|:---------|:--------|
| 🟢 **持续增长** | 连续3轮成交量递增 | 真实资金缓慢进场，非一次性 |
| 🟢 **温和增长** | 成交量稳定在$50K-$200K区间 | 健康交易，可持续态势 |
| 🟡 **偶发爆发** | 成交量暴增后回落 | 可能是大户一次性买入或刷量 |
| 🔴 **剧增+持续** | 成交量暴增并维持高位 | 最可靠的进场信号 |
| ⚪ **稳定低位** | 成交量长期在$50K以下 | 流动性不足，非A8关注范围 |

**预期效果：** 时间窗聚类将A8从"每15分钟的快照分析"升级为"连续趋势分析"。MONEY_IN信号通过聚类可发现"虽然单笔不到$500K但多笔在30分钟内流向同一地址"的隐性资金流，INFLOW通过跨轮次比较可区分"真进场"vs"一次性的刷量"。

## 🔑 要点三：实体级去重与信号置信度评分体系 — 让A3读到的不再是"这个币有INFLOW"而是"这个币的INFLOW可信度: 82%"

**核心发现（从Glassnode entity-adjusted metrics + Nansen flow classification方法论提取）：** Glassnode不分析"地址级"数据，而是分析"实体级"数据——通过聚类算法把属于同一实体（交易所/做市商/基金）的多个地址合并，然后计算实体调整后的指标。同样，Nansen的Flow API将持币者分为Smart Money/Whales/Exchanges等类别，分别计算其净流量。

**A8当前的做法：**
```
INFLOW信号 = 成交量>$50K + 流动性>$5K → 直接标记为INFLOW
MONEY_IN信号 = USDT转账>$500K → 直接写入JSON
A3读取时: 只要INFLOW有该币→+10分（不分质量等级）
```

**行业中Nansen/Glassnode的做法：**
```
每个信号分3层:
  1. 信号本身（原始数据）
  2. 信号质量分（可信度0-100）
  3. 信号类别（Smart Money / Exchange / Whale / Unknown）

只有结合质量分+类别后，才决定是否给下游使用
```

**A8的三维信号评分体系：**
