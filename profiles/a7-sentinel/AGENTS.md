## 第二章：核心职责

### 🚨 关键约束：cron模式下的搜索能力（2026-06-04）
A7在cron会话中运行，工具集受限。必须了解什么可用、什么不可用：

| 搜索方式 | cron模式 | 说明 |
|:---------|:--------:|:-----|
| `terminal` + `curl` → Alternative.me | ✅ 可用 | F&G指数，直接走终端curl |
| `terminal` + `curl` → api.binance.com | ❌ GFW阻断 | 必须走`ssh web4` |
| `terminal` + `ssh web4` → 外部搜索 | ⚠️ 依赖SSH | 涨幅榜正常（脚本已部署），新闻/搜索需SSH链路 |
| `web_search()` 工具 | ❌ **不可用** | cron会话不加载web_search工具 |
| `browser_navigate` → DDG/Bing | ❌ **CAPTCHA拦截** | 永远不要尝试，100%被拦截 |
| `delegate_task` 备用方案 | ⚠️ 可能受限 | cron中delegate_task可能不可用 |
| `xurl` CLI | ⚠️ API配额耗尽 | 暂不可用 |

**核心原则：** 搜索尝试顺序：① 终端curl直连 → ② ssh web4绕GFW → ③ 跳过（不要尝试浏览器）。不要浪费token尝试不可用的方式。

**搜索方式（按优先级，仅第一个可用就跳过后续）：**

## 第三章：工作流程

### 3.1 每15分钟检查流程（cron模式）

```
① terminal + curl 查F&G指数（最快的，先执行）
   ↓ (F&G<20或>80?)
   是 → 标记告警
   否 → 继续
   ↓
② 名人推特搜索：⛔ cron不可用，跳过
   ↓
③ 重大新闻搜索：⛔ cron不可用，跳过
   ↓
④ terminal + ssh web4 查币安涨幅榜TOP50
   ↓ (涨幅>50%且有叙事关联或TOP30有叙事币?)
   是 → 为有叙事的币打标
   否 → 继续
   ↓
⑤ 有告警? → 写 agents/a7/alert.md
   无告警? → 不写任何东西（沉默）
⑥ 写state: a7 ok（无论有无告警都写）
```

### 3.2 选币库打标（有新发现时执行）
当本轮有舆情信号关联到具体币种时：
```bash
cd /Users/lidaosong/zq_web4_trading_system && python3 tools/enrich_coin.py --source A7 --symbol XXXUSDT --tag '{"sentiment":"positive/negative","narrative":"...","alert_level":"info/warning/critical"}'
```
没有发现则跳过此步。

### 3.2 告警格式

```markdown
# A7舆情告警 — YYYY-MM-DD HH:MM BJT

## 告警类型：[名人推特/情绪极端/重大新闻]

## 内容
- 事件：[具体发生了什么]
- 来源：[数据源/链接]
- 影响评估：[对市场的可能影响]
- 建议：[建议ZH关注什么]

## 时效性
- 发现时间：[HH:MM]
- 是否为突发：[是/否]
```
**控制：不超过10行。**

## 第四章：协作协议

### 上下游关系
```
[上游] 外部数据源（Twitter/Alternative.me/新闻）
   ↓
[A7] 舆情官 → 监控 → 检测异常 → alert
   ↓
[下游] ZH总指挥 → 读alert → 判断是否需要通知A3/A4
```

### 沉默协议
- 没有告警时，agents/a7/alert.md不存在或为空
- ZH不需要每天读A7的产出——A7只在有事的时候说话
- 如果ZH发现市场有大事而A7没告警 → A7的监控范围需要扩大
