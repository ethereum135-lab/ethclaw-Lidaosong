## 核心要点提炼

### 1. 影响市场不是看粉丝量，而是看「市场反应比」

| 指标 | 说明 | 用于A7 |
|:-----|:------|:-------|
| **Market Impact Score (MIS)** | KOL发推后60分钟内标的物价格平均变化幅度（归一化后） | 将Elon/CZ/Saylor每条推特的实际市场反应量化，动态调整其「影响力权重」 |
| **Engagement Quality (EQ)** | 真实互动率（去水军后） | 过滤掉补推假互动的噪音KOL |
| **First-Mover Score** | 是否在事件爆出前最早提及 | 区分「源头」和「跟风」 |

**A7如何用：** 当前对所有KOL一视同仁地用关键词搜。改进为——给Elon/CZ/Saylor设动态影响力权重，实时校准。例如，如果CZ最近10条推文平均带动市场<0.5%移动，权重自动降级。

### 2. 真实信号 vs 噪音的5层过滤法

| 层级 | 过滤器 | 效果 |
|:----:|:-------|:-----|
| L1 | **时效窗口过滤**：价格在tweet前10分钟内已上涨超过1%则排除（反向因果） | 排除「KOL跟风补推」 |
| L2 | **交易量与互动量异动**：tweet后5分钟成交量是否显著增加 | 区分「真买盘」和「机器人点赞」 |
| L3 | **钱包验证**：如果KOL公开钱包地址，其推特方向与实际交易方向是否一致 | 排除「说一套做一套」的KOL |
| L4 | **来源独立性**：该消息是否被2个以上独立信息来源同时确认 | 降低单点误报风险 |
| L5 | **回归锚定**：价格异动是否在2小时内回归 | 排除短期噪音扰动 |

**A7如何用：** 当前A7只有L1（关键词匹配）。逐步引入L2（成交量验证）和L3（对已知钱包的KOL做链上交叉验证）。L4-L5可以作为后续高级版本。

### 3. 踩坑案例库：历史证明最危险的误报场景

| 场景 | 例子 | 教训 |
|:----|:-----|:-----|
| **补推效应** | KOL在币价已涨20%后才发推，被误读为「带动市场」 | 必须用timestamp+价格时间序列判断因果方向 |
| **机器人泡沫** | 某KOL 80万粉丝但95%是爬虫——点赞10万但无人交易 | 需要对比互动量和实际交易量 |
| **收费喊单** | 中小KOL收5-10ETH发一条推，币价先拉后砸 | 对「先涨后跌<24h」的模式标记为推销信号而非真实利好 |
| **旧闻重播** | 3天前的黑客攻击被营销号包装成「突发新闻」 | 必须用发布时间窗口过滤，重复事件检测 |
| **自我实现** | 大量KOL推同一话题→价格上涨→更多人推→泡沫 | 对「集中喊单」模式单独标记，评估羊群效应 |

**A7如何用：** 在alert中为每个事件打上「误报风险标签」。例如：「来源：Elon Musk — 反向因果风险：高（价格在推文前已涨1.5%）— 建议ZH谨慎评估」。

## 改进方案：如何让A7告警更准、误报更少？

### 问题诊断
A7当前的核心问题不是搜得不够多，而是**没有区分信号质量**：
- 「Elon发了关于DOGE的推文」→ 总是告警  
- 但Elon的推文里，「DOGE TO THE MOON 🚀」和「lol」或者旧闻的重播，影响力天差地别
- 当前全凭A7模型语义理解判断，缺乏结构化量化评分

### 改进方案

#### 短期（本周可实施）

1. **KOL影响力权重矩阵**（用工具保存到profiles/a7-sentinel/config.yaml）
```
KOL权重:
  elon_musk: 10       # 默认最高
  cz_binance: 8        # 默认高
  saylor: 6
  trump: 5
  vitalik: 5
  brian_armstrong: 4
 其他KOL: 1           # 需要3次以上市场反应才升级
```

告警阈值：权重 * 关键词强度 ≥ 10 才写alert

2. **关键词强度分级**（在监控代码中实现）
```
强度1：「BTC」「ETH」「crypto」→ 基础级
强度2：「buy」「sell」「pump」「dump」→ 行动级
强度3：「$XXXX」「to the moon」「bearish」「这个币」→ 靶向级

告警规则：强度1需要权重≥8才告警，强度2需要≥6，强度3需要≥4
```

3. **时间窗口去重**（已在config.yaml中配置60分钟，确保实际使用）
- 对同一事件/同一条内容，60分钟内不重复告警
- 不同URL但内容hash相近 → 视为同一事件

#### 中期（2-4周）

4. **引入MIS（市场影响评分）自动化**
- 每抓一条KOL推文，记录发布时间戳
- 拉取推文后15分钟的价格变化（通过Binance/CoinGecko API）
- 累积形成该KOL的滚动MIS（最近30条推文的平均影响）
- 当MIS低于阈值时自动降权

5. **成交量异动验证**
- KOL发推后5分钟，查询目标币种交易量是否超过过去1小时的10分钟平均量的3倍
- 如果成交量没有显著增加→降级告警等级

#### 长期（1-2个月）

6. **钱包交叉验证**（针对公开地址的KOL）
- 检测KOL发推前后，其钱包是否有对应操作
- 「说买但自己卖」→ 标记为反向信号

### 量化目标
| 指标 | 当前（估计） | 目标 |
|:-----|:----------:|:----:|
| 重大事件告警时间 | ~15分钟 | ≤10分钟 |
| 误报率 | ~20-30%（凭感觉） | 0% |
| 有效告警率 | ~50-60%（凭相关/因果混杂） | ≥80% |
| KOL覆盖数 | 3个（Elon/CZ/Saylor） | 6+（+Trump/Vitalik/BrianArmstrong） |

## 对A7的启示总结

1. **核心改进方向**：从「关键词触发的报警器」升级为「量化评分驱动的分级预警系统」
2. **第一优先级**：引入KOL影响力权重 + 关键词强度分级（零成本，只改逻辑）
3. **第二优先级**：实现时间窗口去重和内容hash去重
4. **第三优先级**：对接交易量API做成交量异动验证
5. **铁则不变**：宁可漏报不可误报——低级告警（权重*强度<10）宁可静默也不发

**一句话总结：** 不是所有KOL的推文都值得告警，只有「高影响力KOL的有实质内容的推文 + 有成交量验证」才值得ZH看一眼。
