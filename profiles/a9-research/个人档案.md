## 五、核心职责（按你的设计）

### 四项研究维度（每周一08:00）

```
① 新工具
   搜索: web_search("new crypto trading tool github 2026")
         web_search("best crypto trading bot framework")
         web_search("freqtrade plugin strategy")
   评估标准: 能让我们做什么之前做不了的事？

② 新数据源
   搜索: web_search("new crypto data api 2026")
         web_search("crypto on-chain data source")
         web_search("crypto sentiment indicator new")
   评估标准: 这个数据能提高哪个Agent的准确率？

③ 新策略
   搜索: web_search("profitable crypto trading strategy 2026")
         web_search("quantitative trading strategy crypto")
         web_search("trading strategy backtest results")
   评估标准: 这个策略在我们的框架下能跑吗？

④ 案例学习
   搜索: web_search("crypto trading profit case study")
         web_search("crypto trading loss lesson learned")
         web_search("trader mistake avoid")
   评估标准: 这个教训怎么变成系统的规则？
```

### 每周一执行流程

```
① web_search 搜新工具
   ↓ 评估: 能填补什么能力缺口？接入难度？
   ↓
② web_search 搜新数据源
   ↓ 评估: 能提高哪个Agent的准确率？
   ↓
③ web_search 搜新策略
   ↓ 评估: 核心逻辑？适用市场？能否接入？
   ↓
④ web_search 搜案例
   ↓ 评估: 做了什么？结果？教训？系统启示？
   ↓
⑤ 合成 agents/a9/weekly_research.md
   ↓ (找不到有价值的信息?)
   是 → 写"本周无重大发现"
   否 → 输出完整报告
```

### 报告格式

```markdown
# A9本周工具与学习报告 — 第X周 (YYYY-MM-DD)

## 🏆 最有价值发现
- [发现] → [系统影响] → [接入建议/优先级]

## 新工具
- [工具名] [功能] [评估] [接入难度]

## 新数据源
- [数据源] [内容] [价值评估]

## 新策略
- [策略名] [核心逻辑] [适用市场] [能否接入]

## 案例学习
- [案例] [做了什么] [结果] [教训] [系统启示]

## 结论
- 最有价值的1-2个发现
- 建议ZH优先关注
```

备用模型：   claude-sonnet-4         (云端Anthropic)

为什么温度0.4？（全系统最高）
  ZH: 0.3  → 行业研判需要一致性
  A5: 0.3  → 复盘需要客观
  A6: 0.2  → 审计需要精确

  A8: 0.2  → 资金分析需要精确

温度0.4的作用：
  搜到一个股票策略时，0.4温度让它能思考"这个策略的核心逻辑可以改成crypto版接入A3"
  0.2温度只会复述"这是一个股票策略"

月成本估算：~$0.0006/月
  每周1次 × 4周 = 4次/月
  每次~1,500 tokens = 6K tokens
  → $0.0006/月（9个Agent中最便宜）

决策依据：A9是全系统唯一负责"向外看"的Agent
  一次错误评估可能导致一个好策略被放弃，或一个差策略被接入
  $0.0006/月买的是"A9的评估可以信任"
