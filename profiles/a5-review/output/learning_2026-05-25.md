## 第①步：AAR框架学习

### 核心框架

AAR（After Action Review）源自美军，四段式复盘：

```
Q1：预期是什么？
    → 行动前，你认为会发生什么？基于什么判断？

Q2：实际发生了什么？
    → 客观数据，不带情绪地描述事实

Q3：为什么有差异？
    → 是信息不对称？判断错误？还是不可控因素？

Q4：下次怎么改进？
    → 具体可执行的动作，不是「下次注意」
```

### 关键原则

| 原则 | 含义 | 用在A5监督中 |
|:-----|:------|:------------|
| **「预期」必须写下来** | 复盘时容易事后合理化——「我本来就觉得会跌」。AAR要求在行动前记录预期 | 看A3报告中的推荐理由是否具体、可验证 |
| **区分「执行偏差」和「策略偏差」** | 策略对但没执行好 ≠ 策略错 | A3推荐对但A4没按四档价格执行 → 执行问题；A3逻辑链本身有问题 → 策略问题 |
| **不追究责任，追究根因** | AAR不是审判，是学习 | 不要把亏损归因于「A3傻」，要问「选这个币时忽略了什么信号」 |
| **差异分析要量化** | 「亏了」不如「预期+3%实际-5%，差8个百分点」 | 用P&L数字说话，不模糊归因 |
| **改进建议必须可执行** | 「下次注意」不算改进，「建仓前检查24h成交量是否>$500K」才算 | 每个archive条目的改进建议必须是具体规则 |

### 与A5已有工具的结合

| A5工具 | AAR对应 | 结合方式 |
|:-------|:--------|:---------|
| `analyze_exit()` 的 P&L分析 | Q2（实际发生了什么） | 自动完成，但需增加 Q1（预期）的输入 |
| `supervision_eval.py` | 整个AAR | 在监督评估中强制插入四段式结构 |
| archive四要素（归因→规律→改进→评分） | 对应 Q3→Q4 | 已有，但需增加 Q1（预期）的明确记录 |
| exit_quality 分类（correct/wrong/neutral） | Q2的结果判定 | 需与 Q1（预期）对照——如果预期-5%实际-3%，这是correct还是wrong？ |

### 当前系统的AAR盲区

**最大盲区：A5从未记录「预期」。** 系统有642笔交易的经验数据，每一笔都有买价、卖价、盈亏，但**没有任何一笔记录了买入时的「预期涨幅」**。

没有预期 → 无法做AAR Q1 → 复盘永远是「事后分析」而不是「决策评估」。

举例：一笔P&L -0.4%的交易，如果预期是-5%（因为买在短期高点），那-0.4%是正确止损，是good decision但unlucky outcome。但如果预期是+5%（因为信号评分高），那-0.4%就是决策差。

**没有预期，就无法区分「好的决策但运气差」和「差的决策但运气好」。**

## 第②步：提取2条AAR判断规则

### 规则1：「预期必须可验证，不写模糊预期」

```
✅ 好的预期：先建仓价$0.03646，预期T1(+2%=$0.03719)先出25%，T2(+4%=$0.03792)再出25%
❌ 差的预期：「希望它涨」
```

**应用在A5监督：**
- A3推荐时写了四档价格 → 这些就是预期 → 对比实际是否达到
- A4执行时知道退出触发方式 → 预期（E2/E3/P1/止盈触发） → 对比实际退出方式
- 如果实际退出方式和预期不同 → 差异分析的起点

### 规则2：「先看决策质量，再看结果」

```
AAR框架强制在知道结果前先记录决策时的预期。
如果知道结果后再复盘 → 事后偏见 = 会把好的决策说成差的结果，或差的结果说成好的决策
```

**应用在A5监督：**
- A5写archive条目前必须回看A3推荐时的四维分析——「当时A3的理由成立吗？还是纯粹运气？」
- 例：2026-05-25 FIDA买入（Momentum Bypass）→ A3报告里FIDA仅27分「趋势观察」——A4没走A3路径。这个决策的「预期」是什么？预期FIDA momentum会继续。但从AAR角度看：at decision time，买入依据是64pts STRONG（独立于A3）vs A3只给了27分。这是两个独立意见的冲突。A5应该在复盘时指出这个决策冲突，不是等结果出来说「买对了/买错了」。

## 第④步：全局AAR — 用新视角发现系统问题

### 从AAR框架看系统最大问题：缺乏预期记录

**现象：** 系统642笔交易，每笔都有买价、卖价、盈亏、退出信号。但**没有一笔记录了买入时的预期涨幅/持有时间/退出触发条件**。

**根因：** A4 Blade的TRADES.md记录格式专注在执行事实（时间/价格/数量/退出原因），不记录「决策预期」。A3推荐时的四档价格（$640-$665建仓，$715止盈）存在于A3的报告里，但没有被链接到A4的执行记录或trade JSON文件中。

**影响：**
- 每次复盘都是事后分析（只看结果），无法做「决策质量 vs 结果」的分离
- 无法验证A3的推荐逻辑是否被A4遵守（买价是否在建仓区间内？）
- 无法区分「好的决策但运气差」和「差的决策但运气好」

**建议改进方向：**
1. A4在TRADES.md的SELL行data字段中增加「预期退出信号: XXX」备注（如「预期T2退出，实际E4触发」）
2. A5在trade JSON文件中增加 `expected_exit_signal` 和 `expected_pnl_range` 字段
3. A5的archive条目标准格式增加「Q1预期」字段（从A3报告/A4决策记录提取）

## 总结：今天学到的2条规则怎么用

### A5自己怎么用AAR

| A5环节 | 融入AAR | 具体做法 |
|:-------|:--------|:---------|
| 每笔经验值写入 | +Q1预期 | 从A3报告/A4记录提取该笔交易的预期退出方式和预期P&L，写入JSON的 `expected_exit` 字段 |
| 每日复盘 | 强制四段式 | 每个关键交易写完整的Q1→Q2→Q3→Q4 |
| archive条目 | 增加预期记录 | 在archive条目标准四要素前增加「预期」一行 |
| 监督评估 | 区分决策vs结果 | 先用AAR判断决策质量，再对比实际结果 |

### 在feedback.md中给A3/A4的建议

**对A3：** 四档价格中的建仓区间和止盈价是AAR的「预期」输入。请确保每个推荐币的建仓区间足够具体（如「$640-$665」比「$650附近」更可验证），方便A4执行和A5事后AAR分析。如果之后价格偏离建仓区间，A5可以准确判断「是A3区间不合理」还是「A4未按区间执行」。

**对A4：** Momentum Bypass买入的币，请在交易记录中标注「对比A3意见」字段（如「A3对FIDA评27分(SKIP级别)，A4独立决策执行」）。这样A5可以在AAR中识别「A4独立于A3的决策」并追查其闭环效果。
