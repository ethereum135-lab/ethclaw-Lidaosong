## 第二部分：真实经历库

### 经历1：LINK买入匹配错误修复

```
日期: 2026-05-11
问题: get_last_exit()只用文件中的最后一个BUY，不检查时间是否匹配
案例: 
  BUY 2026-05-11 06:30:03 LINK $10.69
  BUY 2026-05-11 09:30:02 LINK $10.70  ← 系统匹配了这个
  SELL 2026-05-11 09:00:02 LINK $10.65  ← 卖出时间在第二个买入之前
结果: P&L算成 -0.56%（用$10.70算），实际应为 -0.47%（用$10.69算）
修复: 在get_last_exit()中加入 bi['time'] < sell_time 条件
教训: 高频交易中同一个币可能在短时间内多次买卖，买入匹配必须检查时间顺序
```

### 经历2：同时间戳多笔卖出陷阱

```
日期: 2026-05-11 12:30
现象: 引擎同一周期卖出LINK和TAO，时间戳相同(12:30:03)
  TRADES.md 行643: SELL LINK
  TRADES.md 行644: SELL TAO
  analyze-recent-sell.py 默认模式：只看最后一行(TAO)
  TAO已有经验值 → DUPLICATE → 退出
  LINK被跳过，从未被分析
修复: cron一律用 --batch，batch模式幂等安全
教训: 默认模式对批量卖出场景不安全，batch才是正确的cron参数
```

### 经历3：Column Shift数据污染

```
日期: 2026-05-11 15:30-16:30
现象: 连续3个批次出现价格数据错位
案例分析:
  UNI: 买入$4.07, TRADES.md卖出显示$100.16 → 实际应在$4-10 → +2362%虚假
  AAVE: 买入$96.78, 卖出显示$0.004 → 实际应在$90+ → -100%虚假
  GALA: 买入$0.004, 卖出显示$1.122 → 实际<$0.05 → +27950%虚假
根因: 引擎批量写入时的Column Shift（列对齐错误）
影响: 虚假P&L计入MASTER_EXPERIENCE，污染exit_signal_performance统计
修复: DQW检测框架，标记为1星不可靠
教训: 同一批次相邻行的qty/price数据疑似互换，qty比是可靠的辅助检测指标
```

### 经历4：精度截断检测

```
日期: 2026-05-11 16:00:01
现象: SHIB买入卖出均在$0.0000显示 → buy_price=0, sell_price=0
根因: TRADES.md用4位小数，SHIB实际价格约$0.00001，被截断为$0.0000
影响: P&L算成0%（中性退出），无法反映真实盈亏
检测: 当buy==0或sell==0时优先怀疑精度截断而非Column Shift
处理: 标记"精度不足"（1星），区别于Column Shift的"数据污染"
```

### 经历5：低波动资产E3过灵敏

```
日期: 2026-05-11 16:30-17:00
案例: XAUT买入$4668.84, 30分钟后卖出$4662.86 (-0.13%)
退出原因: E3趋势转跌(-2)
根因: XAUT黄金锚定代币，日均波幅<0.3%，30分钟内的-0.13%属于正常噪声
     E3对高波幅币种有意义，但对XAUT在30分钟级几乎必然触发
影响: 每一笔都是亏损(含手续费和滑点)，净负价值
建议: 低波动品种(<1%日均波幅)做波动率校准，E3信号降级
```
