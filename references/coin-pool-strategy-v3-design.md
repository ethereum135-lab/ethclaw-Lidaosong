## 二、选币库架构 v3.0 — 四层漏斗+三池动态结构

### 2.1 核心理念

**不是"所有好币"，是"现在能赚钱的币"。** 选币库不是静态目录，是动态过滤器。

```
全量579个USDT交易对
    ↓ 第一层：硬性安全过滤（必须全部通过）
通过 ~300-350个
    ↓ 第二层：质量评分过滤（综合得分排名）
通过 ~150-200个
    ↓ 第三层：赛道均衡分配（按赛道权重分配名额）
通过 ~50-80个
    ↓ 第四层：动态分类（按当前活跃度分为三层）
┌─────────┐ ┌─────────┐ ┌─────────┐
│ 核心池   │ │ 候选池   │ │ 监控池   │
│ 15-20个  │ │ 25-40个  │ │ 30-50个  │
│ 可立即   │ │ 需要等   │ │ 观察但   │
│ 交易的   │ │ 信号才   │ │ 暂时不   │
│ 币       │ │ 交易的   │ │ 交易     │
└─────────┘ └─────────┘ └─────────┘
```

### 2.2 四层漏斗详解

#### 第一层：硬性安全过滤（AND条件，必须全部通过）

| # | 条件 | 阈值 | 过滤掉的风险 | 来源 |
|:-:|:----|:----:|:------------|:-----|
| 1 | 24h成交量 | > $500K | 流动性枯竭的币 | Freqtrade VolumePairList |
| 2 | 价格 | > $0.001 | 灰尘币、精度问题 | Freqtrade PriceFilter |
| 3 | 非稳定币 | 排除USDT/USDC/BUSD/DAI等 | 稳定对不能涨 | 行业共识 |
| 4 | 非杠杆/结构化 | 排除UP/DOWN/BULL/BEAR/LONG/SHORT/杠杆ETF | 非现货标的 | 行业共识 |
| 5 | 上币天数 | ≥ 30天 | 新币砸盘/流动性骤降/操纵 | SSRN 2022统计 + Freqtrade AgeFilter |
| 6 | 价差(Spread) | < 0.5% | 滑点太大吃掉利润 | Freqtrade SpreadFilter + Kaiko 2024 |
| 7 | 日波动率 | 1% ~ 10% | 太低没利润/太高风险不可控 | NostalgiaForInfinity + CoinMetrics |

**价差检测方法：**
```python
def check_spread(symbol):
    """检查币对实时价差（通过订单簿）"""
    orderbook = client.get_order_book(symbol=symbol+'USDT', limit=5)
    best_bid = float(orderbook['bids'][0][0])
    best_ask = float(orderbook['asks'][0][0])
    spread = (best_ask - best_bid) / ((best_ask + best_bid) / 2)
    return spread
```

#### 第二层：质量评分（综合得分，前N名通过）

| 维度 | 权重 | 说明 | 数据来源 |
|:----|:----:|:-----|:---------|
| 流动性深度 | 25% | 订单簿前5档深度总和 | Binance orderbook |
| 成交量稳定性 | 20% | 7日成交量变异系数(CV)，CV<0.5=高分 | Binance klines 7d |
| 波动率合理性 | 20% | 年化波动率40%-100%=高分 | Binance 14d klines |
| 行为表现 | 20% | 历史交易胜率+盈亏比 | coin_pool.behavior |
| BTC相对强度 | 15% | 该币24h涨幅 - BTC 24h涨幅 | Binance ticker |

**注意：这层不是"选牛币"，是"排除垃圾"。** 不考该币会不会涨，只考这币有没有交易价值。

**赛道分配算法：**
```python
def allocate_sectors(pool_candidates, hot_sectors, pool_size=80):
    """
    按赛道权重分配名额。
    hot_sectors = {'ai': 85, 'l1': 72, 'defi': 65, 'meme': 55, ...}
    """
    # 1. 计算基础权重（热点评分映射）
    base_weight = {s: max(s['score'], 10) for s in hot_sectors}
    total_weight = sum(base_weight.values())
    
    # 2. 计算各赛道初始名额
    allocation = {}
    remaining = pool_size
    for sector, w in sorted(base_weight.items(), key=lambda x: -x[1]):
        n = max(1, int(pool_size * w / total_weight))
        allocation[sector] = min(n, len(candidates_by_sector[sector]))
        remaining -= allocation[sector]
    
    # 3. 剩余名额给评分最高的赛道（按权重比例补）
    for sector in sorted(base_weight, key=lambda x: -base_weight[x]):
        if remaining <= 0: break
        sector_candidates = candidates_by_sector[sector][allocation[sector]:]
        add = min(remaining, min(3, len(sector_candidates)))
        allocation[sector] += add
        remaining -= add
    
    return allocation
```

#### 第四层：动态三池分类

完成赛道分配后，将选中的币分为三层：

| 池 | 数量 | 进入条件 | 说明 |
|:-:|:----:|:---------|:-----|
| 🔵 **核心池(Core)** | 15-20 | 同时满足：①5-20%涨幅 ②成交量>5M ③RSI 45-78 ④高于MA20 ⑤7天≥3涨 | 可立即交易，A3直接精选 |
| 🟡 **候选池(Candidate)** | 25-40 | 通过一、二、三层但未达核心条件 | 等信号才交易，A3每天扫描 |
| 🟢 **监控池(Monitor)** | 30-50 | 成交量>500K但未进入核心/候选 | 观察但不交易，只做数据记录 |

**动态流动：**
```
监控池 → 触发动量信号(放量+突破) → 候选池
候选池 → 5因素全通过 → 核心池
核心池 → 涨幅>30%或RSI>80或成交量萎缩 → 候选池
任一池 → 连续3天成交量<500K或价差>0.8% → 移除池 → excluded
```

## 三、出池/淘汰标准

**这是当前系统最大的缺失。** 没有出池 = 垃圾越来越多。

### 3.1 自动移出条件（符合任意一条即触发）

| 条件 | 阈值 | 动作 | 来源 |
|:----|:----|:----|:-----|
| 成交量暴跌 | 连续3天 < $300K | 移出到excluded | Freqtrade社区标准 |
| 价差暴增 | 连续2天价差 > 0.8% | 移出到excluded | Kaiko流动性报告 |
| 波动率归零 | 连续5天日波动 < 0.5% | 移出到excluded | 无利润空间 |
| 波动率过高 | 单日 > 20% 且无趋势 | 移入观察，48h内无改善则移出 | 闪崩/操纵风险 |
| 已下架/公告下架 | 币安发布下架公告 | 立即移出，行为数据保留 | 无法交易 |
| Rug/黑客/负面 | 可验证的严重负面事件 | 立即移出 | 风险不可控 |
| 历史表现差 | 行为追踪胜率<30%且交易数≥10 | 移出到excluded | 该币不稳定 |

### 3.2 自动轮换机制

每周一08:00执行一次轮换：
1. 核心池退出排名后25%的币（成交量下降/表现差）
2. 候选池表现最好的前20%升入核心池
3. 监控池有新动量信号的升入候选池
4. excluded中最近7天有放量复苏信号的重新引入监控池

## 四、Master/Watch规模动态调整

**核心原则：不固定80/120，按市场条件动态调整。**

| 市场状态 | 判定条件 | 核心池 | 候选池 | 监控池 |
|:--------|:--------|:------:|:------:|:------:|
| 🟢 牛市/活跃 | 全市场>50%币种上涨 | 20 | 40 | 40 |
| 🟡 震荡/中性 | 30-50%币种上涨 | 15 | 30 | 50 |
| 🔴 熊市/恐惧 | <30%币种上涨或F&G<30 | 8-10 | 15-20 | 20-30 |

**为什么？**
- 牛市机会多→扩大池子抓更多机会
- 熊市流动性差→缩小池子只做最优质的
- 震荡市居中

**逻辑：**
```python
def get_pool_sizes(market_breadth_pct, fear_greed):
    """根据市场广度动态计算池子大小"""
    if fear_greed < 20:
        return 8, 15, 20  # 极度恐惧，缩量防守
    elif fear_greed < 40:
        return 10, 20, 30  # 恐惧，谨慎
    elif market_breadth_pct > 0.5:
        return 20, 40, 40  # 牛市，全开
    else:
        return 15, 30, 50  # 震荡，中等
```

## 五、赛道权重策略

### 5.1 赛道热度更新

**不再是手动写死30个币。** 改为：

1. **初始分类** — 用CoinGecko `/coins/categories` 获取全量币种赛道映射
2. **每日更新** — 从Binance Top200成交量币种中，实时计算赛道分布
3. **热点检测** — 自动检测哪些赛道正在升温（3+币种同时放量/涨幅榜密集）

### 5.2 赛道轮动规则

```
每7天评估一次赛道热度。极端行情(单日BTC波动>5%)立即重评。

┌─ 判断市场阶段 ──────────────────────┐
│ BTC > 200日SMA + F&G > 50 = 牛市   │
│ BTC > 200日SMA + F&G 30-50 = 震荡   │
│ BTC < 200日SMA = 熊市               │
└─────────────────────────────────────┘
         ↓
┌─ 选择赛道方向 ──────────────────────┐
│ 牛市：L1(30%) + AI(20%) + Meme(20%) │
│        + DeFi(15%) + L2(15%)        │
│ 震荡：L2(25%) + Defi(25%) + Infra(20%)│
│        + RWA(15%) + AI(15%)          │
│ 熊市：仅高流动性币(BTC/ETH/SOL)     │
└─────────────────────────────────────┘
```

### 5.3 赛道覆盖检查清单

每次更新选币库后自动检查：

```
☐ 覆盖了几个赛道？ ≥ 6个
☐ 有没有赛道完全空白（全部标记other）？
☐ 当前热点赛道是否有≥3个币在池中？
☐ 核心池的赛道分布是否均衡（单个赛道占比<35%）？
```

## 六、更新流程 v3.0

### 6.1 每天UTC 00:00 全量更新

```python
def daily_update():
    """选币库每日更新流程"""
    # Step 1: 拉取全量币 + 第一层过滤
    all_coins = fetch_all_tickers(client)        # ~579个
    passed_l1 = [c for c in all_coins if safe_filter(c)]  # ~300-350个
    
    # Step 2: 质量评分
    for c in passed_l1:
        c['quality_score'] = calculate_quality(c)
    passed_l2 = sorted(passed_l1, key=lambda x: -x['quality_score'])[:200]
    
    # Step 3: 赛道分配
    passed_l3 = allocate_by_sector(passed_l2, hot_sectors, pool_size=100)
    
    # Step 4: 动态分三层
    pool['core'] = classify_core(passed_l3)       # 15-20个
    pool['candidate'] = classify_candidate(passed_l3)  # 25-40个
    pool['monitor'] = classify_monitor(passed_l3)  # 30-50个
    
    # Step 5: 出池检查
    remove_dead_coins(pool)  # 检查成交量/价差/表现
    
    # Step 6: 行为数据保留（不重置）
    pool['behavior'] = load_behavior()  # 从旧池保留
```

### 6.2 每4小时轻量刷新

只做Step 1+2（不跑赛道分配），确保持仓币的数据不过时：
- 刷新持仓币的24h成交量、涨幅、价差
- 检查是否有币触发了出池条件
- 检查是否有监控池币触发了入候选信号

### 6.3 分层触发机制

| 更新类型 | 频率 | 触发 | 数据量 |
|:--------|:----|:----|:------|
| 全量更新 | 每天UTC 00:00 | cron | 579个币，全量 |
| 轻量刷新 | 每4小时 | cron | 持仓+候选币 |
| 实时检查 | 每次交易前 | A4 Blade | 单币 |
